    MCP Server Outside VS Code¶

    F&O Studio's metadata server, XppVsCode.Server.exe, is a standard MCP server over stdio. Inside VS Code the extension starts it for Copilot. You can also run it on its own and connect it to another MCP host (an agent CLI, another editor, an agent framework), so that host's agent gets the same xpp_* tools on your D365FO metadata. Every GitHub release includes the server as a separate zip with its SHA-256 checksum for this purpose.

    This page explains what is in the package, what the server needs, how to start and test it, and what is different from VS Code. For the tools themselves see MCP-Agent-Tools.

    When to use it¶

    • You use an agent other than GitHub Copilot in VS Code and want it to read, extend and build X++ through the metadata API.
    • You build your own automation (for example a review bot on a developer machine) that calls the tools over MCP.
    • You use F&O Studio's Claude Code plugin, which uses this server package for its tools and @fno-studio/core for cloud operations (Core-Library).

    If you work in VS Code with F&O Studio installed, you don't need this page: the extension registers the server for Copilot automatically.

    Before you start¶

    Requirement Why
    Windows, x64, .NET Framework 4.8 The server is a .NET Framework 4.8 x64 program
    A D365FO configuration on the machine The server reads it to find the metadata, the custom model folder and the cross-reference database
    PackagesLocalDirectory extracted, with its bin folder The server loads Microsoft's D365FO assemblies from <FrameworkDirectory>\bin at run time; none are shipped
    Git (optional) For xpp_diff_changes
    Cross-reference database (optional) For where-used, message source and obsolete-API checks
    Internet access to learn.microsoft.com (optional) For xpp_search_docs

    A configuration is a JSON file under %LOCALAPPDATA%\Microsoft\Dynamics365\XPPConfig. The machine gets one when you connect a unified developer environment with F&O Studio (Connect-to-Environment) or Visual Studio, or with runUdeSetup of the core library. On cloud-hosted and VHD environments see Cloud-Hosted-and-VHD-Environments.

    Get the server¶

    1. Open the project's GitHub releases (https://github.com/nazmolla/xpp-vscode/releases) and pick the version.
    2. Download fno-studio-server-X.Y.Z.zip and fno-studio-server-X.Y.Z.zip.sha256.
    3. Check the checksum:
    $expected = ((Get-Content .\fno-studio-server-X.Y.Z.zip.sha256 -Raw) -split '\s+')[0]
$actual = (Get-FileHash .\fno-studio-server-X.Y.Z.zip -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "Checksum mismatch" }
    1. Extract the zip to a folder of your choice, for example C:\Tools\FnoStudioServer.

    What is in the zip: the content of the extension's server\bin folder, with XppVsCode.Server.exe and its XppVsCode.Server.exe.config. The release build refuses to package any .dll or Microsoft.Dynamics.* file, so the zip never holds a Microsoft assembly. The agent instructions, tool definitions and development guide are embedded in the exe.

    The release build signs the exe only when code signing is configured for the repository; otherwise it ships unsigned. Check the signature with Get-AuthenticodeSignature .\XppVsCode.Server.exe and always check the SHA-256.

    Start the server¶

    XppVsCode.Server.exe [--config <XPPConfig json>] [--project <rnrproj>] [--rules <agent-rules.md>] [--activity-log]
    Option Meaning
    --config <file> The configuration JSON to use. Without it, the server reads CurrentMetadataConfig under HKCU\Software\Microsoft\Dynamics\AX7\Development\Configurations (the active configuration, shared with Visual Studio)
    --project <file> The active D365FO project: new elements are added to it, scope=project builds use it. Without it, the agent can pick one with xpp_select_project
    --rules <file> A team rules file (normally <repo>\.xpp\agent-rules.md), appended to the agent instructions (first 20,000 characters)
    --activity-log Record each tool call in %LOCALAPPDATA%\XppVsCode\activity.jsonl and keep element copies before writes in snapshots. VS Code's Copilot Activity view reads this file
    --allow-data Never use it for an MCP server. It turns on the business data service (xpp/data), which only F&O Studio's own processes use

    The server speaks MCP over stdio: one JSON-RPC message per line on stdin and stdout. Logs go to stderr, starting with xpp-vscode server <version> | config <file> | project <file or none>. If no usable configuration is found, it logs No usable D365FO configuration (...) and exits with code 1.

    Connect it to an MCP host¶

    Most MCP hosts take a command and arguments for a stdio server. The exact file and key names depend on the host; a typical entry looks like this:

    {
  "mcpServers": {
    "fno-studio": {
      "command": "C:\\Tools\\FnoStudioServer\\XppVsCode.Server.exe",
      "args": [
        "--config", "C:\\Users\\<you>\\AppData\\Local\\Microsoft\\Dynamics365\\XPPConfig\\<config>.json",
        "--project", "C:\\Repos\\ContosoExtensions\\ContosoExtensions.rnrproj",
        "--rules", "C:\\Repos\\ContosoExtensions\\.xpp\\agent-rules.md"
      ]
    }
  }
}

    The server answers initialize with:

    • serverInfo.name xpp-vscode and the server version;
    • capabilities.tools;
    • instructions: the built-in agent instructions plus your team rules. Hosts that pass server instructions to the model give the agent the same rules Copilot gets in VS Code.

    Then tools/list returns the 38 tools of server/Resources/Tools.json, and tools/call runs them.

    Test it by hand¶

    Send a few lines and read the answers, always with a timeout so no session is left waiting:

    $psi = New-Object System.Diagnostics.ProcessStartInfo 'C:\Tools\FnoStudioServer\XppVsCode.Server.exe'
$psi.Arguments = '--config "C:\Users\<you>\AppData\Local\Microsoft\Dynamics365\XPPConfig\<config>.json"'
$psi.UseShellExecute = $false; $psi.RedirectStandardInput = $true; $psi.RedirectStandardOutput = $true; $psi.RedirectStandardError = $true
$p = [System.Diagnostics.Process]::Start($psi)
function Ask($line) {
    $p.StandardInput.WriteLine($line)
    $answer = $p.StandardOutput.ReadLineAsync()
    if ($answer.Wait(120000)) { $answer.Result } else { 'No answer within 2 minutes' }
}
Ask '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18"}}'
Ask '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"xpp_find_object","arguments":{"objectName":"CustGroup","objectType":"AxTable","exactMatch":true}}}'
$p.StandardInput.Close()
if (-not $p.WaitForExit(10000)) { $p.Kill() }

    Each answer is one line of JSON. Read each answer before you close stdin: the server stops when stdin closes, and read-only tools answer from a worker thread. The first metadata call takes longer, because the metadata loads once per process.

    The repository's scripts/smoke-test.ps1 does the same with 16 read-only tool calls; see Testing-the-Extension.

    What is different from VS Code¶

    Feature In VS Code Outside VS Code
    The 38 MCP tools Yes Yes
    xpp_open_element, xpp_run_tests, xpp_query_data Yes (extension tools) No: they need the extension's editor, sign-in and database credentials
    Arguments kept up to date (environment, project, team rules) The extension restarts the server when they change You pass them; restart the server after a change
    Write limits to your own models, all-or-nothing creates, validation Yes Yes (enforced by the server)
    Copilot scope and checkpoints Set with the F&O Studio commands The server still reads %LOCALAPPDATA%\XppVsCode\agentSession.json before agent writes when --activity-log is on, but only the VS Code extension writes that file and reverts checkpoints
    Activity log Copilot Activity view Only the activity.jsonl file, with --activity-log
    Report preview runtime F&O Studio: Install Report Preview Runtime xpp_render_report and xpp_compare_layout need the same runtime in %LOCALAPPDATA%\FOStudio\ReportViewer; install it once with the VS Code command

    For deploy, database sync, tests and SQL credentials on a UDE outside VS Code, use the core library (Core-Library): it has deployPackages, syncDatabase, runTests and requestSqlCredentials with a sign-in your host provides.

    How it works¶

    • Program.Main reads the configuration (from --config or the registry), registers AssemblyResolve to <FrameworkDirectory>\bin, and only then runs the code that uses D365FO types (server/Program.cs).
    • McpStdioServer reads stdin line by line; read-only tools run in parallel, everything else in order, and one lock guards the metadata API (server/McpStdioServer.cs).
    • Tools come from the registry in ToolRouter and the embedded Tools.json; the server refuses to start when the two differ (MCP-Agent-Tools).
    • The release workflow builds the server against Microsoft's compiler package, checks that server\bin holds no Microsoft DLL, zips it and writes the .sha256 (.github/workflows/release.yml). See Release-Process.

    Limitations¶

    • Windows only, on a machine with a D365FO configuration and its packages; the server does no cloud setup itself.
    • No sign-in: tools that need Dataverse or SQL credentials exist only in the VS Code extension or through the core library.
    • The server is unsigned unless the release was signed.
    • One server process serves one configuration; start another process for another environment.

    Troubleshooting¶

    Symptom Cause Fix
    The process exits at once with code 1; stderr says No usable D365FO configuration (...) No configuration in the registry, or the file passed with --config has no usable packages Pass --config with a valid configuration, or set up the environment first
    Tools answer MetaModel bridge is not available... The configuration points to a PackagesLocalDirectory that is missing or not extracted Finish the environment setup
    The host shows no tools The host could not start the process, or the arguments are wrong Check the command path and arguments; read the server's log on stderr
    xpp_find_references explains the cross-reference database is missing No XRef database for the configuration Restore it (Connect-to-Environment)
    No active project. Select one with xpp_select_project. Started without --project Pass --project or let the agent select one
    The report preview needs Microsoft's Report Viewer runtime The runtime is not installed Install it once with F&O Studio: Install Report Preview Runtime in VS Code

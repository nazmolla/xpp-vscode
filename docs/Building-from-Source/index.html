    Building from Source¶

    This page explains how to build F&O Studio from its GitHub repository, run it in a development host, and package a local VSIX for testing. It is for contributors and for anyone who wants to check what the extension does by building it themselves.

    You do not need this to use F&O Studio: install it from the Visual Studio Marketplace (see Getting-Started).

    What gets built¶

    Output From Tool
    core/dist/ core/src (@fno-studio/core) tsc -p core
    out/ src/ (the extension) tsc -p .
    server/bin/XppVsCode.Server.exe (+ .config) server/ (.NET Framework 4.8, x64) dotnet build through scripts/build-server.ps1
    tools/pdb2pdb/ Microsoft.DiaSymReader.Pdb2Pdb (MIT), downloaded scripts/fetch-pdb2pdb.ps1
    xpp-vscode-<version>.vsix all of the above vsce package

    All of these are in .gitignore; the repository holds only sources.

    Before you start¶

    • Windows. The server targets .NET Framework 4.8 x64 and the extension only runs on Windows.
    • Node.js 20 or later (core requires >=20; the release workflow uses Node 22) and npm.
    • .NET SDK with dotnet build and dotnet test. The server project uses Microsoft.NETFramework.ReferenceAssemblies, so you do not need a .NET Framework developer pack.
    • A Dynamics 365 Finance and Operations installation whose PackagesLocalDirectory\bin contains xppc.exe and Microsoft.Dynamics.AX.Metadata.dll. Any of these works:
    • a unified developer environment connected with Connect to Environment… (installed F&O Studio, or Visual Studio's Power Platform Tools);
    • a cloud-hosted or VHD environment;
    • any folder with those files, given in the environment variable XPP_BIN.
    • Git to clone https://github.com/nazmolla/xpp-vscode.git.
    • Optional: MSBuild (Visual Studio or Build Tools) for the C# reference tests.

    The server compiles against Microsoft's assemblies but never copies them: every reference to them has <Private>false</Private>. At run time the server loads them from the installation of whoever runs it.

    How to build¶

    1. Clone and install the development dependencies:
    git clone https://github.com/nazmolla/xpp-vscode.git
cd xpp-vscode
npm install

    The extension has no runtime npm dependencies; npm install gets TypeScript, @types/*, @vscode/test-electron and @vscode/vsce.

    1. Build everything:
    npm run build

    This runs, in order:

    Script Does
    npm run build:server scripts/build-server.ps1
    npm run build:tools scripts/fetch-pdb2pdb.ps1
    npm run compile tsc -p core && tsc -p .
    1. Check the output: server\bin\XppVsCode.Server.exe, tools\pdb2pdb\Pdb2Pdb.exe, core\dist\index.js and out\extension.js exist.

    How build-server.ps1 finds the D365FO binaries¶

    The script takes the first candidate folder that contains xppc.exe:

    1. XPP_BIN;
    2. FrameworkDirectory of the active configuration (registry HKCU\Software\Microsoft\Dynamics\AX7\Development\Configurations, value CurrentMetadataConfig);
    3. the registry's FrameworkDirectory;
    4. every configuration in %LOCALAPPDATA%\Microsoft\Dynamics365\XPPConfig, newest first;
    5. on cloud-hosted and VHD environments, the local AOS's Aos.PackageDirectory (from the batch service's web.config) and Visual Studio's machine default configuration.

    Each candidate gets \bin appended. When nothing matches, the script stops with "D365FO compiler (PackagesLocalDirectory\bin\xppc.exe) not found".

    It then runs:

    dotnet build server\XppVsCode.Server.csproj -c Release -o server\bin -p:D365BinPath=<bin> -p:Version=<package.json version>

    -p:Version puts the extension's version into the exe's file metadata (Product "F&O Studio for VS Code"); the release build checks it. The project also stops with a clear error when D365BinPath has no Microsoft.Dynamics.AX.Metadata.dll.

    Options: -Configuration Debug for a debug build, -Test to run the server unit tests after the build (npm run test:server does that and also runs the bridge contract check).

    Pdb2Pdb¶

    xppc writes Windows PDBs; the VS Code debugger (vsdbg) reads only portable ones, so builds convert them, and the VSIX must carry Pdb2Pdb. fetch-pdb2pdb.ps1 downloads a pinned version from the public .NET tools feed, checks its SHA-256 and extracts it into tools\pdb2pdb. It does nothing when that version is already there.

    Run the extension from source¶

    The repository has a launch configuration Run Extension (.vscode/launch.json) that starts an Extension Development Host with --extensionDevelopmentPath=${workspaceFolder} and runs the npm: compile task first.

    1. Build the server once (npm run build:server), because launching does not build it.
    2. Open the repository folder in VS Code.
    3. Press F5 (Run and Debug > Run Extension).
    4. In the new window, open a D365FO workspace or project and use F&O Studio as usual.

    For continuous TypeScript builds use npm run watch (extension only; rebuild core with tsc -p core when you change it).

    After a server change, rebuild the server and run F&O Studio: Restart X++ Server in the development host. Copilot's MCP server restarts when VS Code restarts it; reload the window if it still uses the old exe.

    Package a VSIX for testing¶

    npm run package

    This fetches Pdb2Pdb, regenerates CHANGELOG.md from docs/FEATURES.md, and runs vsce package with docs/FEATURES.md as the Marketplace overview. Install the result with Extensions: Install from VSIX….

    .vscodeignore keeps sources, scripts, tests, docs and server/ out of the package, except server/bin/XppVsCode.Server.exe and its .config.

    A local build's server is unsigned. npm run publish refuses on purpose: releases are built, signed and published by the release workflow. See Release-Process.

    Other generated files¶

    Command Writes Check
    npm run agents agents/*.agent.md, agents/fno-agents.instructions.md, chatAgents and chatInstructions in package.json, from scripts/agent-definitions.js node scripts/build-agents.js --check
    npm run changelog CHANGELOG.md from the "What's new" sections of docs/FEATURES.md node scripts/changelog.js --check

    Never edit the generated files by hand; the release build fails when they are out of date.

    Project layout¶

    Folder Contents
    src/ extension (TypeScript)
    core/ @fno-studio/core (TypeScript, Node, no VS Code)
    server/ metadata and MCP server (C#)
    server/Resources/ embedded agent instructions, agent guide, Tools.json, report resources
    media/ webview scripts, styles and icons
    syntaxes/ X++ TextMate grammar
    agents/ generated Copilot agents
    scripts/ build, check and test scripts
    test/ extension-host smoke tests (*.js) and the server unit tests (test/server)
    docs/ Marketplace overview (FEATURES.md), roadmap, review findings, images
    .github/workflows/release.yml release build

    Troubleshooting¶

    Symptom Cause Fix
    "D365FO compiler (PackagesLocalDirectory\bin\xppc.exe) not found" No configuration with a usable FrameworkDirectory on this machine Connect to a UDE, build on a cloud-hosted or VHD environment, or set XPP_BIN to a folder with xppc.exe
    "Set D365BinPath (or XPP_BIN) to PackagesLocalDirectory\bin" dotnet build ran without the script, or the folder lacks Microsoft.Dynamics.AX.Metadata.dll Use npm run build:server, or pass -p:D365BinPath=...
    "Pdb2Pdb ... has hash ..., expected ..." The download was changed or corrupted Delete tools\pdb2pdb and run npm run build:tools again
    The development host says the X++ server could not run server\bin\XppVsCode.Server.exe is missing npm run build:server
    check-core.js fails after your change Something in core/ imports vscode or reaches into src/ Move the VS Code part to the extension and pass it in (see Core-Library)
    MSBuild skips a rebuild after you restored files with Copy-Item Old timestamps Touch the files

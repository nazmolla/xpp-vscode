    Wizard: Batch Job¶

    New Batch Job (SysOperation)… creates a complete SysOperation batch job in your model: a data contract, a service class, a controller, an action menu item and a privilege. You enter a name and a caption; the wizard writes the standard pattern, so you only write the job's work in the service's process method. Visual Studio has no equivalent wizard; there you create the five elements by hand.

    When to use it¶

    • You need a new periodic job that users run from a menu, either at once or scheduled in batch.
    • You want the current SysOperation pattern (contract, service, controller) instead of the older RunBaseBatch.
    • You want the menu item and the privilege created with the code, so security is not forgotten.

    Before you start¶

    • A D365FO project is open (D365FO Projects). The wizard creates its elements in the project's model and stops with Open a D365FO project first: the new elements go to its model. when no project is open.
    • The metadata server runs (F&O Studio is connected to an environment, see Connect to Environment).
    • Optional: your model has a label file with an en-US language. The wizard then puts the caption in a label; otherwise it uses the plain text (see Labels).

    How to use it¶

    Where to find it¶

    Place How
    Dynamics 365 view Create > New Batch Job…
    New Element Wizards > Batch job (SysOperation)
    Command Palette F&O Studio: New Batch Job (SysOperation)…

    Prompts¶

    # Prompt (title) What to enter Example
    1 New batch job (SysOperation): name Base name with your prefix. The classes get Contract, Service and Controller appended. Letters, digits and _, starting with a letter, 3 to 61 characters. ContosoPostVendInvoices
    2 New batch job: caption What users see on the menu and in the batch job list Post vendor invoices

    The grey text in each box (for example ABCPostVendorInvoices) is a placeholder, not a default value. Leave a box empty or press Escape to cancel; nothing is created.

    Result¶

    A progress notification Creating ContosoPostVendInvoices… shows each element as it is created. Then a message lists the elements and reminds you to add the privilege to a duty and write the job in the service. Open Service opens the service class.

    Elements created¶

    For base name ContosoPostVendInvoices:

    Element Type Content
    ContosoPostVendInvoicesContract Class [DataContractAttribute] class with one parameter, parmTransDate (TransDate)
    ContosoPostVendInvoicesService Class Extends SysOperationServiceBase; empty process(ContosoPostVendInvoicesContract _contract)
    ContosoPostVendInvoicesController Class Extends SysOperationServiceController; main and defaultCaption
    ContosoPostVendInvoices Action menu item Label = caption, Object type Class, Object = the controller
    ContosoPostVendInvoicesGenerate Security privilege Label = caption, entry point on the menu item with Invoke access

    All five are added to the project.

    Generated code¶

    The contract:

    /// <summary>
/// Parameters of Post vendor invoices.
/// </summary>
[DataContractAttribute]
class ContosoPostVendInvoicesContract
{
    TransDate transDate;

    /// <summary>
    /// The date the job works for.
    /// </summary>
    [DataMemberAttribute]
    public TransDate parmTransDate(TransDate _transDate = transDate)
    {
        transDate = _transDate;
        return transDate;
    }

}

    The service, where you write the job:

    /// <summary>
/// Post vendor invoices: the work, run by ContosoPostVendInvoicesController in batch or interactively.
/// </summary>
class ContosoPostVendInvoicesService extends SysOperationServiceBase
{
    /// <summary>
    /// Runs the job for the contract's parameters.
    /// </summary>
    /// <param name="_contract">The parameters.</param>
    public void process(ContosoPostVendInvoicesContract _contract)
    {
        // Write the job's work here for _contract.parmTransDate(), in one transaction per unit of work so a restart can continue.
    }

}

    The controller:

    /// <summary>
/// Starts Post vendor invoices (dialog, batch scheduling) for ContosoPostVendInvoicesService.
/// </summary>
class ContosoPostVendInvoicesController extends SysOperationServiceController
{
    /// <summary>
    /// Entry point of the menu item.
    /// </summary>
    /// <param name="_args">Menu item arguments.</param>
    public static void main(Args _args)
    {
        ContosoPostVendInvoicesController controller = new ContosoPostVendInvoicesController(classStr(ContosoPostVendInvoicesService), methodStr(ContosoPostVendInvoicesService, process), SysOperationExecutionMode::Synchronous);
        controller.parmArgs(_args);
        controller.startOperation();
    }

    /// <summary>
    /// The caption of the dialog and the batch job.
    /// </summary>
    /// <returns>The caption.</returns>
    public ClassDescription defaultCaption()
    {
        return "@ContosoLabels:ContosoPostVendInvoices";
    }

}

    When the model has no label file, defaultCaption returns the caption text instead, for example "Post vendor invoices".

    After the wizard¶

    1. Write the work in ContosoPostVendInvoicesService.process. Add parameters to the contract as parm methods with [DataMemberAttribute]; the SysOperation framework puts them on the dialog.
    2. Add the privilege ContosoPostVendInvoicesGenerate to a duty (for example with a duty extension or Add to Privilege), and the menu item to a menu.
    3. Build (Build Project and Model) and deploy (Deploy to Environment).
    4. Open the menu item in the web client (Copy Name and Open in Browser). The dialog shows the date parameter and the batch options.
    5. Write a test (Generate SysTest Class) that calls the service with a contract.

    Labels¶

    Before creating the elements, the wizard looks for a label file in your model (a file <LabelFileId>_en-US.xml under the model's AxLabelFile folder). When it finds one, it creates a label with the ID = the base name and the text = the caption, and uses @<LabelFileId>:<base name> in the menu item, the privilege and defaultCaption. When there is no label file, or the label cannot be created (for example the ID exists), the plain caption is used; Best Practice Checks then report the hard-coded text.

    How it works¶

    1. The wizard is newSysOperationJob in src/scaffolding/batch.ts. It reads the project's model, asks the two questions, and creates the label with the create_label bridge action (src/scaffolding/common.ts).
    2. Each element is a create_object request to the metadata server, which saves it through Microsoft's metadata API (never by writing XML). Each created element is added to the .rnrproj with add_to_project.
    3. All or nothing: when one element fails (for example a class with that name exists), the wizard deletes the elements it already created, in reverse order, and reports the failure, for example Class ContosoPostVendInvoicesService: ... The elements created before it were removed again.
    4. The generated code is checked by scripts/scaffold-test.js: it creates the elements of every wizard in a test model, builds the model with the X++ compiler, requires no errors in the generated elements, lists any warnings, and deletes everything again. The wizards' output is meant to compile without errors or warnings.

    Limitations¶

    • The contract has one example parameter (TransDate). Replace or extend it for your job.
    • The controller runs the operation Synchronous; change the execution mode in main if you need another default.
    • The wizard does not add the privilege to a duty, the menu item to a menu, or write the job's logic.
    • A label created before a failure stays in the label file; only the elements are removed.

    Troubleshooting¶

    Symptom Cause Fix
    Open a D365FO project first: the new elements go to its model. No project is open Open or create a project (D365FO Projects)
    A name of letters, digits and _, starting with a letter. Invalid characters, or fewer than 3 characters Use a valid X++ name
    The wizard closes without creating anything A prompt was left empty or cancelled Run it again and fill both prompts
    Class ...: ... already exists ... and the elements were removed One of the generated names is already used Choose another base name
    Not removed: ... The rollback could not delete some elements Delete them from the project view (Delete)
    The caption shows as plain text, not a label The model has no en-US label file, or the label ID exists Create a label file (Label Editor) or rename the existing label

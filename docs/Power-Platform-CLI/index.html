    Power Platform CLI¶

    The Power Platform CLI (pac) is Microsoft's command-line tool for Power Platform and Dataverse, including unified developer environments (UDE). F&O Studio does not need it: deploy, database sync, tests and environment setup all call the environment's Dataverse directly. Two commands remain for developers who run pac themselves: Sign In to Environment (pac) keeps one pac auth profile per environment, and Initialize Deployment Solution (pac) creates a pac package project for your models.

    When to use it¶

    • You run your own pac commands (scripts, pipelines you test locally, pac solution work) and want a pac profile for the environment this window uses.
    • You want a pac ERP package project in your workspace to package or deploy with pac yourself.

    You do not need pac to:

    Task F&O Studio uses
    Connect to a UDE Dataverse and Microsoft's developer tools service (Connect to Environment)
    Deploy models Dataverse (msprov_fnopackages, msprov_deploypackagetofinopsasync) (Deploy to Environment)
    Synchronize the database Dataverse (msprov_dbsynctofinopsasync) on UDE, SyncEngine.exe on cloud-hosted and VHD (Synchronize Database)
    Run SysTest tests Dataverse (Run Tests)
    Database credentials Dataverse (msprov_getfinopssqljitaccessasync) (Database Access)

    Before you start¶

    • The Power Platform CLI installed, on PATH or at the path in xpp.pacPath.
    • A unified developer environment. On cloud-hosted and VHD environments the (pac) commands are hidden from the Command Palette and the Dynamics 365 view; run from elsewhere, they show "This is a cloud-hosted or VHD environment: your models run on the local AOS once they are built, so there is nothing to deploy."
    • For Initialize Deployment Solution (pac): a folder open in VS Code.

    How to use it¶

    Sign In to Environment (pac)¶

    1. Run F&O Studio: Sign In to Environment (pac) from the Command Palette, or Sign In (pac) in the Dynamics 365 view's Environment group or the status bar environment menu.
    2. The environment is the one this window uses (Select Environment). If none is selected, enter the Dataverse URL in Dataverse environment URL (https://yourorg.crm.dynamics.com).
    3. F&O Studio selects the profile named after the environment's org (pac auth select --name <org>).
    4. If the profile exists, it becomes pac's active profile and you see "pac uses its profile for ." with Sign In Again. Click it to delete the profile and create it again (for example after a password change or when the account was wrong).
    5. If it does not exist, F&O Studio creates it: pac auth create --name <org> --environment <url>. pac opens its own browser sign-in.
    6. The pac commands run as visible tasks in the terminal panel (source X++), so you see pac's output and can answer its prompts.

    Because each environment has its own named profile, environments in different tenants keep their own accounts. Switching the window to another environment and running Sign In again selects that environment's profile. Your own pac commands in the terminal then use it.

    Profile names are the org name, cut to 30 characters (the pac limit).

    Initialize Deployment Solution (pac)¶

    1. Run F&O Studio: Initialize Deployment Solution (pac) from the Command Palette, or Initialize Deployment Solution… in the Dynamics 365 view's Deploy group.
    2. Enter the model names in Model(s) for the deployment solution (comma-separated). The box is filled with the active project's model.
    3. F&O Studio runs, as a visible task named Initialize erp solution:
    pac package init --package-type erp --model <models> --outputDirectory <first workspace folder>

    The result is pac's package project in your workspace folder. Build and deploy it with pac yourself; F&O Studio's Deploy Models to Environment does not use it.

    Using pac in the terminal after Sign In¶

    After Sign In to Environment (pac), the environment's profile is pac's active profile, so your own commands in any terminal go to that environment. For example, to check which profile and org pac uses:

    pac auth list
pac org who

    When you switch the window to another environment with Select Environment…, run Sign In to Environment (pac) again: it only selects that environment's existing profile, without a new sign-in.

    Automating deploy and sync without pac¶

    If you used pac in scripts to deploy and sync from your machine, the xpp task type does the same through Dataverse, with your local build. Add tasks to .vscode/tasks.json:

    {
    "version": "2.0.0",
    "tasks": [
        { "type": "xpp", "action": "buildModel", "label": "Build model" },
        { "type": "xpp", "action": "deploy", "dbSync": "Module", "label": "Deploy and sync my package" },
        { "type": "xpp", "action": "syncDatabase", "mode": "Full", "label": "Full database sync" }
    ]
}

    deploy deploys the package of the active project's model as built on this machine (dbSync: None by default, Module or Full). syncDatabase takes mode (Full by default, or Module with modules, a comma-separated list that defaults to the project's model). See Build Tasks.

    Options and settings¶

    Setting Default Effect
    xpp.pacPath empty Path to pac. Empty: pac on PATH. A value that contains a quote character is ignored and pac is used.
    xpp.environmentUrl empty Default environment; the sign-in uses the window's environment.

    How it works¶

    The commands are in src/pac.ts (class PacCommands, which also holds deploy and database sync, which no longer use pac).

    • pac runs through a shell task (ShellExecution) because pac from PATH is usually a .cmd shim. The task is revealed in the shared terminal panel and its exit code is awaited.
    • Selecting the profile runs pac auth select --name <org> in the background (60-second timeout). Success means the profile exists.
    • A non-zero exit fails the command with "pac failed (exit n). Is the Power Platform CLI installed and signed in? See the terminal output."
    • pac keeps its profiles in its own store. F&O Studio never reads or stores pac's tokens. Its own Dataverse calls use VS Code's Microsoft account (Sign-In and Authentication), so signing in with pac does not sign in F&O Studio, and the other way round.

    Why deploy does not use pac¶

    Earlier versions deployed with pac. pac's package compile recompiles a scaffolded copy of your model with pac's own compiler, so the build you made locally (and its PDBs for the debugger) never reached the environment. F&O Studio now deploys the packages exactly as built on your machine, the way Visual Studio's Deploy Models to Online Environment does. See Deploy to Environment. The Dynamics 365 view still shows pac as the description of some Deploy entries; they run through Dataverse.

    Limitations¶

    • Only sign-in and package initialization are wrapped. Other pac commands you run yourself in the terminal.
    • Initialize Deployment Solution (pac) writes into the first workspace folder only.
    • UDE only.

    Troubleshooting¶

    Symptom Cause Fix
    "pac auth create failed (exit n). Is the Power Platform CLI installed and signed in?..." pac not found or the sign-in failed Install the Power Platform CLI or set xpp.pacPath; read the task output.
    The sign-in uses the wrong account The profile was created with another account Run Sign In to Environment (pac) and click Sign In Again.
    "Open a workspace folder first." Initialize Deployment Solution (pac) needs a folder Open your workspace folder.
    The (pac) commands are missing from the Command Palette The active environment is cloud-hosted or VHD Not needed there.
    xpp.pacPath seems ignored The path contains quotes Remove the quotes from the setting.

    FAQ¶

    Answers to the questions D365FO developers ask most about F&O Studio. For error messages, see Troubleshooting; for terms, see the Glossary.

    General¶

    What is F&O Studio?¶

    A VS Code extension, F&O Studio for VS Code (ID MNazmi.xpp-vscode), for Dynamics 365 Finance & Operations X++ development without Visual Studio. It has an Application Explorer, element, form and report designers, X++ code navigation, build, best practice checks, deployment packages, deploy, database sync, the debugger, data browsing, and agent tools and agents for GitHub Copilot. See Getting-Started.

    Is it from Microsoft?¶

    No. F&O Studio is an independent open-source project under the Apache License 2.0. It is not affiliated with or endorsed by Microsoft. It uses Microsoft's D365FO tools (metadata API, compiler, scripts) from your own installation.

    Is it finished?¶

    It is a preview. Some features are not yet verified end to end on a live environment: the version drift guard, Open Team Repository on a real team repository, Try Data Entity and Try Service Operation, and Verify Changes in the Running App. Cloud-hosted environments use the same code path as VHD environments but have not been tested yet.

    Does it cost anything?¶

    The extension is free. Copilot features need your own GitHub Copilot subscription.

    Visual Studio¶

    Do I need Visual Studio?¶

    No. F&O Studio builds with xppc and LabelC, deploys through the environment's Dataverse and debugs with Microsoft's debugger proxy, without Visual Studio. See Compared-with-Visual-Studio.

    Can I use Visual Studio and F&O Studio on the same machine?¶

    Yes. F&O Studio reads and writes the same configuration Visual Studio uses (the CurrentMetadataConfig registry value and the JSON files in XPPConfig), and the same project (.rnrproj) and export (.axpp) formats. Visual Studio's FinOps tools must match the metadata version; Check Visual Studio's FinOps Tools Version installs the matching tools into Visual Studio when they differ. See Visual-Studio-Side-by-Side.

    Will my projects open in Visual Studio?¶

    Yes. Create D365FO Project… writes a .rnrproj and a .slnx the way Visual Studio does, and the project view follows the .rnrproj, so elements added in Visual Studio show up in F&O Studio and the other way round. See D365FO-Projects.

    Is the build the same as Visual Studio's?¶

    It uses the same compilers: xppc for X++, LabelC for labels and reportsc for reports. Referenced C# projects are built and copied into the package first, as Visual Studio does. Errors go to VS Code's Problems view. See Build-Project-and-Model.

    Is the deploy the same as Visual Studio's?¶

    On a unified developer environment, Deploy Models to Environment uploads your packages as built on this machine through the environment's Dataverse, as Visual Studio's Deploy Models to Online Environment does. Nothing is recompiled, so the environment runs the build you debug. See Deploy-to-Environment.

    Environments¶

    Which environments does it support?¶

    Unified developer environments (UDE), cloud-hosted environments (CHE) and VHD environments, on Windows. A UDE needs Connect to Environment… once; a cloud-hosted or VHD environment needs no setup. See Connect-to-Environment and Cloud-Hosted-and-VHD-Environments.

    Does it run on macOS or Linux?¶

    No. It needs Windows, because Microsoft's D365FO compiler and metadata API are Windows tools.

    What does Connect to Environment download, and where?¶

    The standard metadata (PackagesLocalDirectory), the cross-reference database backup and the FinOps tools for the environment's application version, from the same Microsoft service Visual Studio's Power Platform Tools use. They go into %LOCALAPPDATA%\Microsoft\Dynamics365\<application version>\. You need about 16 GB of free disk space. The cross-reference database is restored into SQL Server LocalDB.

    Can I work with several environments?¶

    Yes. Connect each one, then switch with Select Environment… or the environment name in the status bar. Each workspace remembers its environment, so two VS Code windows can work with two environments. See Select-Environment.

    The UDE was updated. What do I do?¶

    F&O Studio warns you when the environment runs a newer application version than the metadata on your machine. Select Update Metadata to download the new version, and Clean Up Old Application Versions… to remove old ones. See Version-Drift-Guard.

    Why are Deploy and Run Tests missing?¶

    They are UDE-only: they run through the environment's Dataverse, which cloud-hosted and VHD environments do not have. F&O Studio hides them there. On those environments the build goes into the local PackagesLocalDirectory and the running AOS restarts after a successful build.

    Do I need the Power Platform CLI (pac)?¶

    No. Deploy and database sync run through Dataverse directly. Only Sign In to Environment (pac) and Initialize Deployment Solution (pac) use pac, for when you run your own pac commands. See Power-Platform-CLI.

    Do I need SQL Server LocalDB?¶

    Yes, for the cross-reference database. Find References, rename, the references diagrams and the report data provider list use it.

    Development¶

    Can I change standard code?¶

    No, the same as in Visual Studio. Standard elements are read-only; you extend them with Create Extension (metadata) or Create Code Extension (Chain of Command), or event handlers. Delete and rename work only on elements of your own models. See Create-Extension and Create-Code-Extension.

    Does F&O Studio write AOT XML files by hand?¶

    No. Metadata changes go through Microsoft's metadata API, as in Visual Studio. Only the project file (.rnrproj) and the label text files are edited directly, because they are not AOT metadata.

    Can I debug Microsoft's code?¶

    Yes, on unified developer environments: set a breakpoint in the code view of a standard element (for example the init method of the PurchTable form). Open the form or run the code once before you start the debugger, so the breakpoint binds right away. See Debugging-Standard-Code.

    Can I debug on a cloud-hosted or VHD environment?¶

    Yes. Launch Debugger attaches to the local AOS with the C# extension's .NET debugger; F&O Studio offers to install the C# extension. See Debugging-on-Cloud-Hosted.

    Can I use C# projects with my X++ project?¶

    Yes. The project view shows the solution's C# projects; Add Reference… and New C# Project… add references and C# class libraries, and the build compiles them first. See Solution-View-and-CSharp-References.

    Can I build an LCS deployable package?¶

    Create Deployment Package… runs the same script Visual Studio runs (RunPackageCreationAll.ps1 from PackagesLocalDirectory's bin folder). See Create-Deployment-Package.

    Does it have SSRS report design?¶

    Yes. The element designer shows reports as Visual Studio does, the Report Designer lays out precision designs, and the preview renders with Microsoft's report engine. The preview downloads Microsoft's Report Viewer runtime from nuget.org the first time, after you accept Microsoft's licence. See Report-Designer and Report-Preview.

    Data¶

    Can I look at table data?¶

    Yes. Browse Table Data and New SQL Query work against the environment's database. On a UDE, F&O Studio requests temporary SQL credentials (the same just-in-time request Visual Studio makes); on a cloud-hosted or VHD environment it uses the local AxDB with Windows authentication. See Database-Access.

    Why does the database request fail?¶

    Database access on a unified developer or sandbox environment needs the System administrator role. New credentials can take a minute before Azure SQL accepts them. See Troubleshooting.

    Can a query change data?¶

    New SQL Query is read-only by default: one SELECT, always rolled back. Allow changes commits after a confirmation each run, with a warning that X++ business logic is skipped. Copilot's xpp_query_data runs only a read-only, row-limited SELECT after your confirmation. See SQL-Query-Panel.

    Copilot¶

    Do I need GitHub Copilot?¶

    Only for the agents and the agent tools. Everything else works without it.

    What can Copilot do with F&O Studio?¶

    It gets agent tools to read, create, extend, validate and build elements through the metadata API, search code, find references and message sources, analyze security, performance and traces, run tests and, with your confirmation, read data. F&O agents (for developers and for functional consultants) appear in the chat's agent picker. See Copilot-Agents and MCP-Agent-Tools.

    Can Copilot break my model or change standard code?¶

    Agent tools write only to your own models, every write is all or nothing, and an existing name is never overwritten. Standard elements are extended, never changed. Start Copilot Checkpoint lets you revert everything Copilot changed afterwards, and Set Copilot Scope… limits which elements it may change; the server enforces both. See Copilot-Checkpoints-and-Scope and Scenario-Work-Safely-with-Copilot.

    Does Copilot see my database credentials?¶

    No. xpp_query_data runs one read-only query after your confirmation, and the agent never sees the credentials.

    Where did @fno go?¶

    It was removed, because VS Code retires chat participants. Pick an F&O agent in the chat's agent picker instead: for example /extend became the F&O Developer agent and /review the Code Reviewer.

    Can I share rules with my team for Copilot?¶

    Yes. Create Team Rules for Copilot creates .xpp/agent-rules.md in your repository; it is added to the agent instructions of everyone working in the repository. See Team-Rules.

    Can I use the agent tools outside VS Code?¶

    Each GitHub release includes a standalone server package (fno-studio-server-X.Y.Z.zip) with its SHA-256 checksum for MCP hosts outside VS Code. See MCP-Server-Outside-VS-Code.

    Privacy and security¶

    Does F&O Studio collect telemetry?¶

    No. It talks to the Finance and Operations and Dataverse environments you connect it to, Microsoft's download service for that environment's tools, nuget.org for the report preview runtime (after you accept the licence), and GitHub only when you choose to report a problem. Optional command counts stay on your machine. See Usage-Statistics.

    Does it ship Microsoft's assemblies?¶

    No. The extension's server is compiled against Microsoft's D365FO assemblies but never includes them; it loads them at run time from your own installation.

    How do I sign in?¶

    With VS Code's Microsoft account sign-in. If your tenant does not allow VS Code's default sign-in for Dataverse, set xpp.auth.clientId to your own Entra application ID. See Sign-In-and-Authentication.

    Where are database credentials stored?¶

    In VS Code's secret storage, until they expire. Forget Database Credentials removes them.

    Support¶

    How do I report a problem?¶

    Use Report a Problem… (Command Palette, the bottom of the Dynamics 365 view, or the Report Problem button on an error). It shows you a redacted report first. See Report-a-Problem.

    Where are the logs?¶

    In the Output panel: X++ (server, setup, debugger, failed commands), X++ Build, X++ Deploy and X++ Tests.

    Where is the source code?¶

    On GitHub: nazmolla/xpp-vscode. See Building-from-Source and Architecture.

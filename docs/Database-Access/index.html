    Database Access¶

    F&O Studio reads (and, if you ask for it, changes) the business database of your active environment. All data features use this access: Browse Table Data, the SQL Query Panel, Explain Plan, Database Performance Insights, Open in SSMS and the agent tool xpp_query_data. On a cloud-hosted or VHD environment it connects to the local AxDB with Windows authentication. On a unified developer environment (UDE) it requests temporary just-in-time (JIT) SQL credentials, the same request Visual Studio's Power Platform Tools make, and keeps them in VS Code's secret storage until they expire.

    When to use it¶

    • You want to see the rows behind a form, check setup, or confirm what your code wrote.
    • You investigate a performance problem and need query plans or the database's own statistics.
    • A Copilot agent needs to look at real data (it asks you before each query).
    • You want to open the same database in SQL Server Management Studio without copying passwords around by hand.

    Before you start¶

    Environment What F&O Studio connects to What you need
    Unified developer environment (UDE) The environment's Azure SQL database A selected environment (Select Environment or the xpp.environmentUrl setting), a Microsoft sign-in (Sign-In and Authentication), and the System administrator role in the environment
    Cloud-hosted or VHD environment The local business database (AxDB by default) on this machine A Windows account that can sign in to the local SQL Server

    F&O Studio decides which case applies from the active configuration: a configuration without RuntimePackagesDirectory and with a host type other than 4 is treated as local (cloud-hosted or VHD). For a local environment the server and database come from the configuration's DatabaseServer and BusinessDatabaseName (defaults localhost and AxDB). On cloud-hosted and VHD machines F&O Studio writes that configuration itself from the AOS settings DataAccess.DbServer and DataAccess.Database. See Cloud-Hosted and VHD Environments.

    How to use it¶

    Where to find it¶

    • Dynamics 365 view, Data group. The group shows the access state next to its name: no access, the database name (local), or the role and expiry time (for example Reader · until 14:30). It contains Browse Table Data…, New SQL Query, Performance Insights… and Database… (credentials, connection, SSMS).
    • Status bar. Once there is access, a $(database) item shows the database name (local) or the role and expiry (Reader until 14:30). Its tooltip names the database, server, user and expiry. Click it to open the Database menu. It stays hidden while a UDE has no credentials. See Status Bar.
    • Environment menu. The environment status bar menu has a Database… entry that opens the same menu.
    • Command Palette (category F&O Studio): Request Database Credentials, Forget Database Credentials, Test Database Connection, Copy Database Connection Detail, Open Database in SQL Server Management Studio, Browse Table Data, New SQL Query, Database Performance Insights.

    The Database menu¶

    The menu title is Database of <environment>. It offers:

    Entry What it does
    Browse Table Data… Opens Browse Table Data after you pick a table
    New SQL Query Opens an empty SQL Query Panel
    Performance Insights… Opens the Database Performance Insights picker
    Test Connection Connects and reports the database, server, signed-in SQL user and SQL Server version
    Open in SQL Server Management Studio See Open in SSMS
    Copy Connection Detail… Copies the server, database, user name or password to the clipboard
    Request Database Credentials… / Request New Credentials… UDE only (or when there is no access yet)
    Forget Credentials UDE only, when credentials are stored

    Request credentials on a UDE¶

    You do not have to request credentials up front. The first data feature you use asks in a modal dialog: "The database of a unified environment needs temporary credentials." Choose Request Credentials. You can also run F&O Studio: Request Database Credentials directly.

    1. Reason (1/3). Describe why you need access, at least five characters, for example Investigate why sales order SO-001234 does not post. The reason is recorded with the request.
    2. Allowed IPv4 addresses (2/3). The database firewall refuses connections from other addresses. The box is prefilled with this machine's public address, as seen by https://checkip.amazonaws.com/ (the service Visual Studio uses). Enter a single address (203.0.113.10) or a range (203.0.113.1-203.0.113.50); the first address of a range must not be above the last. If you are offline the box starts empty.
    3. Access (3/3). Choose Reader (read data only, recommended) or Writer (read and change data; changes made in SQL skip X++ business logic). If you already have valid credentials, the prompt warns that new credentials replace them, including credentials Visual Studio requested.
    4. A progress notification shows while the request runs; you can cancel it.
    5. When it succeeds you see Database credentials (Reader) for <environment> until <date and time>. They are kept in VS Code's secret storage. The status bar item and the Data group update.

    Azure SQL needs a few minutes to apply the new firewall rule and password. If a connection fails with a sign-in error in the first ten minutes after the request, F&O Studio tells you the credentials are not active yet and keeps them. Try again a minute later.

    Test and copy the connection¶

    • Test Database Connection shows Connected to <database> on <server> as <user> (SQL Server <version>).
    • Copy Database Connection Detail lets you pick Server, Database, User name or Password (the last two only with JIT credentials). The value goes to the clipboard. Paste the password where you need it, then clear the clipboard.

    Forget credentials¶

    Forget Database Credentials deletes the stored credentials for the active environment. The next data feature asks again. On a local environment this command and Request Database Credentials report that the database uses Windows authentication and needs no credentials.

    Read-only by default¶

    Every read goes through the same rules, whichever feature sends it:

    • One statement, SELECT only. A read-only batch must start with SELECT or WITH, contain a single statement (a trailing ; is fine) and use none of these keywords outside strings, quoted names and comments: INSERT, UPDATE, DELETE, MERGE, TRUNCATE, DROP, ALTER, CREATE, EXEC, EXECUTE, SP_EXECUTESQL, GRANT, REVOKE, DENY, INTO, BACKUP, RESTORE, DBCC, KILL, SHUTDOWN, RECONFIGURE, BULK, OPENROWSET, OPENQUERY, OPENDATASOURCE, OPENXML, WRITETEXT, UPDATETEXT, COMMIT, ROLLBACK, SAVE, BEGIN, USE, SET, DECLARE, WAITFOR, CHECKPOINT, SETUSER, REVERT.
    • Always rolled back. The batch runs inside a READ COMMITTED transaction that is rolled back afterwards, even when the keyword check passed. The keyword check is the first line of defence; the rollback is the second.
    • Bounded output. At most 5 result sets, a row limit per result set (the panel's choice, at most 10,000), cells longer than 4,000 characters cut, binary values shown as hex up to 64 bytes.
    • Time limit. 60 seconds by default (at most 600).

    Changing data needs an explicit choice in the SQL Query Panel: the Allow changes check box, which is only enabled on a local database or with Writer credentials, and a confirmation for every run. Agents can never change data.

    Options and settings¶

    Setting Default Effect
    xpp.environmentUrl empty Dataverse URL of your default unified developer environment. Credentials are requested from the selected environment; Select Environment chooses another one per workspace.

    There are no settings for row limits or timeouts; they are chosen in the panels.

    How it works¶

    Where each part runs¶

    Part Where Source
    Access state, status bar, Database menu Extension src/database/connection.ts, src/database/index.ts
    Credential prompts and secret storage Extension src/database/credentials.ts
    JIT credential request @fno-studio/core core/src/data/credentials.ts
    Data client, read-only agent query @fno-studio/core core/src/data/client.ts
    SQL execution Extension's own server process, JSON-RPC method xpp/data server/Host/DataQueryService.cs
    Read-only check Server server/Host/ReadOnlySql.cs

    Requesting JIT credentials¶

    requestSqlCredentials calls the unbound Dataverse action msprov_getfinopssqljitaccessasync on the selected environment with three inputs:

    {
  "sqljitclientipaddress": "203.0.113.10",
  "sqljitreason": "Investigate why sales order SO-001234 does not post",
  "sqljitrole": "Reader"
}

    The output parameters servername, databasename, sqljitusername, sqljitpassword, sqljitrole, sqljitexpiration and ipaddress (names compared without case) become the stored credentials. If the server, database, user or password is missing, the request fails with "The environment did not return database credentials. Database access needs the System administrator role in a unified developer or sandbox environment." and the operationhistoryid, when the service returns one.

    Credential lifetime and storage¶

    • The credentials are stored as JSON in VS Code's secret storage (Windows Credential Manager) under the key xpp.database.<environment name>. They are never written to settings, logs or files.
    • The expiry is the one the service returns (sqljitexpiration). When it parses as a date, F&O Studio drops expired credentials the next time it reads them, and a timer refreshes the status bar at the expiry time.
    • If the database refuses the sign-in (SQL errors 18456, 40615, 18487, 18488) more than ten minutes after the request, F&O Studio deletes the stored credentials so the next use asks again. The message says the credentials expired, were replaced, or this address is not allowed.

    The connection travels with each request¶

    The extension starts its own server process with --allow-data (src/serverClient.ts). Only that process answers xpp/data. Each request carries the connection (server, database, and either Windows authentication or the user and password); the server opens a connection for the request and never stores or logs the credentials. SQL logins use an encrypted connection with certificate validation (Encrypt=true, TrustServerCertificate=false), a 20-second connect timeout and the application name F&O Studio, so the sessions are recognisable on the server.

    Values come back in a form JSON keeps exactly: 64-bit integers (RecId, RefRecId) and decimals as text, dates as yyyy-MM-ddTHH:mm:ss.fff, GUIDs as text.

    Data requests run outside the metadata lock, so a long query does not block the designers or code navigation. Cancelling (closing the tab or pressing Cancel) sends cancel with the query's ID and the server cancels the running SQL command.

    Separation from the MCP server¶

    The MCP server that Copilot starts (MCP Agent Tools) is launched without --allow-data. It answers xpp/data with "Method not found". Agents read data only through xpp_query_data, a VS Code language model tool the extension registers (src/database/queryTool.ts):

    • You confirm each query; the confirmation shows the SQL.
    • It runs read-only (never with changes allowed), 50 rows by default, at most 500.
    • The result is tab-separated text cut at 20,000 characters.
    • Without access it answers NO DATABASE ACCESS and tells the agent to ask you to run F&O Studio: Request Database Credentials.
    • The agent never sees the server name, user or password.

    See Agent Tools: Build and Data and Security Model.

    Limitations¶

    • Windows only, like the rest of F&O Studio.
    • One database per window: the active environment's.
    • The firewall rule covers the addresses you entered. If your public address changes (VPN, another network), request new credentials.
    • Changes made with Allow changes skip X++ business logic. Use them only on development data.
    • F&O Studio does not show the request history; the reason is recorded by the environment.

    Troubleshooting¶

    Symptom Cause Fix
    "The environment did not return database credentials. Database access needs the System administrator role…" Your account lacks the role, or the environment is not a UDE Ask for the System administrator role in the environment
    "No environment selected. Run "F&O Studio: Connect to Environment" or "F&O Studio: Select Environment" first." No Dataverse environment selected Run Select Environment or set xpp.environmentUrl
    "The new database credentials are not active yet…" Azure SQL has not applied the firewall rule and password Wait a minute and run again
    "…The credentials expired, were replaced, or this address is not allowed. Request new database credentials." Expired, replaced (for example by Visual Studio), or a new public IP Run Request Database Credentials again
    "…Check that your Windows account can sign in to the database." Local database refused your Windows account Give your account a login on the local SQL Server
    "This environment's database is on this machine and uses Windows authentication; it needs no credentials." You ran a credentials command on a cloud-hosted or VHD environment Nothing to do; use the data features directly
    "Enter an IPv4 address (203.0.113.10) or a range (203.0.113.1-203.0.113.50)." Invalid address in step 2 Use IPv4 only, one address or a range

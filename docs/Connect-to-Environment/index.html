    Connect to Environment¶

    Connect to Environment… prepares this machine for X++ development against a unified developer environment (UDE). It downloads the environment's system metadata (PackagesLocalDirectory), cross-reference database and FinOps tools, extracts and restores them, links the runtime packages, writes the metadata configuration and makes it the active one. It is the same client setup that Visual Studio's Power Platform Tools perform when you connect Visual Studio to a Dataverse environment, and the configuration it writes is the one Visual Studio reads.

    When to use it¶

    • The first time you work with a unified developer environment on this machine.
    • When Microsoft has updated the environment to a new application version and the Version Drift Guard offers Update Metadata. The new version gets its own folder and configuration.
    • When a previous setup failed or was cancelled, to finish it. Steps that are already done are skipped.
    • When you want the same environment's configuration rewritten (for example after you deleted the runtime links folder).

    You do not need it on a cloud-hosted or VHD environment. Those already have PackagesLocalDirectory, an AOS and AxDB on the machine; see Cloud-Hosted and VHD Environments.

    Before you start¶

    Requirement Why
    A unified developer environment (Dataverse environment with finance and operations, deployment type OnlineDev) Setup stops with "Not a unified developer environment" for any other type, such as a sandbox.
    The environment's Dataverse URL, for example https://yourorg.crm.dynamics.com Copy the Environment URL from the Power Platform admin center. The finance and operations URL (https://yourenv.operations.dynamics.com) also works; see below.
    A Microsoft account with access to the environment You sign in through VS Code's Microsoft account. See Sign-In and Authentication.
    SQL Server Express LocalDB with the instance MSSQLLocalDB The cross-reference database is restored into (LocalDB)\MSSQLLocalDB with Windows authentication.
    At least 16 GB free on the drive of %LOCALAPPDATA% Checked before the download when the version's PackagesLocalDirectory is not there yet.
    Windows F&O Studio runs on Windows only. Extraction uses the Windows tar.exe.

    If LocalDB is missing or its instance is not created, setup stops at the second step with a message that tells you to install it or run:

    sqllocaldb create MSSQLLocalDB -s

    How to use it¶

    1. Open the setup in one of these ways:
    2. Dynamics 365 view: Environment group > Connect to Environment….
    3. Status bar: click the environment item (it shows the environment name), then Connect to Environment….
    4. Command Palette: F&O Studio: Connect to Environment….
    5. The Get started walkthrough: step Connect to your environment.
    6. F&O Studio: Select Environment… > Connect to Another Environment….
    7. Enter the Dataverse URL in the input box Connect to a unified developer environment. The box is filled with the environment this window already uses, if any.
    8. The box rejects Power Platform portal pages (powerplatform.microsoft.com, powerapps.com) and tells you to copy the environment's Environment URL instead.
    9. You can enter a URL without https://; it is added.
    10. You can enter the finance and operations URL (https://yourenv.operations.dynamics.com). A UDE's finance and operations host starts with the same org name as its Dataverse host, so F&O Studio looks up <org>.crm.dynamics.com, <org>.crm2.dynamics.com and the other regional Dataverse hosts and uses the one that exists. If none exists, you get "No Dataverse environment found for ..." and should enter the Dataverse URL.
    11. Sign in when VS Code asks (a browser window opens if you have no session for that org yet).
    12. Follow the progress:
    13. A notification X++ environment setup shows Step n/6: <message>. It has a Cancel button.
    14. The X++ output channel opens and logs every message with a time stamp.
    15. The Dynamics 365 view gets focus. Its Environment group lists the six phases with an icon each: pending, running (spinning), done or failed. The running phase shows its current message, such as Downloading PackagesLocalDirectory.zip: 42%.
    16. When setup succeeds you see Environment connected. The Application Explorer, designers and code views now use it. Click Done in the Environment group to return it to the normal environment menu.

    The six phases¶

    # Phase (as shown in the view) What happens
    1 Sign in to Dataverse Interactive sign-in, then two Dataverse calls read the environment details. Setup checks that the deployment type is OnlineDev and that an application version is returned. The log shows Environment <finance and operations URL>, application <version>.
    2 Check SQL Server LocalDB F&O Studio's server (XppVsCode.Server.exe --sql-check) connects to (LocalDB)\MSSQLLocalDB with Windows authentication. Then the free disk space is checked (16 GB) if PackagesLocalDirectory is not there yet.
    3 Download metadata and tools Downloads what is missing: PackagesLocalDirectory.zip, DYNAMICSXREFDB.bak and Microsoft.Dynamics.FinOps.ToolsVS2022.vsix. Progress is reported every 5 seconds.
    4 Extract PackagesLocalDirectory Extracts the zip (this takes several minutes) and deletes it, then extracts the FinOps tools VSIX into a FinOpsTools folder.
    5 Restore cross-reference database Restores the .bak into LocalDB and deletes it. Skipped when the database of the existing configuration is already there.
    6 Configure this machine Creates the runtime package links, writes the configuration file and sets it as the active configuration in the registry.

    When it fails: retry¶

    If a step fails, the phase gets a red icon with the error, the view shows Retry and Done, and an error notification Environment setup failed: ... offers:

    • Retry: runs Connect to Environment again for the same URL without asking for it.
    • Show Log: opens the X++ output channel.
    • Report Problem: opens Report a Problem for this command.

    Retrying is cheap because every step checks what is already on the machine (see What is reused on a second run). A download that failed or was cancelled leaves no partial file: it is written to <file>.partial and renamed only when complete, so a retry starts that file again.

    Options and settings¶

    Setting Default Effect
    xpp.environmentUrl empty Dataverse URL of your default environment. Connect to Environment sets it when it is empty, or when no folder is open. See Select Environment.
    xpp.auth.clientId empty Optional Microsoft Entra app (client) ID for the sign-in, when your tenant does not allow VS Code's default sign-in for Dataverse. See Sign-In and Authentication.

    How it works¶

    The command is registered in src/extension.ts and implemented in src/setup.ts (input, progress, status in the view, retry). The setup itself is runUdeSetup in the VS Code-free core library: core/src/environment/setup.ts, with the Dataverse and download-service calls in core/src/environment/ude.ts. The VS Code side passes in the sign-in (dataverseTokens in src/ude.ts), the progress reporter and a cancellation signal. See Core Library.

    1. Reading the environment from Dataverse¶

    With the Dataverse token, setup calls two unbound Dataverse messages on https://yourorg.crm.dynamics.com/api/data/v9.2:

    Message Values used
    RetrieveFinanceAndOperationsIntegrationDetails Url (finance and operations URL), TenantId
    msprov_getfinopsapplicationdetails applicationdeploymenttype (must be OnlineDev), applicationversion, platformversion, finopsenvironmentid

    Each message is called as an action (POST) first, and as a function (GET with ()) if the org returns 404 or 405.

    2. Downloads¶

    For each asset, setup asks Microsoft's developer tools service for a time-limited download link:

    GET https://developertools.powerplatform.microsoft.com/api/clientmetadata/<resource>?version=<application version with dashes>
Authorization: Bearer <Dataverse token>
dataverseEnvironmentUri: https://yourorg.crm.dynamics.com/
    Resource File
    systemmetadata PackagesLocalDirectory.zip
    crossreference DYNAMICSXREFDB.bak
    finopsvsix22 Microsoft.Dynamics.FinOps.ToolsVS2022.vsix

    The service answers with a blob storage link, which is downloaded into the version folder %LOCALAPPDATA%\Microsoft\Dynamics365\<application version>\. If the server reports a content length and fewer bytes arrive, the download fails as incomplete. This service is not documented by Microsoft; F&O Studio calls it the same way Power Platform Tools does.

    3. Extraction¶

    PackagesLocalDirectory.zip is extracted with %SystemRoot%\System32\tar.exe into <version folder>\PackagesLocalDirectory, then the zip is deleted. The FinOps tools VSIX is extracted into <version folder>\FinOpsTools (it contains the debugger proxy used by the Debugger and Microsoft's configuration template). The VSIX file itself is kept, so Visual Studio Side by Side can install it into Visual Studio.

    4. Cross-reference database¶

    • The database name is XRef_<org><application version without dots>, for example XRef_yourorg10024701234. If that name already exists in LocalDB, _1 to _5 is appended.
    • The data and log files go to %LOCALAPPDATA%\Microsoft\Dynamics365\XPPConfig\<configuration name>\ as DYNAMICSXREFDB1.mdf and DYNAMICSXREFDB1_log.ldf.
    • Before the restore, NETWORK SERVICE gets full control of the Dynamics365 folder, the version folder and the data folder (icacls), because a full SQL Server instance reads the files as that account. Failures of this step are ignored.
    • The restore runs in F&O Studio's server (--restore-xref), the same restore Visual Studio performs:
    RESTORE DATABASE [XRef_...] FROM DISK = @bak WITH REPLACE,
  MOVE 'DYNAMICSXREFDB' TO @mdf, MOVE 'DYNAMICSXREFDB_log' TO @ldf, RECOVERY
    • The .bak is deleted after a successful restore.

    5. Custom metadata folder¶

    Your own models live in the custom metadata folder (ModelStoreFolder). Setup keeps the folder of the active configuration when it is a UDE configuration and the folder exists, so every environment and version builds the same models. Otherwise it creates C:\CustomXppMetadata<random> (on the drive of your user profile).

    6. Runtime package links¶

    Setup creates %LOCALAPPDATA%\Microsoft\Dynamics365\RuntimeSymLinks\<org> and fills it with directory junctions:

    Junction Points to
    bin <version folder>\PackagesLocalDirectory\bin
    PackagesLocalDirectory <version folder>\PackagesLocalDirectory
    ZZZZ__<custom folder name> the custom metadata folder

    An existing folder of that name is deleted first; if it cannot be deleted, <org>1, <org>2 and so on is used. This folder becomes RuntimePackagesDirectory, which the compiler and runtime see as one package folder.

    7. Configuration file and registry¶

    The configuration is written to %LOCALAPPDATA%\Microsoft\Dynamics365\XPPConfig\<org>___<application version>.json. It starts from every member of Microsoft's Template_xppconfig.json (read from FinOpsTools\Resources when present, otherwise built-in values), keeps the values of an existing file for this org and version, and sets:

    {
    "Description": "Unified development environment yourorg. FinOps application version 10.0.x. Configuration generated on <date> by X++ for VS Code.",
    "CloudInstanceURL": "https://yourenv.operations.dynamics.com",
    "ReferencePackagesPaths": [ "...\\Dynamics365\\<version>\\PackagesLocalDirectory" ],
    "FrameworkDirectory": "...\\Dynamics365\\<version>\\PackagesLocalDirectory",
    "ModelStoreFolder": "C:\\CustomXppMetadata...",
    "DebugSourceFolder": "C:\\CustomXppMetadata...",
    "RuntimePackagesDirectory": "...\\Dynamics365\\RuntimeSymLinks\\yourorg",
    "CrossReferencesDbServerName": "(LocalDB)\\MSSQLLocalDB",
    "CrossReferencesDatabaseName": "XRef_..."
}

    Then two values are written under HKCU\Software\Microsoft\Dynamics\AX7\Development\Configurations:

    • CurrentMetadataConfig = the configuration file
    • FrameworkDirectory = the PackagesLocalDirectory folder

    This registry key is where Visual Studio reads its active configuration too, so after a connect Visual Studio uses the same environment. See Visual Studio Side by Side.

    8. Switching the window to the environment¶

    After setup, the window works with the new environment (Select Environment explains how this is stored per workspace). The metadata servers restart, and the Application Explorer, project view, open designers and unchanged code views reload. No window reload is needed. The MCP server for Copilot is restarted with the new configuration as well.

    What is reused on a second run¶

    Item Considered done when
    PackagesLocalDirectory download and extraction <version folder>\PackagesLocalDirectory exists
    Cross-reference download and restore the existing configuration names a database and that database exists in LocalDB
    FinOps tools download <version folder>\FinOpsTools exists
    Any download the downloaded file is already in the version folder
    FinOps tools extraction FinOpsTools\extension.vsixmanifest exists

    The configure phase always runs again: links are recreated, and the configuration and registry are rewritten.

    Disk space¶

    Each application version takes its own folder under %LOCALAPPDATA%\Microsoft\Dynamics365. PackagesLocalDirectory is about 16 GB. After an update, remove versions you no longer need with Clean Up Old Application Versions… (Version Drift Guard).

    Check Environment Connection¶

    F&O Studio: Check Environment Connection (also in the Environment group and the status bar menu) runs every read-only step of the setup without downloading anything:

    1. Signs in.
    2. Reads the environment (type, application, platform, finance and operations URL).
    3. Asks for each asset's download link and reports its size.

    The output goes to the X++ channel:

    --- Checking https://yourorg.crm.dynamics.com
1. Signed in.
2. Environment: type OnlineDev, application 10.0.x, platform 7.0.x, F&O https://yourenv.operations.dynamics.com
3. PackagesLocalDirectory.zip: download link OK, ...
3. DYNAMICSXREFDB.bak: download link OK, ...
3. Microsoft.Dynamics.FinOps.ToolsVS2022.vsix: download link OK, ...
All read-only setup steps succeeded.

    If the environment is not OnlineDev, the log says setup would stop there. If no environment is selected yet, a successful check selects it. If this window works with another environment, you are offered Use This Environment.

    Show Active Environment¶

    F&O Studio: Show Active Environment (Show Active Configuration in the view and status bar menu) writes the active configuration as JSON to the X++ output channel: name, configuration file, framework and bin folders, reference package paths, custom metadata folder, runtime packages folder, cross-reference server and database, business database, application version, web client URL, Dataverse URL and whether it is a local (cloud-hosted or VHD) environment.

    Limitations¶

    • Unified developer environments only. Sandboxes and other environment types are refused.
    • The developer tools download service is undocumented; if Microsoft changes it, setup can fail at the download phase. The manual steps Microsoft documents for Visual Studio (connect with Power Platform Tools) produce a configuration F&O Studio also reads.
    • The cross-reference database always goes to (LocalDB)\MSSQLLocalDB.
    • Interrupted extraction is not detected: if the PackagesLocalDirectory folder exists, extraction is treated as done.
    • Old cross-reference databases are not removed when you clean up versions.

    Troubleshooting¶

    Symptom Cause Fix
    "That is a portal page..." in the URL box You pasted a Power Platform admin center or maker portal link Copy the environment's Environment URL (https://yourorg.crm.dynamics.com).
    "No Dataverse environment found for ..." A finance and operations URL whose org has no regional Dataverse host that resolves Enter the Dataverse URL directly.
    "Not signed in to ..." The sign-in was cancelled Run the command again and complete the sign-in. If your tenant blocks VS Code's sign-in, set xpp.auth.clientId.
    "Not a unified developer environment (type ...)" The environment is not OnlineDev (for example a sandbox) Use a unified developer environment.
    "SQL Server Express LocalDB is not reachable with Windows authentication" LocalDB not installed or instance missing Install SQL Server Express LocalDB or run sqllocaldb create MSSQLLocalDB -s, then Retry.
    "At least 16 GB free disk space is needed on C:\ ..." Not enough space on the drive of %LOCALAPPDATA% Free space (for example with Clean Up Old Application Versions…) and retry.
    "DevTools service returned 4xx for systemmetadata" The download service refused the request Check access to the environment with Check Environment Connection; retry later.
    "Download of ... was incomplete" or failed Network interruption Retry; finished downloads are kept.
    "Extracting PackagesLocalDirectory.zip failed" Disk full or files locked Free space, then retry.
    Build or Application Explorer misses standard packages after a cancelled extraction PackagesLocalDirectory exists but is incomplete; setup treats it as done Delete <version folder>\PackagesLocalDirectory. If the zip is still there, Connect to Environment… extracts it again; otherwise it downloads it.
    "Cross-reference restore failed: ..." LocalDB could not read or write the files, or the name exists Check the message in the log; free space; retry.

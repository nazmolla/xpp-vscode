    Code Lens¶

    Code lens puts small, clickable counts above the code of an element: how many places reference each method, how many Chain of Command wrappers, overrides and event handlers it has, and how many Chain of Command classes, handlers and subclasses the element has. In an extension or handler class it shows what each method wraps or handles. Visual Studio's X++ editor has no code lens; you would run Find References or search for extensions by hand.

    When to use it¶

    • See at a glance which methods are used, and how often, before you change them.
    • See which standard methods are wrapped or handled, so you know where extra code runs.
    • In your own Chain of Command class, jump from each wrapper to the method it wraps.
    • In a handler class, see which event each handler method subscribes to.

    Before you start¶

    • The element must be open in a code view of the whole element (not a single nested method such as a form data source method).
    • Counts come from the cross-reference database and the extension index; see Implementations and Chain of Command.
    • xpp.codeIntelligence.codeLens must be on (the default), and VS Code's own editor.codeLens setting must be on.

    How to use it¶

    Open a class, table or form in the code view. The lenses appear above the first line and above each method signature.

    On the first line (the element)¶

    Lens Shown when Click
    N Chain of Command classes · N event handlers · N subclasses The element has any of them (parts with 0 are left out) Opens Show Extensions and Handlers… for the element
    extends X (Chain of Command) The element is a Chain of Command class ([ExtensionOf(...)]) Opens the extended element
    extension index building… (with a spinning icon) The extension index is not ready yet Runs Rebuild Extension Index

    Above each method¶

    Lens Meaning Click
    N references Calls of the method from the cross-reference database (method calls, test calls and test helper calls) Peeks the references
    N Chain of Command Chain of Command methods that wrap this method Peeks the wrappers
    N overrides Methods in subclasses that override it Peeks the overrides
    N handlers Pre/post, delegate and form/data event handlers of the method Peeks the handlers
    wraps X.method This method is a Chain of Command wrapper Opens the wrapped method
    Post handler of X.method (or another handler kind) This method is an event handler Opens the handled method or element

    The reference lens shows for every method that has an entry in the cross-reference database or a Chain of Command wrapper; it can read 0 references when the method is only overridden or wrapped. The other counts show only when they are above zero. A method that nothing references, overrides or wraps shows no lens.

    Example: in the code view of SalesFormLetter, the run method shows 49 references | 2 Chain of Command | 2 overrides | 1 handler. Clicking 2 Chain of Command peeks the two wrappers. In your own extension class, the method run shows wraps SalesFormLetter.run.

    The lenses refresh when you save a code view, when you change a code intelligence setting and when the extension index finishes building.

    Options and settings¶

    Setting Default Effect
    xpp.codeIntelligence.codeLens true Show the code lens
    xpp.codeIntelligence.eventHandlerIndex true Count form and data event handlers too
    xpp.build.crossReference true Keep the reference counts of your code current when you build

    You can also switch the code lens in Configure Code Intelligence… (see Code Intelligence Settings).

    How it works¶

    1. codeLenses in src/codeIntel/providers.ts sends one code_lens request for the open element to the code intelligence server process.
    2. CodeLens in server/Ported/Tools/CodeIntel.cs answers with:
    3. one SQL query over the cross-reference database that counts, for every method path under the element (/Classes/SalesFormLetter/Methods/%), the references of kinds MethodCall, TestCall and TestHelperCall, and the MethodOverride references;
    4. the number of subclasses (kind ClassExtended);
    5. from the extension index: the Chain of Command classes of the element, its handlers, and per method the wrappers and handlers;
    6. for a class that is itself an extension or handler class: what it extends, what each method wraps and what each handler handles.
    7. The extension finds each method's signature line with methodSpans from src/xppSource.ts and places the lenses there.
    8. Clicking a count runs the internal command xpp.codeIntel.peek, which asks for the references or for the implementations of that kind and shows them in a peek window. wraps and handler lenses run xpp.codeIntel.goto.

    The server waits up to 15 seconds for the extension index; if it is not ready the counts from the database still show and the "building" lens is added.

    Limitations¶

    • No lenses in nested method documents (data source, field and control methods).
    • Reference counts are as of the last build with cross references.
    • Only calls (method calls, test calls and test helper calls) are counted as references; the References view (Find All References) shows every kind.
    • The lens counts Chain of Command classes of the element itself; those on its data sources or controls appear in Show Extensions and Handlers….

    Troubleshooting¶

    Symptom Cause Fix
    No lenses at all xpp.codeIntelligence.codeLens or editor.codeLens is off, or the document is a nested method Turn the settings on; open the element's code view
    No reference lenses, but the extension lenses show The cross-reference database is not usable See Find All References
    extension index building… stays The index is still building or failed Look at the status on the Code Intelligence node in the Dynamics 365 view; run Rebuild Extension Index
    A count is lower than expected Your latest code is not built with cross references Build the project

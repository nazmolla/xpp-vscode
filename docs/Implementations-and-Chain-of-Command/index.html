    Implementations and Chain of Command¶

    Go to Implementations (Ctrl+F12) answers "what else runs when this runs?". On a method it lists the Chain of Command wrappers, the pre/post and delegate event handlers and the overrides in subclasses. On an element it lists the Chain of Command classes, the event handlers, the subclasses and the metadata extensions (table, form, enum, EDT extensions...). Show Extensions and Handlers… shows the same for any element in a grouped picker. Visual Studio has no single command for this; you would combine Find References, the extension list in Application Explorer and the event handler search.

    When to use it¶

    • Before you change or wrap a standard method, see who already wraps or handles it (Microsoft's own extensions and yours, and ISV code installed with the metadata).
    • Find out why a standard method behaves differently than its code suggests: a Chain of Command class or an event handler adds code around it.
    • Find every subclass that overrides a method.
    • List every extension of a table or form, including metadata extensions that have no code.
    • From a Chain of Command class or handler class, jump back to what it extends (see Code Lens).

    Before you start¶

    • Cross-reference database with the standard application (restored by Connect to Environment). Overrides, subclasses, metadata extensions and the standard Chain of Command classes and handlers come from it.
    • Your own code is read from disk, so Chain of Command classes and handlers you wrote since the last build count.
    • The extension index (below) builds in the background the first time an X++ document opens. Until it is ready you see "Extension index still building; Chain of Command and handlers may be missing" in the status bar.
    • The setting xpp.codeIntelligence.navigation must be on (the default) for Go to Implementations.

    How to use it¶

    Go to Implementations in code¶

    1. In a code view, put the cursor on:
    2. a method name (in its signature or in a call such as salesFormLetter.run()), for the method's implementations;
    3. the element name on the declaration line, for the element's implementations;
    4. anywhere inside a method of the current element, for that method.
    5. Press Ctrl+F12, or right-click and choose Go to Implementations or Peek > Peek Implementations.
    6. One result opens directly; several open in a peek list. Each entry opens the code at the class or the method.

    What you get:

    Cursor on Results
    A method, e.g. SalesFormLetter.run Chain of Command methods that wrap it (next run()), Event handler methods ([PreHandlerFor], [PostHandlerFor], delegate subscribers, and form/data event handlers on that method), Override methods in subclasses
    An element, e.g. SalesFormLetter or CustTable Chain of Command class ([ExtensionOf(...)] of the element, its data sources or its controls), Event handler methods on the element's events, Subclass (classes that extend it), Metadata extension (CustTable.ContosoExtensions)

    Metadata extensions have no code, so the editor can't show them. When some results are left out for that reason you see "N more without code (metadata extensions); see Show Extensions and Handlers" in the status bar.

    Show Extensions and Handlers…¶

    1. Run Show Extensions and Handlers…:
    2. from the context menu of an element with code or an extensible element in the Application Explorer or the project view;
    3. from the Element Designer context menu;
    4. from the Code Intelligence node in the Dynamics 365 view;
    5. from the command palette (F&O Studio: Show Extensions and Handlers…). It uses the element of the active code view; without one it asks "Show extensions of" (for example SalesTable, SalesFormLetter, CustTable).
    6. A picker titled "N extension(s) of X" opens. Results are grouped under separators in this order: Chain of Command class, Event handler, Metadata extension, Subclass. Each row shows the name, a detail such as "extends SalesFormLetter" or "Post handler of SalesFormLetter.run", and the element type.
    7. Pick a row. Classes and methods open in the code view; metadata extensions open in the designer.

    When nothing extends the element you see "Nothing extends X."

    Event handlers of a designer node¶

    In the Element Designer, the Events node of a table, a form data source, a data source field or a form control lists the handlers of those events from the same index. See Event Handlers.

    Rebuild Extension Index¶

    The index is cached and refreshed on its own. Run Rebuild Extension Index (command palette, or the Code Intelligence node in the Dynamics 365 view) when:

    • you restored a new cross-reference database, or built many packages;
    • results look out of date.

    The node shows the index status: reading cross references, reading your models, scanning form/data event handlers, then ready (N extension classes, N wrapped methods, N handlers) or failed: <reason>. While it builds, the Code Intelligence node says "indexing…".

    Rebuilding also reloads the obsolete API list.

    Writing Chain of Command¶

    F&O Studio gives you several ways to start a wrapper:

    • Create Code Extension on an element creates the [ExtensionOf] class (Create Code Extension).
    • The quick fix create a Chain of Command wrapper writes the wrapper method (Quick Fixes).
    • The snippets coc, coctable, cocform, cocformds, cocmethod and cocmethodret (Snippets).

    Completion after . on a type lists the methods its Chain of Command classes add, marked "(extension)" (Completion and Signature Help).

    Options and settings¶

    Setting Default Effect
    xpp.codeIntelligence.navigation true Go to Implementations, call hierarchy and type hierarchy
    xpp.codeIntelligence.eventHandlerIndex true Include [FormControlEventHandler], [DataEventHandler] and similar handlers. The first scan of all packages takes about a minute; it is cached afterwards
    xpp.codeIntelligence.codeLens true Counts of Chain of Command, handlers and overrides above methods (Code Lens)

    How it works¶

    The extension index¶

    ExtensionIndex in server/Ported/Tools/ExtensionIndex.cs knows who extends what, in both directions, and keeps it in memory. It merges three sources:

    1. Cross-reference database (set-based queries over the whole application, about 6 seconds). An [ExtensionOf] attribute row (reference kind Attribute to /Classes/ExtensionOf) and the type reference on the same line give the extended element: a class, table, form, form data source or control, data entity, view or map. A wrapper is a method of the extension class that calls the method of the same name (its next call). Pre/post handlers and delegate subscribers come from their attribute row and the method reference on the same line. The result is cached on disk in %LOCALAPPDATA%\XppVsCode\cache\extensions-<database>.json and reused until the database changes.
    2. Your own models, read from the class files on disk on each refresh (at most every 20 seconds), so extensions written since the last build count.
    3. Form and data event handlers ([FormControlEventHandler], [DataEventHandler], [FormEventHandler], [FormDataSourceEventHandler]...). The cross-reference database doesn't record them, so the reference packages are scanned once (about a minute) and cached in %LOCALAPPDATA%\XppVsCode\cache\event-handlers-<hash>.json. This part only runs when xpp.codeIntelligence.eventHandlerIndex is on.

    The requests¶

    Code intelligence runs in a second F&O Studio server process, separate from the one the designers use. The extension (src/codeIntel/providers.ts) sends xpp/lang requests; CodeIntel in server/Ported/Tools/CodeIntel.cs answers them:

    • implementations waits up to 15 seconds for the index, then adds from the index the Chain of Command classes or wrappers and the handlers, and from the cross-reference database the subclasses (kind ClassExtended, at most 500), the overrides (kind MethodOverride, at most 500) and the metadata extensions (paths such as TableExtension/CustTable.<suffix>, at most 50 per extension type);
    • status and refresh_index start or force the index build; the extension polls the status every 3 seconds until it is ready;
    • event_handlers answers the designer's Events node.

    Each result is an element path such as /Classes/SalesFormLetter_Extension/Methods/run. The extension turns it into a code view location (xpp:/AxClass/...), or opens the designer when the element has no code.

    Limitations¶

    • Standard Chain of Command classes and handlers are only as current as the cross-reference database.
    • Classes of your models are found from source; other custom packages (for example ISV packages) are found only when they are in the cross-reference database.
    • Form and data event handlers are missing while xpp.codeIntelligence.eventHandlerIndex is off.
    • Go to Implementations doesn't show metadata extensions in the editor; use Show Extensions and Handlers….
    • Up to 500 subclasses or overrides are listed.

    Troubleshooting¶

    Symptom Cause Fix
    Status bar: "Extension index still building; Chain of Command and handlers may be missing" The index is not ready after 15 s Wait for ready on the Code Intelligence node, then try again
    Index status failed: cross-reference database unavailable: ... The cross-reference database can't be used See Find All References troubleshooting
    A form control handler is missing eventHandlerIndex is off, or the scan is still running Turn it on in Configure Code Intelligence… and wait for ready
    A new standard extension is missing after an update The cache is from the old database Run Rebuild Extension Index
    Ctrl+F12 does nothing xpp.codeIntelligence.navigation is off Turn it on
    "No class, table, form or other element named X." The name typed in Show Extensions doesn't exist Check the name

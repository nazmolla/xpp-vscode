    Agent Tools: Analysis¶

    These agent tools answer questions about existing code and metadata: who uses an element, which standard code to follow, where a message comes from, what a role costs in licenses, where code is slow, what a trace shows, what an upgrade breaks, and what Microsoft's documentation says. They don't change anything. For the overview and the guarantees, see MCP-Agent-Tools.

    Most of them have a command in F&O Studio that shows the same analysis in VS Code; the "UI equivalent" line of each section links to it.

    When the agent uses them¶

    Question Tool
    Who calls this method, uses this table, extends this class? xpp_find_references
    How does standard code do this? Which class should I copy or extend? xpp_find_examples, xpp_search_code
    Where does this error message come from? xpp_find_message_source
    Which license does this role need? Who can open this form? Which roles should get my new duty? Are there security gaps or SoD conflicts? xpp_analyze_security
    Is this code slow? Is this data entity ready for OData and data management? xpp_analyze_performance
    What happened in this trace? xpp_analyze_trace
    What breaks when we take the next version? xpp_find_deprecations
    How does this X++ feature or API work? xpp_search_docs, xpp_get_guide

    Before you start¶

    • An active D365FO configuration with its packages on disk.
    • The cross-reference database of the configuration (named in the configuration, usually on (LocalDB)\MSSQLLocalDB) for xpp_find_references, the usages in xpp_find_message_source, xpp_find_examples and the obsolete-API part of xpp_find_deprecations. Your own code is in it after a build with cross-references (xpp.build.crossReference, default true).
    • Internet access to learn.microsoft.com for xpp_search_docs.
    • A .etl file and the trace event manifests for xpp_analyze_trace.

    xpp_find_references¶

    Where-used: every element and member that uses or references an element, or one method or field of it. It queries the cross-reference database (indexed, milliseconds). If the database is missing or incomplete, the result says exactly why; agents are told to report that and never fall back to searching XML files.

    Parameter Type Meaning
    objectType (required) string Type of the target: AxClass, AxTable, AxForm, AxEnum, AxEdt, AxView, AxQuery, AxDataEntityView, AxMap, AxMenuItemDisplay, AxMenuItemAction, AxMenuItemOutput, AxTableExtension, AxEnumExtension, AxReport, AxSecurityRole, AxSecurityPrivilege, AxSecurityDuty
    objectName (required) string Exact name of the target
    memberName string A method or field of the target: only who uses that member
    referenceKind string Any (default), MethodCall, TypeReference, InterfaceImplementation, ClassExtended, TestCall, Property, Attribute, TestHelperCall, Tag, MethodOverride
    maxResults integer Default 25, max 100
    includeCode boolean Also show the code line of each reference (max 25 references) 
    { "objectType": "AxClass", "objectName": "SalesFormLetter", "memberName": "construct", "includeCode": true }

    A typical use: the API you need is internal or private. The agent finds the public entry points (controllers, services, forms) that call it, and calls or wraps those instead.

    UI equivalent: Find-All-References.

    xpp_find_examples¶

    Finds standard (Microsoft) implementations to learn from, reuse or copy. Give a task in words, an element to resemble, or both. Output: ranked examples with the reason; small, focused examples come first for framework patterns.

    Parameter Type Meaning
    query string The task in words, for example "batch job with a data contract", "number sequence for a new table", "custom lookup", "business event", "report data provider", "service operation", "workflow", "form with the SimpleList pattern"
    objectType string With objectName: find elements similar to this one (AxClass, AxTable, AxForm...)
    objectName string The element to resemble
    maxResults integer Default 15, max 50 
    { "query": "batch job with a data contract" }

    { "objectType": "AxClass", "objectName": "SalesFormLetter", "maxResults": 10 }

    Similar elements are those that share the most distinctive references with the given one (base class, interfaces, attributes, called APIs, tables; rare targets count most). A task in words maps to the framework classes such implementations extend, call or carry as attributes. Your own models are left out of the examples.

    UI equivalent: Find-Similar-Implementations.

    xpp_search_code¶

    Searches the X++ source of every package, standard and custom: method code and declarations of classes, tables, forms, views, data entities, queries and maps. Literal text by default, case-insensitive; regex=true for a .NET regular expression. Output: element, method, line and the matching line.

    Parameter Type Meaning
    pattern (required) string Text or regex, at least 3 characters, for example NumberSeq::newGetNum(
    regex boolean Treat pattern as a .NET regular expression
    caseSensitive boolean Case-sensitive match
    objectTypes string[] Limit to these types, for example ["AxClass"]. Default: all code types
    model string One model or package (a package such as ApplicationSuite covers all its models)
    maxResults integer Default 50, max 200 
    { "pattern": "SysOperationServiceController", "objectTypes": ["AxClass"], "maxResults": 20 }

    The files are scanned in parallel from the metadata folders. Until they are in the operating system's file cache, a search over everything reads them from disk (30 to 60 seconds); limiting to AxClass or one model is much faster.

    UI equivalent: Search-Code.

    xpp_find_message_source¶

    Finds the X++ code that raises a message. Paste the message as the user saw it, values included. It is matched against every label text (placeholders %1..%9 match any value), and the label's usages come from the cross-reference database with the code line: raising code first, tests last. Messages written as literal strings are found by a code search.

    For the platform's "Field '%1' must be filled in." it first lists the table fields with that label whose Mandatory property is Yes (on the table or a table extension), and separates code that raises it for one of those fields from code that reuses the text for other fields.

    Parameter Type Meaning
    message (required) string The message text as shown, for example "Customer 1001 is on hold. Cannot post the order."
    language string Language of the message. Default en-US
    maxLabels integer Labels to report. Default 5
    maxResults integer Usages per label. Default 15 
    { "message": "Field 'Customer group' must be filled in." }

    UI equivalent: Find-Message-Source. Scenario: Scenario-From-Error-Message-to-Fix.

    xpp_analyze_security¶

    Security and license analysis of the metadata of all packages. No environment is needed. One tool, six operations chosen with op.

    Parameter Type Used by Meaning
    op (required) string all license, access, placement, gaps, sod or report
    objectType string license, access license: AxSecurityRole, AxSecurityDuty or AxSecurityPrivilege. access: AxMenuItemDisplay, AxMenuItemOutput, AxMenuItemAction, AxForm, AxTable or AxDataEntityView
    objectName string license, access The element
    duty string placement Your new duty
    objects string[] placement Standard elements of the same job as Type:Name, for example ["AxForm:CustTable", "AxMenuItemDisplay:SalesTableListPage"]
    role string sod, placement sod: one role (default: the roles of your models and the roles they extend). placement: the requirement's role wording, for example "Accounts receivable clerk"
    models string[] gaps Models to check (default: your custom models)
    rulesJson string sod Optional rules: [{"Name":...,"First":duty,"Second":duty,"Severity":"High","Reason":...}]
    roles string[] report Roles to report
    model string report All roles of this model and the roles it extends
    format string report markdown or csv

    What each operation returns:

    op Result
    license The user license the object needs (Team Members, Activity, Operations), the menu items and grants that drive it, and which grants Read would lower
    access Who reaches a menu item, form, table or data entity: privileges, duties and roles with their grants
    placement Standard roles to give a new duty, ranked by whether they already reach the same standard objects (the forms the duty's menu items open, plus objects) and by label similarity to the role wording
    gaps Menu items no privilege grants, privileges in no duty, duties in no role, over-granting, missing objects, data entities without permissions
    sod Segregation-of-duties conflicts in your roles (or one role) against standard rules or rulesJson
    report A Markdown or CSV security report for roles or a model, for sign-off 
    { "op": "license", "objectType": "AxSecurityRole", "objectName": "TradeSalesClerk" }

    { "op": "access", "objectType": "AxMenuItemDisplay", "objectName": "CustGroup" }

    { "op": "sod", "role": "TradeSalesClerk" }

    UI equivalents: Analyze-License, Who-Can-Access, Find-Security-Gaps, Segregation-of-Duties, Security-Report, Security-View.

    xpp_analyze_performance¶

    Static performance review of the X++ methods of a class, table, form or data entity. No environment is needed. Each finding gives the method, line, why it is slow and the fix. Findings are heuristics: the agent should confirm before changing code.

    What it checks:

    • Queries and row-by-row insert, update or delete inside loops.
    • select firstonly inside while select (use a join or exists join).
    • while select of every field.
    • select forupdate without a write.
    • Unbalanced ttsbegin/ttscommit.
    • crossCompany queries.
    • insert_recordset, update_recordset and delete_from that quietly run row by row because the table overrides insert, update or delete, has delete actions or is date-effective.
    • Forms: display methods in grids without cacheAddMethod; data sources that fetch every field but show a few in a grid (OnlyFetchActive); data sources shown in a parent's grid with link type Delayed or Active instead of a join.
    • Data entities: readiness for OData and data management (public entity and collection names, an entity key, staging table fields missing for entity fields, mandatory fields of the root table that are not mapped) and set-based processing over views, entities or temporary tables.

    Database log and alerts, which also force row-by-row operations, are environment setup and are not checked.

    Parameter Type Meaning
    objectType (required) string AxClass, AxTable, AxForm or AxDataEntityView
    objectName (required) string The element 
    { "objectType": "AxClass", "objectName": "CustCollectionLetterCreate" }

    Output: <name>: N performance finding(s) in M method(s). then up to 100 lines - [severity] rule in method line N: message Fix: fix.

    UI equivalent: Analyze-Performance; rules: Performance-Rules-Reference.

    xpp_analyze_trace¶

    Analyzes a trace (.etl) taken in the web client (Settings > Trace) or with the trace tools, with F&O Studio's own trace parser. A trace covers every AOS and session that ran while it was recorded: other users, dual-write and OData integrations, batch.

    The report lists:

    • the AOS instances and the sessions with their user, UTC time range and errors;
    • errors and exceptions with the full X++ call stack (calls to Global::error, checkFailed, warning, and frames unwound by an exception with the method that caught it);
    • platform messages;
    • the slowest requests with their hot call path;
    • methods by exclusive time; SQL by total time; pauses.

    To look at one scenario, the agent calls it again with filters taken from the session list, then reads the methods it names.

    Parameter Type Meaning
    path (required) string Full path of the .etl file
    minRequestMs number Ignore requests shorter than this when nothing is filtered. Default 50
    aos string Only this AOS (machine name or part of it)
    session string Only this X++ session ID
    user string Only sessions of this user (user ID or GUID, or part of it)
    method string Only requests whose call tree has a method containing this text; shows the path to it
    from string Requests running at or after this time: UTC time (20:05:50), UTC date and time, or seconds from the start of the trace
    to string Requests that started at or before this time (same formats)
    manifestFolder string Folder with DynamicsAXXppExecutionTraces.man, only when the tool reports none were found 
    { "path": "C:\\Traces\\SalesOrderPosting.etl", "method": "SalesFormLetter", "from": "20:05:50", "to": "20:06:30" }

    The manifests are found in PackagesLocalDirectory\bin\Monitoring, AosService\WebRoot\Monitoring or the registered trace providers' folder. The tool runs in parallel with other calls and never uses the metadata lock.

    UI equivalent: Analyze-Trace. Scenario: Scenario-Performance-Tuning-a-Slow-Process.

    xpp_find_deprecations¶

    Upgrade readiness of one model, in three or four parts:

    1. Every place its code uses a class, table or method marked [SysObsolete], with the attribute's message (often the replacement) and whether it is marked as an error (it will stop compiling). Read from the cross-reference database.
    2. Extension compatibility against the installed application: Chain of Command wrappers whose target method is gone, changed its signature (static, return type, parameters) or is no longer wrappable (private, final, Wrappable(false)/Hookable(false), internal); event handlers whose class, method, delegate or table is gone; table, form and enum extensions whose base element, fields, field groups or controls are gone.
    3. Collisions with other models: your extensions compared with the other installed models' extensions of the same elements.
    4. With previousPackagesFolder: wrapped standard methods whose code changed since the earlier version (number of changed lines, no code), so behaviour around next may differ.
    Parameter Type Meaning
    modelName (required) string The model to check (its package's code is read)
    previousPackagesFolder string PackagesLocalDirectory of the earlier application version (under %LOCALAPPDATA%\Microsoft\Dynamics365\<version>) 
    { "modelName": "ContosoExtensions", "previousPackagesFolder": "%LOCALAPPDATA%\\Microsoft\\Dynamics365\\<previous version>\\PackagesLocalDirectory" }

    Run it after installing a new version (or on the version you upgrade to) and before building. Environment variables in previousPackagesFolder are expanded.

    UI equivalents: Upgrade-Readiness, Standard-Code-Drift. Scenario: Scenario-Upgrade-to-a-New-Version.

    xpp_search_docs¶

    Searches Microsoft Learn for D365FO, X++, extensibility and technical references, or fetches one Learn page. Output: Source: <url>, other matches the agent can pass as url, and the page text.

    Parameter Type Meaning
    query (required) string What to search for
    url string A Microsoft Learn URL to fetch instead
    maxLength integer Maximum characters returned. Default 12000 (accepted range 1000 to 50000) 
    { "query": "Chain of Command wrapping rules" }

    How it searches: Microsoft Learn's public MCP endpoint (https://learn.microsoft.com/api/mcp, microsoft_docs_search) first, then Learn's keyword search API. Questions about code get developer pages (/dev-itpro/) first. Only learn.microsoft.com and docs.microsoft.com URLs are fetched; AX 2012 pages are refused with the advice to read the D365FO element with xpp_read_object.

    xpp_get_guide¶

    Returns the full F&O Studio development guide by topic. The instructions the agent always has are its summary; the guide adds rules with examples and code templates. Without topic it lists the topics.

    Parameter Type Meaning
    topic string Words of a topic title, for example ssrs, chain of command, event handlers, display methods, language reference 
    { "topic": "acceptance test library" }

    Topics include: the tool-first directive, query size limits, what to do when the API you need is internal or not extensible, JSON only, environment, workflow, critical rules, models and packages, ownership, the five extensibility mechanisms, the X++ language reference, object types and properties, display and edit methods, the full decision tree, naming conventions, best practices, tests with the Acceptance Test Library (ATL), and SSRS report patterns. One topic is returned at a time, capped in size.

    How it works¶

    Tool Implementation
    xpp_find_references XRefQuery (XRefQuery.cs): SQL against the cross-reference database of the active configuration
    xpp_find_examples CodeExamples (CodeExamples.cs) over the cross-reference database
    xpp_search_code CodeSearch (CodeSearch.cs): parallel scan of the metadata files, parsing only files with a match
    xpp_find_message_source MessageTrace (MessageTrace.cs): label texts of all packages (built once per server), then label usages from the cross-reference database
    xpp_analyze_security SecurityAnalysis (SecurityAnalysis.cs)
    xpp_analyze_performance Bridge action analyze_performance (PerformanceAnalysisService)
    xpp_analyze_trace TraceService in server/Tracing, F&O Studio's own .etl parser
    xpp_find_deprecations DeprecationReport plus bridge actions extension_compatibility, extension_collisions and wrapper_drift
    xpp_search_docs DocSearchHandler (DocSearchHandler.cs)
    xpp_get_guide AgentGuide over the embedded XppCopilotGuide.txt

    All of these tools are registered as ParallelRead: they run in parallel with other calls. Those that need the metadata API still wait for its lock.

    Limitations¶

    • Where-used, examples, message usages and obsolete-API usages depend on the cross-reference database. Your own code is only in it after a build with cross-references; a deleted element's own entries are removed by F&O Studio.
    • Performance findings are static heuristics, not measurements. Use traces for measurements.
    • Security analysis works on metadata, not on the user-role assignments of an environment.
    • xpp_search_docs needs internet access to Microsoft Learn.

    Troubleshooting¶

    Symptom Cause Fix
    xpp_find_references explains that the cross-reference database is missing or unusable No XRef database for the configuration, or LocalDB not running Restore it (Connect-to-Environment) or start LocalDB
    Your own code is missing from where-used The model was built without cross-references Build with xpp.build.crossReference on (Build-Project-and-Model)
    xpp_search_code takes close to a minute The files are not in the file cache yet Limit with objectTypes or model; later searches are faster
    xpp_analyze_trace reports no manifests found The event manifests are not in the usual folders Pass manifestFolder (or set xpp.trace.manifestFolder for the panel)
    Pass modelName. from xpp_find_deprecations modelName missing Pass the model
    Only Microsoft Learn URLs are allowed url is not on learn.microsoft.com Use query or a Learn URL

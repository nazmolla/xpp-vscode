    Settings reference¶

    This page lists every setting F&O Studio contributes, with its type, default value, allowed values, scope and the feature it affects. It also covers the two other places where you configure F&O Studio: the xpp debug configuration in .vscode/launch.json and the xpp task type in .vscode/tasks.json.

    Opening the settings¶

    • Run F&O Studio: Options… from the Command Palette, or click Options… at the bottom of the Dynamics 365 view. It opens the Settings editor filtered on F&O Studio (@ext:MNazmi.xpp-vscode).
    • Or open File > Preferences > Settings and search for xpp..
    • The code intelligence switches are also in the Dynamics 365 view under Code Intelligence > Configure Code Intelligence…. See Code-Intelligence-Settings.

    All settings are in the F&O Studio section and start with xpp..

    Scopes¶

    VS Code applies a setting at one of several levels. Four F&O Studio settings declare a scope:

    Scope Meaning in VS Code Settings
    machine Only in the user settings of this machine; a workspace cannot set it xpp.build.msbuildPath, xpp.pacPath, xpp.debuggerProxyPath, xpp.trace.manifestFolder
    window User or workspace settings xpp.project
    (not declared) VS Code's default: user, workspace or workspace folder settings all other settings

    xpp.project is special: F&O Studio writes it into a project's own workspace, and a value in your user settings is not used.

    The sections below describe each setting.

    Project and environment¶

    xpp.project¶

    • Type: string. Default: empty. Scope: window.
    • The D365FO project (.rnrproj) of this workspace. Open D365FO Project… sets it in the project's own workspace. A value in the user settings is not used.
    • You normally never edit it by hand: open projects with Open D365FO Project….
    • Affects: D365FO-Projects, the project status bar item (Status-Bar), and the project the agent tools work on (MCP-Agent-Tools).

    xpp.environmentUrl¶

    • Type: string. Default: empty.
    • The Dataverse URL of your default unified developer environment, for example https://yourorg.crm.dynamics.com.
    • Select Environment… chooses another environment per workspace, so two VS Code windows can work with two environments.
    • Affects: Select-Environment, Connect-to-Environment.

    xpp.auth.clientId¶

    • Type: string. Default: empty.
    • An optional Microsoft Entra application (client) ID to sign in with, for tenants that do not allow VS Code's default sign-in for Dataverse. When set, F&O Studio asks VS Code's Microsoft account provider for a token with that client ID.
    • Affects: every Dataverse call (connect, deploy, sync, tests, database credentials, debugger). See Sign-In-and-Authentication.

    xpp.financeAndOperationsUrl¶

    • Type: string. Default: empty.
    • The web client URL, for example https://yourenv.operations.dynamics.com. Open in Browser and Open Table Browser use it when the selected environment's configuration has none.
    • Affects: Copy-Name-and-Open-in-Browser.

    Build¶

    xpp.build.crossReference¶

    • Type: boolean. Default: true.
    • Updates the cross-reference database while building, so where-used (Find References, rename, references diagrams) includes your own code.
    • Affects: Build-Project-and-Model, Find-All-References.

    xpp.build.runAppCheckerRules¶

    • Type: boolean. Default: false.
    • Runs the AppChecker rules during the build.
    • Affects: Build-Project-and-Model, Best-Practice-Checks.

    xpp.build.saveBeforeBuild¶

    • Type: boolean. Default: true.
    • Saves unsaved X++ code views before a build, so the compiler sees your latest changes. When it is off, unsaved code views are compiled from the metadata on disk, without your unsaved edits.
    • Affects: Build-Project-and-Model.

    xpp.build.restartLocalAos¶

    • Type: boolean. Default: true.
    • Cloud-hosted and VHD environments only: after a successful build, restarts the AOS hosts that are running (IIS Express or the AOS application pool in IIS, and the batch service) so they load the new build, as Visual Studio does. Batch tasks that were running are cut off.
    • Not used on unified developer environments.
    • Affects: Cloud-Hosted-and-VHD-Environments, Debugging-on-Cloud-Hosted.

    xpp.build.msbuildPath¶

    • Type: string. Default: empty. Scope: machine.
    • The MSBuild.exe used to build the C# projects and assemblies your X++ project references. They are copied into the package before X++ is compiled and deployed, as Visual Studio does.
    • Empty: Visual Studio's or the Build Tools' MSBuild, else the .NET SDK's (dotnet msbuild).
    • If the path you set does not exist, the build stops with "MSBuild not found at ... (setting xpp.build.msbuildPath)."
    • Affects: Solution-View-and-CSharp-References, Build-Project-and-Model, Deploy-to-Environment.

    Tools¶

    xpp.pacPath¶

    • Type: string. Default: empty (uses pac on the PATH). Scope: machine.
    • Path to the Power Platform CLI. Only the (pac) commands use it: Sign In to Environment (pac) and Initialize Deployment Solution (pac). Deploy and database sync do not need pac.
    • Affects: Power-Platform-CLI.

    xpp.debuggerProxyPath¶

    • Type: string. Default: empty. Scope: machine.
    • Path to Microsoft.Dynamics.AX.DebuggerProxy.exe. Empty: the FinOps tools that Connect to Environment… installed.
    • If the proxy is not found, debugging stops with "Microsoft.Dynamics.AX.DebuggerProxy.exe was not found. Run F&O Studio: Connect to Environment, or set xpp.debuggerProxyPath."
    • Affects: Debugger, Debugging-Standard-Code.

    xpp.trace.manifestFolder¶

    • Type: string. Default: empty. Scope: machine.
    • Folder with the Dynamics 365 trace event manifests (DynamicsAXXppExecutionTraces.man) for Analyze Trace….
    • Empty: F&O Studio looks in PackagesLocalDirectory\bin\Monitoring, AosService\WebRoot\Monitoring or the registered trace providers' folder.
    • Affects: Analyze-Trace.

    Code intelligence¶

    Each of these switches one code intelligence feature on or off. All of them are also in the Dynamics 365 view under Code Intelligence > Configure Code Intelligence…, which shows which ones are on. See Code-Intelligence-Settings.

    Setting Default What it turns on Page
    xpp.codeIntelligence.outline true Outline and breadcrumbs: methods and members of the open object Outline-and-Workspace-Symbols
    xpp.codeIntelligence.navigation true Go to Implementations (overrides, Chain of Command, event handlers, subclasses), call hierarchy and type hierarchy Implementations-and-Chain-of-Command, Call-and-Type-Hierarchy
    xpp.codeIntelligence.workspaceSymbols true Go to Symbol in Workspace (Ctrl+T) over elements and methods of all models Outline-and-Workspace-Symbols
    xpp.codeIntelligence.completion true Completion after . and ::, label references in strings, keywords; signature help Completion-and-Signature-Help
    xpp.codeIntelligence.hover true Hover details: label texts, EDT and enum details, method signatures Hover
    xpp.codeIntelligence.codeLens true Code lens: reference, override, Chain of Command and handler counts; what a CoC or handler method wraps Code-Lens
    xpp.codeIntelligence.syntaxCheck true Live syntax check with the X++ compiler's parser Syntax-Check-and-Obsolete-Warnings
    xpp.codeIntelligence.obsoleteWarnings true Calls to methods and uses of classes and tables marked [SysObsolete] are reported in Problems (as errors when the attribute says so) Syntax-Check-and-Obsolete-Warnings
    xpp.codeIntelligence.formatting true Format Document / Format Selection with a 4-space Allman layout Formatting-and-Folding
    xpp.codeIntelligence.eventHandlerIndex true Includes form and data event handlers ([FormControlEventHandler], [DataEventHandler], ...), which the cross-reference database does not record. The first scan takes about a minute and is cached Event-Handlers
    xpp.codeIntelligence.semanticHighlighting false Semantic highlighting: colours classes, tables, enums, EDTs, methods and fields. Looks up every identifier of the open document (slow) Code-Intelligence-Settings
    xpp.codeIntelligence.diagnosticsOnSave false Builds the project with the X++ compiler after you save code, so semantic errors reach Problems (about 10 s per save) Compiler-Diagnostics

    The last two are off by default because they are slow. eventHandlerIndex is on by default but is slow the first time.

    Entity relationship diagram¶

    These are the defaults the ERD starts with; you can change all three in the diagram itself.

    Setting Type Default Values
    xpp.erd.depth integer 1 1 to 5: levels of related tables the diagram follows from the table it starts from
    xpp.erd.direction string "outgoing" outgoing: tables the table refers to (its relations); incoming: tables that refer to the table (their relations to it); both
    xpp.erd.fields string "keys" keys: primary key and the fields of the drawn relations; all: all fields

    Affects: Entity-Relationship-Diagram.

    Review, source control and security¶

    xpp.git.baseBranch¶

    • Type: string. Default: empty.
    • The branch your work is compared with, for example main. Show Changed Elements, Review My Changes and the change marks in the project view include what the current branch changed since it left this branch.
    • Empty: only uncommitted changes.
    • Affects: Review-My-Changes, Show-Changed-Elements, Git-Changes-in-the-Project-View.

    xpp.security.sodRulesFile¶

    • Type: string. Default: empty (built-in rules).
    • A JSON file with segregation of duties rules. Each rule has Name, First, Second, Severity and Reason; First and Second are duty names.
    • Edit Segregation of Duties Rules creates the file from the built-in rules.
    • A relative path is resolved under the first workspace folder.
    • If the file is missing, the check fails with "The segregation of duties rules file ... was not found. Fix xpp.security.sodRulesFile or clear it to use the built-in rules."
    • Affects: Segregation-of-Duties.

    Example rule file:

    [
  {
    "Name": "Vendor master vs vendor payments",
    "First": "VendVendorMasterMaintain",
    "Second": "PaymVendorPaymentsMaintain",
    "Severity": "High",
    "Reason": "Create or change a vendor (bank account) and pay it."
  }
]

    This is one of the built-in rules. Run Edit Segregation of Duties Rules to get the full built-in list as a starting point.

    xpp.usageStatistics¶

    • Type: boolean. Default: false.
    • Counts which F&O Studio commands you run, on this machine only. Nothing is sent anywhere. Show Usage Statistics lists the counts.
    • Affects: Usage-Statistics, Report-a-Problem.

    Example settings.json¶

    {
  "xpp.environmentUrl": "https://yourorg.crm.dynamics.com",
  "xpp.git.baseBranch": "main",
  "xpp.build.saveBeforeBuild": true,
  "xpp.codeIntelligence.semanticHighlighting": false,
  "xpp.erd.depth": 2,
  "xpp.erd.direction": "both"
}

    Debug configuration (launch.json)¶

    The debugger works without a configuration: Launch Debugger starts it. To change it, add a configuration of type xpp to .vscode/launch.json (Run and Debug > create a launch.json file > X++). The only request type is attach.

    Attribute Type Default Description
    processName string "AXHost.exe" Process to attach to. On cloud-hosted and VHD environments, for example Batch.exe to debug the batch server; without it the debugger attaches to the AOS of the runtime host type set in Visual Studio's Dynamics 365 options (IIS or IIS Express)
    justMyCode boolean true Step only through code that has symbols loaded. Turning it off makes every exception the environment throws go through the debugger, which can make the environment stop responding
    additionalModules array [] More modules whose symbols load, added to your packages and the module of each standard element with a breakpoint. Wildcards allowed. Each extra module makes loading slower
    symbolOptions object none Replaces F&O Studio's symbol options entirely (vsdbg symbolOptions). Use additionalModules to add modules instead
    logging object none vsdbg logging options, for example { "exceptions": false } to stop printing exceptions in the Debug Console
    sourceFileMap object none Extra source path mappings 
    {
  "type": "xpp",
  "request": "attach",
  "name": "Attach to Dynamics 365",
  "justMyCode": true,
  "additionalModules": ["Dynamics.AX.ApplicationSuite.Forms.*.netmodule"],
  "logging": { "exceptions": false }
}

    See Debugger-Options for details.

    Task definition (tasks.json)¶

    F&O Studio contributes the task type xpp. action is required.

    Property Type Values Description
    action string buildProject, buildModel, deploy, syncDatabase buildProject reports the problems of the project's elements; buildModel those of the whole model; deploy deploys the package of the active project's model, as built on this machine, to the unified environment; syncDatabase synchronizes the database (through Dataverse on a unified environment, SyncEngine on cloud-hosted and VHD)
    model string model name Model to build. Defaults to the active project's model
    dbSync string None, Module, Full For deploy: the database sync after the deploy (Module synchronizes the deployed package). Default None
    mode string Full, Module For syncDatabase on a unified environment. Default Full
    modules string comma-separated For syncDatabase with mode Module. Defaults to the active project's model 
    {
  "version": "2.0.0",
  "tasks": [
    { "label": "Build project", "type": "xpp", "action": "buildProject", "group": "build" },
    { "label": "Deploy with module sync", "type": "xpp", "action": "deploy", "dbSync": "Module" }
  ]
}

    See Build-Tasks.

    Settings that are not settings¶

    Some choices are stored by F&O Studio itself, not in settings.json:

    • The environment selected with Select Environment… is remembered per workspace.
    • Temporary database credentials are kept in VS Code's secret storage until they expire. Forget Database Credentials removes them. See Database-Access.
    • Team rules for Copilot live in .xpp/agent-rules.md in your repository. See Team-Rules.
    • The active D365FO configuration (metadata folders, cross-reference database) comes from the registry and the XPPConfig JSON files that Visual Studio also uses. See Select-Environment and Visual-Studio-Side-by-Side.

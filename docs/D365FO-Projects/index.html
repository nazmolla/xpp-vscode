    D365FO Projects¶

    A D365FO project (.rnrproj) is the same project file Visual Studio uses: an MSBuild file that names one model and lists the elements you work on. F&O Studio opens, creates and edits these projects, shows them in the D365FO Project view (F&O Studio's Solution Explorer), and opens each project in its own VS Code workspace with the project folder and the model folder. Projects stay compatible with Visual Studio in both directions.

    When to use it¶

    • You work on a feature or fix: the project collects its elements, and Build Project compiles only those.
    • You want new elements (New Element, wizards, extensions, Copilot) to land in a known model and be listed in one place.
    • You want the change marks of Git on your elements, and Review My Changes and Best Practice Checks scoped to your work.
    • You share work with Visual Studio users: they open the same .rnrproj.

    A project is optional. The Application Explorer, designers, code views and agent tools also work without one. Without a project, commands that create elements ask which of your models to use.

    Before you start¶

    • An environment with metadata on this machine (Connect to Environment).
    • A custom model for the project. Create one with Create Model… (Models and Model Dependencies) if you have none; Create D365FO Project… refuses to run without one.
    • For source control, put the project folder in your Git repository (see Source Control for X++).

    The project view¶

    The D365FO Project view is the second view of the F&O Studio side bar.

    Without a project it shows: No D365FO project open. Opening a project opens its workspace: the project folder and its model folder. The Application Explorer and agent tools also work without one. with links Open D365FO Project, Open Recent D365FO Project and Create D365FO Project.

    With a project it shows the solution, like Visual Studio's Solution Explorer:

    ContosoProject                     ContosoExtensions
  References
    ContosoLibrary                 C# project
  Classes                          3
    ContosoOrderStatusService
    CustTable_ContosoExtensions_Extension
    SalesFormLetter_ContosoExtensions_Extension
  Table Extensions                 1
    CustTable.ContosoExtensions
ContosoReports                     ContosoReporting · not open
ContosoLibrary                     C#
  Greeter.cs
    • The project node shows the project name and its model. It opens expanded.
    • References lists the C# projects and assemblies the X++ project references (Solution View and C# References).
    • Folders group the elements by the folder Visual Studio gives them (Classes, Tables, Table Extensions, Forms...). The number of elements is shown next to the folder.
    • Elements show their name and their type (Class, Table Extension...). A click opens them like in the Application Explorer.
    • Other X++ projects of the same solution appear as further project nodes, marked not open.
    • C# projects of the solution, or that the project references, appear with their files.
    • An empty project shows the hint No elements yet: New Element….

    The view's description shows the solution name, <solution> (solution), or, without a solution, <project> (<model>).

    Git change marks¶

    Elements of your models that differ from Git carry Git's letter and colour: M modified, A added, D deleted, R renamed. The tooltip says whether the change is uncommitted or only on the current branch. With xpp.git.baseBranch set (for example main), elements changed since the branch left that base are marked too. The marks refresh when you save and every 30 seconds. See Git Changes in the Project View.

    Title bar¶

    Button / menu Shown Command
    + With a project New Element… (New Element)
    Build With a project Build Project (Build Project and Model)
    Open element Always Open Element… (Open Element)
    Open project Without a project Open D365FO Project…
    Create project Without a project Create D365FO Project…
    Project submenu (... menu) With a project Open D365FO Project…, Open Recent D365FO Project…, Create D365FO Project…, Close D365FO Project, Add Reference…, New C# Project…
    Check submenu (... menu) With a project Run Best Practice Checks on Project, Review My Changes, Pre-Deploy Checklist, Run Tests (unified developer environments only)
    ... menu Always Build Model, Refresh Project

    Right-click actions¶

    On a folder of the open project: New Element… (also as an inline +). The element type of the folder is preselected, so + on Classes starts a new class.

    On an element, the same actions as in the Application Explorer (see Application Explorer), except Add to Project, plus:

    Action Details
    Locate in Application Explorer Selects the element in the Application Explorer, clearing a filter that hides it
    Exclude from Project Removes the element from the .rnrproj. The element stays in the model. Not offered on elements of the other X++ projects of the solution.

    Project items always count as elements of your own model, so Rename…, Delete and View History are available on them.

    On a project node: Add Reference… and New C# Project… on the open project; Open This Project on another X++ project of the solution. On References, Add Reference… and New C# Project…; on a reference, Remove Reference. On a C# project, Build C# Project and Open Project File. See Solution View and C# References.

    The view supports multi-select, and elements dragged from the Application Explorer are added to the project when dropped on it (Drag and Drop).

    How to use it¶

    Open a project¶

    1. Run Open D365FO Project… (project view, Dynamics 365 view > Model and project > Open Project…, Command Palette, or the Open or create a D365FO project walkthrough step).
    2. The picker titled Open D365FO project (.rnrproj) lists:
    3. projects you opened before (marked recently opened), newest first;
    4. .rnrproj files found in your source\repos folder (Visual Studio's default, up to four folders deep) and in the current workspace;
    5. Browse… to pick any .rnrproj.
    6. Pick a project. F&O Studio opens the project's workspace in the current window (the window reloads).

    Open Recent D365FO Project… shows only the recent list (up to 10 projects that still exist). If it is empty you get No recent D365FO projects. Open one with Open D365FO Project.

    The project workspace¶

    Opening a project opens a VS Code workspace file that F&O Studio writes for that project. It contains:

    Folder Name in the Explorer
    The folder of the .rnrproj (with the .slnx and your source control) <Project> (project)
    The model's metadata folder, <package>\<model> <Model> (model)
    Each C# project of the solution, or that the project references <Folder> (C#)

    and the setting xpp.project with the full path of the .rnrproj.

    • The workspace files live in F&O Studio's own storage (workspaces\<Project>-<hash>.code-workspace), so your repository stays clean.
    • Folders and settings you add to the workspace yourself are kept when F&O Studio rewrites it.
    • VS Code's File > Open Recent lists the workspaces too.
    • Each window has at most one project. Two windows can have two projects.

    Close D365FO Project closes the workspace; the window stays open without a project.

    Create a project¶

    1. Run Create D365FO Project….
    2. Create D365FO project (1/3): model — pick one of your custom models. The project's elements belong to it.
    3. (2/3): name — the default is <Model>Project. Letters, digits, _, . and -, starting with a letter.
    4. (3/3): parent folder — your source\repos folder (Visual Studio's repos folder) or Browse…. The project goes to <parent>\<name>.
    5. F&O Studio writes <name>.rnrproj and <name>.slnx, shows Created D365FO project for model . and opens the project's workspace.

    If the .rnrproj already exists, it stops with an error and leaves the file alone.

    Add and remove elements¶

    • New elements created by New Element, the wizards, Create Extension, Create Code Extension, Duplicate… and Copilot's tools are added to the open project automatically.
    • Existing elements of the project's model: Add to Project in the Application Explorer or Open Element, or drag them onto the project view.
    • Exclude from Project removes an element from the project only. Delete removes it from the model too.

    A project holds elements of its own model only. Adding an element of another model fails; extend it instead.

    Build and check¶

    • Build Project (Ctrl+Shift+B in an X++ code view or a .rnrproj editor) compiles the project's elements, after building the C# projects it references. See Build Project and Model.
    • The Check submenu runs Best Practice Checks, Review My Changes, the Pre-Deploy Checklist and Run Tests on the project.

    Projects selected by Copilot¶

    An agent can switch the project with the tool xpp_select_project. When it does, F&O Studio shows The agent selected project . with Open Project. The window only switches when you click it, because opening a project reloads the window and would interrupt the agent.

    The project file¶

    F&O Studio writes .rnrproj files the way Visual Studio saves them. A new project looks like this (shortened):

    <Project ToolsVersion="14.0" DefaultTargets="Build" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <PropertyGroup>
    <Model>ContosoExtensions</Model>
    <TargetFrameworkVersion>v4.8</TargetFrameworkVersion>
    <OutputPath>bin</OutputPath>
    <GenerateCrossReferences>True</GenerateCrossReferences>
    <RunAppCheckerRules>False</RunAppCheckerRules>
    <DeployOnline>False</DeployOnline>
    <ProjectGuid>{...}</ProjectGuid>
    <Name>ContosoProject</Name>
    <StartupType>Class</StartupType>
  </PropertyGroup>
  <PropertyGroup Condition="'$(Configuration)|$(Platform)' == 'Debug|AnyCPU'">
    <DBSyncInBuild>False</DBSyncInBuild>
    <Partition>initial</Partition>
  </PropertyGroup>
  <Import Project="$(MSBuildBinPath)\Microsoft.Common.targets" />
  <Import Project="$(BuildTasksDirectory)\Microsoft.Dynamics.Framework.Tools.BuildTasks.17.0.targets" />
</Project>

    Elements are Content items. Adding CustTable.ContosoExtensions writes:

    <ItemGroup>
  <Folder Include="Table Extensions\" />
</ItemGroup>
<ItemGroup>
  <Content Include="AxTableExtension\CustTable.ContosoExtensions">
    <SubType>Content</SubType>
    <Name>CustTable.ContosoExtensions</Name>
    <Link>Table Extensions\CustTable.ContosoExtensions</Link>
  </Content>
</ItemGroup>
    • Include is <AxType>\<Name>; the project view's folder is the first part of Link.
    • The folder names follow Visual Studio: Classes, Tables, Forms, Extended Data Types, Base Enums, Views, Queries, Maps, Data Entities, Menus, Tiles, Display Menu Items, Output Menu Items, Action Menu Items, Security Privileges, Security Duties, Security Roles, Services, Service Groups, Configuration Keys, Label Files, Reports, and the extension folders (Table Extensions, Form Extensions...).
    • Removing the last element of a type removes its Folder entry and empty item groups, as Visual Studio does.
    • References to C# projects and assemblies are ProjectReference and Reference items (Solution View and C# References).

    The .slnx written next to it lists the project:

    <Solution>
  <Configurations>
    <BuildType Name="Debug" />
  </Configurations>
  <Project Path="ContosoProject.rnrproj" Type="fc65038c-1b2f-41e1-a629-bed71d161fff" Id="..." />
</Solution>

    Options and settings¶

    Setting Default Effect
    xpp.project empty The .rnrproj of this workspace. Written by Open D365FO Project… into the project's workspace. A value in the user settings is not used. Changing it restarts the metadata server and refreshes the project view.
    xpp.git.baseBranch empty Branch the change marks compare with, in addition to uncommitted changes
    xpp.build.saveBeforeBuild true Save code views before Build Project
    xpp.build.msbuildPath empty MSBuild for the referenced C# projects

    Earlier versions kept xpp.project in the user settings, so every window opened the same project. F&O Studio now moves such a value to the recent projects list and removes it from the user settings.

    How it works¶

    • src/project.ts: ProjectWorkspaces (open, recent, close, workspace files), createProject (the .rnrproj and .slnx templates) and ProjectTreeProvider (the view). The project of a window is the workspace value of xpp.project; a .rnrproj that happens to be in an open folder does not select a project.
    • The view reads the .rnrproj itself (model and Content items). It watches the project's folder and refreshes 0.4 seconds after the file changes, so elements added by Copilot, the MCP server, Visual Studio or a Git pull show up on their own. It also watches the C# project folders and the solution file.
    • Writes to the project go through the metadata server: bridge actions add_to_project and remove_from_project, implemented by XppProject in server/Host/XppProject.cs, which edits the MSBuild XML the way Visual Studio saves it. add_to_project checks that the element exists and belongs to the project's model.
    • The metadata server is started with --project <rnrproj>; agent tools such as xpp_list_project_items, xpp_add_to_project, xpp_remove_from_project and xpp_select_project work on the same file (Agent Tools: Metadata).
    • An agent's project choice is written to %LOCALAPPDATA%\XppVsCode\activeProject.txt; the extension checks it every 3 seconds and asks before opening the project. Choices written before the window started are ignored.
    • Git marks come from ChangeDecorations in src/changes.ts, which runs git status (and git diff against the merge base of xpp.git.baseBranch) on the real path of each custom model folder.

    Limitations¶

    • One model per project, as in Visual Studio.
    • One project per window. To work on two projects at once, open two windows.
    • The project view does not rename or move project folders; folders follow the element types.
    • Project properties other than the model (Company, Partition, DBSyncInBuild...) are kept but not edited by F&O Studio. Edit the .rnrproj as XML if you need to.

    Troubleshooting¶

    Symptom Cause Fix
    No custom model found in the active configuration… when creating a project The environment has no model of yours Create one with Create Model…
    …already exists. Select it with "Select D365FO Project". A project with that name is in the parent folder Open it with Open D365FO Project…, or choose another name
    The project view is empty although a .rnrproj is in the folder The window has no project selected Run Open D365FO Project…
    Elements added by another tool do not appear The file watcher failed Click Refresh Project
    No Git marks The model folder is not in a Git repository, or nothing changed See Git Changes in the Project View
    Add to Project fails with a model message The element belongs to another model Extend it in your model or open that model's project

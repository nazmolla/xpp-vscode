    Visual Studio Side by Side¶

    F&O Studio never needs Visual Studio, but many developers keep Visual Studio on the same machine, or a team uses both. The two share the same files: the active metadata configuration, the custom metadata folder, the cross-reference database and the .rnrproj projects. This page explains what is shared, what F&O Studio does to keep Visual Studio working, and how Check Visual Studio's FinOps Tools Version keeps Visual Studio's Finance and Operations tools in step with the metadata.

    When to use it¶

    • You use Visual Studio and VS Code on the same machine, for example Visual Studio for a task F&O Studio does not cover yet.
    • After Connect to Environment downloaded a new application version and Visual Studio's Application Explorer no longer opens.
    • Your team is moving from Visual Studio to VS Code gradually.

    Before you start¶

    • Visual Studio 2022 with Microsoft's Finance and Operations tools (extension DynamicsFnO.DeveloperTools) installed, if you want to use it. If no such Visual Studio is installed, F&O Studio's Visual Studio checks do nothing.
    • For a unified developer environment (UDE), a configuration written by Connect to Environment… (it keeps the FinOps tools it downloaded).

    What is shared¶

    Item Where Notes
    Active configuration Registry HKCU\Software\Microsoft\Dynamics\AX7\Development\Configurations, values CurrentMetadataConfig and FrameworkDirectory Connect to Environment… sets both, so Visual Studio switches to the same environment. Select Environment… in VS Code does not change them.
    Configuration files %LOCALAPPDATA%\Microsoft\Dynamics365\XPPConfig\<org>___<version>.json Written by either tool; read by both. Visual Studio lists them in Manage local XPP configurations.
    System metadata %LOCALAPPDATA%\Microsoft\Dynamics365\<version>\PackagesLocalDirectory Same download, same layout.
    Custom metadata folder ModelStoreFolder, for example C:\CustomXppMetadata... Your models. Changes in one tool are visible in the other.
    Cross-reference database (LocalDB)\MSSQLLocalDB, XRef_... Same database for find references in both.
    Projects .rnrproj files F&O Studio edits them the way Visual Studio saves them.
    Build output and PDBs The package's bin folder F&O Studio converts PDBs to portable PDBs after every build; Visual Studio debugs the converted PDBs too.

    On a cloud-hosted or VHD environment, F&O Studio writes its own configuration into its extension storage and does not touch the registry or Visual Studio's files. Both tools build into the same PackagesLocalDirectory. See Cloud-Hosted and VHD Environments.

    How to use it¶

    Configurations Visual Studio can read¶

    Visual Studio reads configuration files with a strict serializer: a file that lacks a required member (AosWebsiteName, AudienceUri, DatabaseServer, DebugSourceFolder, DefaultModelForNewProjects, EnableOfflineAuthentication, ModelStoreFolder, WebRoleDeploymentFolder) is silently left out of Manage local XPP configurations, and Visual Studio cannot load metadata with it.

    • Connect to Environment… writes every member of Microsoft's Template_xppconfig.json (from the downloaded FinOps tools, or the same values built in), so its files are always complete.
    • Configurations written by older F&O Studio versions are completed automatically when the extension starts. Only files whose Description says they were generated "by X++ for VS Code" or "by F&O Studio for VS Code" are touched; missing members are added and existing values are kept. Each completed file is logged in the X++ output channel: Completed configuration <file> for Visual Studio (added ...).

    You do not need to do anything for this.

    Keep Visual Studio's FinOps tools in step¶

    Visual Studio's FinOps tools must match the metadata version of the active configuration, or its Application Explorer fails to open. After a connect to a new application version, they usually do not.

    Automatic prompt

    1. About 15 seconds after VS Code starts, F&O Studio looks for Visual Studio installations with the FinOps tools.
    2. If one has a different FinOps tools version than the active configuration needs, you see a warning:

    Visual Studio 2022 has FinOps tools 7.0.a, but the active configuration's metadata needs 7.0.b. Visual Studio's Application Explorer will not load until they match. F&O Studio is not affected.

    with Update Visual Studio and Don't Ask Again. 3. Don't Ask Again is remembered for this Visual Studio instance and this pair of versions; a later version mismatch asks again.

    Nothing is shown when no Visual Studio with the FinOps tools is installed, when the versions match, or when there is nothing to compare.

    On demand

    Run F&O Studio: Check Visual Studio's FinOps Tools Version from the Command Palette. It reports every outcome:

    Message Meaning
    "No Visual Studio with the Finance and Operations tools is installed on this machine; there is nothing to update." No Visual Studio, or none with the FinOps tools.
    "The active configuration has no FinOps tools downloaded by F&O Studio (for example a cloud-hosted environment), so there is nothing to compare." The active configuration's version folder has no FinOpsTools folder.
    "Visual Studio's FinOps tools match this environment ()." Nothing to do.
    The warning above, with Update Visual Studio A mismatch.

    Update Visual Studio

    1. Click Update Visual Studio.
    2. F&O Studio uses the FinOps tools VSIX that Connect to Environment… downloaded (<version folder>\Microsoft.Dynamics.FinOps.ToolsVS2022.vsix). If it is not there (older setups deleted it), it packs one from the extracted FinOpsTools folder into your temp folder (notification Preparing FinOps tools …).
    3. Visual Studio's VSIX Installer opens for that Visual Studio instance. A message tells you: "Close Visual Studio, then confirm the install in the VSIX Installer (it asks for administrator approval)."
    4. Close Visual Studio and confirm in the installer.

    Options and settings¶

    No settings. The "Don't Ask Again" answers are stored in VS Code's global state.

    How it works¶

    • Configuration template and repair: core/src/environment/config.ts; the repair runs at activation in src/extension.ts.
    • FinOps tools check: src/visualStudioTools.ts and src/vsFinOpsTools.ts.

    Finding Visual Studio and its FinOps tools¶

    1. Visual Studio installations come from vswhere.exe -all -prerelease -format json (in %ProgramFiles(x86)%\Microsoft Visual Studio\Installer). If vswhere.exe is missing, there is no Visual Studio.
    2. For each installation, the extension folders are searched up to three levels deep for an extension.vsixmanifest with the identity DynamicsFnO.DeveloperTools:
    3. <install>\Common7\IDE\Extensions (machine-wide install)
    4. %LOCALAPPDATA%\Microsoft\VisualStudio\<major>.0_<instance id>\Extensions (per-user install)
    5. The version is the Version attribute of that <Identity> element (Microsoft's manifest also holds a commented-out template identity, which is ignored).

    The version the environment needs¶

    The needed version is read the same way from <version folder>\FinOpsTools\extension.vsixmanifest, which Connect to Environment… extracts. The version folder is the parent of the active configuration's FrameworkDirectory.

    Packing and installing¶

    When the downloaded VSIX is missing, the files of FinOpsTools are zipped with the Windows tar.exe (zip format, forward-slash paths as VSIX packages need). The installer is started as:

    <install>\Common7\IDE\VSIXInstaller.exe /instanceIds:<instance id> <vsix>

    The VSIX Installer asks for confirmation and elevation itself.

    Limitations¶

    • Only Visual Studio installations that vswhere reports are found.
    • Only the first mismatched installation is offered per run.
    • Visual Studio must be closed for the VSIX Installer to finish.
    • Select Environment… changes only the VS Code workspace; Visual Studio keeps the active configuration from the registry until you connect again or change it in Visual Studio.
    • On cloud-hosted and VHD environments there is nothing to compare: the FinOps tools come with the VM.

    Troubleshooting¶

    Symptom Cause Fix
    Visual Studio's Application Explorer does not open after a connect Its FinOps tools do not match the new metadata Run Check Visual Studio's FinOps Tools Version and Update Visual Studio.
    Visual Studio does not list a configuration F&O Studio wrote The file lacks a member Visual Studio requires Restart VS Code (generated files are completed at startup) and check the X++ output for "Completed configuration".
    "VSIXInstaller.exe was not found in ..." The Visual Studio installation is incomplete Repair Visual Studio with the Visual Studio Installer.
    "... does not hold the FinOps tools." FinOpsTools is empty or incomplete Delete the FinOpsTools folder in the version folder and run Connect to Environment… again; it downloads and extracts the tools again.
    "Packing the FinOps tools failed: ..." tar.exe failed (disk full, temp folder not writable) Free space and try again.
    Visual Studio works with another environment than VS Code Each VS Code workspace has its own choice; Visual Studio uses the registry Run Connect to Environment… for the environment you want in Visual Studio, or switch in Visual Studio.

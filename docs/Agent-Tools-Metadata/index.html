    Agent Tools: Metadata¶

    These are the agent tools that read and change D365FO elements, find them, describe models and the environment, work with labels and manage the D365FO project. They all go through Microsoft's metadata API in F&O Studio's server, so an agent never reads or writes AOT XML files. For the overview, the guarantees and how the tools are registered, see MCP-Agent-Tools.

    Each section gives the tool's purpose, every input parameter, the output and an example of the arguments object of a tools/call request. Examples use standard objects and a custom model named ContosoExtensions.

    When the agent uses them¶

    Task Tools, in the usual order
    Understand an element xpp_find_object, xpp_read_object
    Create something new xpp_find_examples (see Agent-Tools-Analysis), xpp_get_object_type_schema, xpp_create_object, xpp_validate_object
    Extend a standard table or form xpp_read_object / xpp_get_form_layout on the base, xpp_create_object with AxTableExtension / AxFormExtension
    Change an element of your model xpp_read_object, xpp_update_object
    Clean up xpp_delete_object or xpp_remove_from_project
    Labels xpp_read_label, xpp_create_object (AxLabelFile), xpp_create_label
    Project xpp_select_project, xpp_list_project_items, xpp_add_to_project

    Before you start¶

    • An active D365FO configuration with its packages on disk.
    • A custom model in the custom metadata folder for every write (Models-and-Model-Dependencies).
    • An active project if new elements should be added to it. Without one, xpp_get_environment says ActiveProject: none and new elements are not added to a project.

    Elements¶

    xpp_read_object¶

    Reads any element by type and name: the declaration, every method's signature (with internal, private, public) and full source, and the strongly typed metadata (typedMetadata plus properties, enum values, fields, indexes, field groups, relations, data sources), the model and whether you can edit it. Large objects return a summary first.

    Parameter Type Meaning
    objectType string Any metadata type: AxClass, AxTable, AxForm, AxEnum, AxEdt, AxView, AxQuery, AxMap, AxReport, AxDataEntityView, AxTableExtension, AxFormExtension...
    objectName string The element name
    methodNames string[] Return the full source of only these methods (after a read that listed signatures only)
    sections string[] Only these sections, for example properties, dataSources, entityFields, fields, relations, indexes, fieldGroups, methods, declaration, controls, typedMetadata. ["summary"] lists the sections with their sizes; ["all"] returns everything
    filePath string Absolute path of the metadata file, if you have it; objectType + objectName is preferred

    Output: a header (ObjectType, Name, Model, Editable: YES/NO), then === Declaration ===, the methods and the metadata. Without sections, objects over 25,000 characters return their small sections plus a list of the large ones.

    { "objectType": "AxClass", "objectName": "SalesFormLetter", "methodNames": ["construct"] }

    xpp_create_object¶

    Creates a new element, all or nothing, and adds it to the active project. The response ends with a Validation: line; check it.

    Parameter Type Meaning
    objectType (required) string One of: AxClass, AxTable, AxView, AxDataEntityView, AxEdt, AxEnum, AxForm, AxTile, AxMenu, AxMenuItemDisplay, AxMenuItemOutput, AxMenuItemAction, AxQuery, AxSecurityPrivilege, AxSecurityDuty, AxSecurityRole, AxService, AxServiceGroup, AxConfigurationKey, AxTableExtension, AxEnumExtension, AxEdtExtension, AxFormExtension, AxDataEntityViewExtension, AxSecurityDutyExtension, AxSecurityRoleExtension, AxLabelFile, AxMenuExtension, AxCompositeDataEntityView, AxWorkflowCategory, AxWorkflowTemplate, AxWorkflowApproval, AxReport
    objectName (required) string Name, with the model's naming prefix. Extensions are named <Base>.<Suffix>
    modelName string Target model; default the active project's model
    typedMetadata object Full typed metadata graph of the type (see xpp_get_object_type_schema)
    declaration string Plain X++ class or table declaration; no XML, no CDATA
    methods string[] Complete X++ method sources; XML is rejected
    properties object Scalar properties as strings (Label, IsExtensible, TableGroup, EdtType, Extends, StringSize, Languages...); bool, int and enum values are converted
    enumValues object[] AxEnum: { name, value, label } (name, value required)
    fields object[] Tables: { name, fieldType, extendedDataType, enumType, label }; fieldType is String, Int, Real, Date, DateTime, Enum, Int64, Container, Guid or Time
    indexes object[] { name, allowDuplicates, alternateKey, fields[] }
    fieldGroups object[] { name, label, fields[] }
    relations object[] { name, relatedTable, constraints: [{ field, relatedField }] }; every relation is checked before saving
    dataSources object[] AxQuery: { name, table, parentDataSource, joinMode, linkType, dynamicFields, fields[], relations, firstOnly, ranges: [{ name, field, value }] }. AxFormExtension: data sources to add (name, table, parentDataSource, linkType)
    controls object[] AxFormExtension: controls to add: { name, controlType, parent, position (end, begin, after), previousSibling, dataSource, dataField, dataGroup, label, properties, controls[] }
    controlModifications object[] AxFormExtension: { name, properties } on base-form controls. Allowed properties: Text, Label, HelpText, Caption, Visible, Enabled, EnableFormRef, CountryRegionCodes, Pattern, PatternVersion, NeedsRecord, SaveRecord, AllowEdit, NeededPermission, Style, DataGroup
    entryPoints object[] Privileges: { name, objectType, objectName, grant }; objectType MenuItemDisplay, MenuItemOutput or MenuItemAction; grant such as Read or Read,Update,Create,Delete or Invoke
    dataEntityPermissions object[] Privileges: { name, grant, integrationMode (All, DataServices, DataManagement) }
    privileges string[] Duties, roles and their extensions: privileges to add
    duties string[] Roles and role extensions: duties to add
    entityFields object[] AxDataEntityViewExtension: { name, dataSource, dataField, label, mandatory }; the staging table extension gets the same fields
    skipStagingTable boolean AxDataEntityViewExtension: don't extend the staging table. Default false
    rootDataEntities object[] AxCompositeDataEntityView: one root { name, dataEntity, embeddedDataEntities: [{ name, dataEntity, relation, embeddedDataEntities }] }
    menuElements object[] AxMenuExtension: { name, menuItemName, menuItemType (Display, Output, Action), parent, position, previousSibling }

    Rules the tool applies:

    • Extensions. To change a standard table, enum or EDT, create AxTableExtension, AxEnumExtension or AxEdtExtension named <Base>.<Suffix> in your model. Fields, indexes, field groups, relations and enum values are added to the base; properties become property modifications of the base.
    • Form extensions. Call xpp_get_form_layout first. Placement is validated against the base form plus all its existing extensions before saving and verified after saving. Other control properties in controlModifications are rejected (they fail the build with UnsupportedPropertyForModification).
    • Security. Standard privileges can't be extended: create your own privilege and add it to a standard duty or role with AxSecurityDutyExtension / AxSecurityRoleExtension.
    • Label files. objectName is the label file ID, properties.Languages such as en-US,fr-CA; one label file per language is created.

    Example, a table extension with one field:

    {
  "objectType": "AxTableExtension",
  "objectName": "CustGroup.ContosoExtensions",
  "modelName": "ContosoExtensions",
  "fields": [ { "name": "ContosoPriority", "fieldType": "Int", "extendedDataType": "Integer", "label": "@ContosoLabels:Priority" } ]
}

    Example, a form extension that places a field after an existing control:

    {
  "objectType": "AxFormExtension",
  "objectName": "CustGroup.ContosoExtensions",
  "controls": [ { "name": "ContosoPriority", "parent": "<group from xpp_get_form_layout>", "position": "after",
                  "previousSibling": "<control from xpp_get_form_layout>", "dataSource": "CustGroup", "dataField": "ContosoPriority" } ]
}

    xpp_update_object¶

    Changes an element of your own model: declaration, methods, properties, structure, form extension controls, security content. Only custom-model elements; read the element first.

    Parameter Type Meaning
    objectType, objectName (required) string The element. For extensions, properties are written as property modifications of the base
    typedMetadata object Full typed metadata graph
    declaration string Replaces the declaration
    methods string[] Methods to add or replace (matched by name)
    removeMethodNames string[] Methods to remove
    properties object Scalar properties to set
    enumValues object[] Values to add; existing names are skipped
    fields object[] New fields. An existing name is refused; the EDT's base type must match fieldType; a removed field name can't come back with another base type
    updateFields object[] Change fields this object defines: { name, extendedDataType, enumType, label, helpText, properties }. The base type never changes
    removeFields, removeIndexes, removeFieldGroups, removeRelations string[] Names to remove (removed fields also leave their field groups)
    indexes, fieldGroups, relations object[] Add; an existing one of this object with the same name is replaced
    dataSources object[] AxQuery data sources, or data sources to add to an AxFormExtension
    controls object[] AxFormExtension: controls to add (same shape as in create)
    controlModifications object[] AxFormExtension: allowed property changes on base controls
    updateControls object[] AxFormExtension: change controls this extension added: { name, properties, label, dataSource, dataField, dataGroup, parent, position, previousSibling }; moves are verified
    removeControls string[] Controls this extension added (with their children). Base controls can't be removed: hide them with Visible=No
    removeControlModifications string[] "Control" or "Control.Property"
    entryPoints object[] Privileges: add or update by name; grant Read, Update, Create, Correct, Delete, Invoke or All
    privileges, duties string[] Add to duties and roles (and their extensions)
    dataEntityPermissions object[] Add or update
    removeSecurityItems string[] Entry points, data entity permissions, privileges or duties to remove
    entityFields, skipStagingTable object[], boolean Data entity extensions, as in create
    menuElements object[] AxMenuExtension: add or replace by name
    rootDataEntities object[] AxCompositeDataEntityView: the full reference tree (replaces the current one) 
    {
  "objectType": "AxClass",
  "objectName": "ContosoOrderStatusService",
  "methods": [ "public static void main(Args _args)\n{\n    info(\"Done\");\n}" ]
}

    To change a field's type, add a new field with another name and remove the old one: an Int field can't become a String field, because the database sync can't convert the column (Visual Studio behaves the same).

    xpp_delete_object¶

    Deletes an element of your own model completely (the metadata file and the project entry), like Visual Studio's Delete. Ownership is checked first. Then where-used: when other elements reference it, the delete is refused and the referencing elements are listed, unless force is true. If where-used can't be checked, the result says so.

    Parameter Type Meaning
    objectType (required) string Metadata type. Label files are deleted per language: <Id>_<lang>
    objectName (required) string The element
    force boolean Delete even when referenced (the referencing elements stop compiling). Default false 
    { "objectType": "AxClass", "objectName": "ContosoOrderStatusService" }

    xpp_validate_object¶

    Checks that an element exists, is in the active project and has the expected metadata, with a deep comparison of each section you pass. Returns valid=true only when every check passes; otherwise a list of mismatches with expected and actual values. Create and update run it automatically.

    Parameter Type Meaning
    objectType, objectName (required) string The element
    typedMetadata object Graph compared recursively (form controls, design, query data sources, role privileges...)
    properties object Expected key-value pairs, compared case-insensitively
    fields object[] Name, fieldType, extendedDataType, enumType, label
    enumValues object[] Name, value, label
    indexes object[] Name, allowDuplicates, fields
    relations object[] Name, relatedTable, constraints
    fieldGroups object[] Name, label, fields
    entryPoints object[] Name, objectType, objectName, grant
    dataSources object[] Table, joinMode, linkType, ranges, child data sources 
    { "objectType": "AxEnum", "objectName": "ContosoOrderStatus", "enumValues": [ { "name": "Open", "value": 0 } ] }

    xpp_get_object_type_schema¶

    Returns a JSON schema for an element type, generated by reflection over Microsoft's metadata classes. Agents use it to learn the full typedMetadata shape for create, update and validate.

    Parameter Type Meaning
    objectType (required) string For example AxClass, AxTable, AxForm, AxEnum, AxQuery, AxView 
    { "objectType": "AxEnum" }

    xpp_get_form_layout¶

    Shows the effective layout of a form: the base form with all its extensions applied by D365FO's own extension applier. Lists the data sources and the control tree with each control's type, binding and the extension that added it. Required before creating or updating an AxFormExtension.

    Parameter Type Meaning
    formName (required) string The base form (for example CustTable), not the extension
    rootControl string Show only the subtree under this control
    maxDepth integer Tree depth. Default 4, max 12. Containers with hidden children show (+N children) 
    { "formName": "CustGroup", "maxDepth": 3 }

    Finding elements¶

    xpp_find_object¶

    Searches the loaded metadata for elements by name, across all models and packages. Best for one exact name. Roles, duties and privileges (with a partial name) are also found by label text, such as "Sales manager"; each match shows its label. Output: matches with type, model and whether they are yours; exact matches come first.

    Parameter Type Meaning
    objectName (required) string Full or partial name, case-insensitive; partial names need at least 3 characters
    objectType string Limit to one type (much faster). An unknown type is reported as an error, never as "not found"
    exactMatch boolean Only exact name matches. Default false
    maxResults integer Default 10, max 50 
    { "objectName": "CustGroup", "objectType": "AxTable", "exactMatch": true }

    A no-match means nothing matched in the loaded metadata. Scans stop after a few seconds and return partial results with a message; the agent should narrow the search, not repeat it.

    xpp_list_objects¶

    Lists a handful of elements whose name contains a text. Only for substring discovery.

    Parameter Type Meaning
    nameFilter (required) string At least 3 characters, specific (for example SalesOrder)
    objectType string Strongly recommended; required with modelName
    modelName string Model filter
    maxResults integer Default 10, max 50 
    { "nameFilter": "CustGroup", "objectType": "AxForm", "maxResults": 5 }

    xpp_list_model_objects¶

    Lists what one model contains, reading the model's index on disk without loading metadata. Without objectType it returns counts per type; with it, sorted names, paged. Names only; reflects saved elements only.

    Parameter Type Meaning
    modelName (required) string Model, for example ApplicationPlatform or your model
    objectType string Type to list; omit for counts per type
    nameFilter string Case-insensitive substring
    offset integer Default 0
    limit integer Default 200, max 1000 
    { "modelName": "ContosoExtensions", "objectType": "AxClass" }

    Models and environment¶

    xpp_list_models¶

    Lists all models of the environment with their display name and editability (your own models are marked). No parameters.

    {}

    xpp_get_model_info¶

    Returns a model's name, display name, publisher, version, layer, model ID, package and dependencies.

    Parameter Type Meaning
    modelName (required) string The model 
    { "modelName": "ContosoExtensions" }

    xpp_get_environment¶

    Returns CustomMetadataFolder, each ReferenceMetadataFolder, ActiveProject, ActiveModel and Layer. Agents are told to call it only when the task needs this context, not to check whether an element exists. No parameters.

    Labels¶

    xpp_read_label¶

    Reads labels by ID or searches them by text. A full reference such as @SYS7149 or @SCM:SalesStatusLabel can be passed as labelId without labelFileId.

    Parameter Type Meaning
    labelFileId string Label file ID; optional with a full @ reference
    language string Default en-US
    labelId string Label ID or full reference
    searchText string Find labels containing this text
    maxResults integer Default 25, max 100 
    { "labelId": "@SYS7149" }

    xpp_create_label¶

    Creates labels in a label file of your model: one (labelId + text) or many (labels), each in the given language and optionally in other languages. Each label file is written once per call. The result lists every label and language as created, unchanged (same text already there) or FAILED, and the reference to use in properties: @<labelFileId>:<labelId>. The label file must exist (create it with xpp_create_object, type AxLabelFile).

    Parameter Type Meaning
    labelFileId (required) string The label file ID
    language string Language of text. Default en-US
    labelId string Letters and digits; omit when using labels
    text string The text
    translations object Texts in other languages of the same file, keyed by language code
    comment string Optional comment
    labels object[] { labelId, text, comment, translations } (labelId, text required) 
    {
  "labelFileId": "ContosoLabels",
  "labels": [
    { "labelId": "Priority", "text": "Priority", "translations": { "fr-CA": "Priorité" } },
    { "labelId": "PriorityHelp", "text": "Priority of the customer group" }
  ]
}

    Label text files are not AOT metadata: the server writes <Id>.<lang>.label.txt under your model's AxLabelFile\LabelResources\<lang> folder directly, sorted by ID, and only under the custom metadata folder. See Label-Editor.

    Project¶

    xpp_select_project¶

    Without projectFile, lists the .rnrproj projects that can be opened (the active one marked *), from searchFolder, the current project's repos folder and %USERPROFILE%\source\repos. With projectFile, makes it the active project for all tools: new elements are added to it and scope=project builds use it. The VS Code project view follows the selection.

    Parameter Type Meaning
    projectFile string Full path of the .rnrproj to activate; omit to list
    searchFolder string Extra folder to search, 3 levels deep

    xpp_add_to_project¶

    Adds an existing element to the active project, the way Visual Studio saves it (<Content Include="AxClass\Name">).

    Parameter Type Meaning
    objectType, objectName (required) string The element 
    { "objectType": "AxTable", "objectName": "CustGroup" }

    xpp_list_project_items¶

    Lists the items of the active project with their file paths. Says The active project is empty. or No active project. Select one with xpp_select_project. No parameters.

    xpp_remove_from_project¶

    Excludes an element from the active project and keeps it in the model, like Visual Studio's Exclude From Project.

    Parameter Type Meaning
    objectType, objectName (required) string The element

    How it works¶

    • xpp_create_object, xpp_update_object, xpp_list_models, xpp_get_environment, xpp_list_project_items, xpp_remove_from_project and xpp_select_project pass their arguments to the bridge action of the same name (create_object, update_object, ...) in MetaModelBridgeServer.cs. Element types and what each supports are in MetaModelBridge.ElementTypes.cs.
    • xpp_delete_object first calls delete_object with checkOnly (ownership and existence), then queries the cross-reference database for users of the element, then deletes.
    • xpp_list_model_objects is served by ModelObjectLister (ModelObjectLister.cs), which reads the model folder on disk.
    • Labels are handled by LabelStore in server/Host; .rnrproj edits by XppProject.
    • After a write the metadata host reloads what changed, so the next read sees it.
    • Write tools are checked against your models, the Copilot scope and the open checkpoint (see MCP-Agent-Tools).

    Limitations¶

    • Writes only in your own models. Standard reports and standard privileges can't be extended; copy the report (Agent-Tools-Reports) or create your own privilege.
    • xpp_list_model_objects reflects saved elements only.
    • Name searches are bounded in time and results; they are not a full inventory.

    Troubleshooting¶

    Symptom Cause Fix
    Validation: FAILED after a create or update The saved element doesn't contain everything requested Read the mismatches; fix with xpp_update_object or delete with xpp_delete_object
    ... is still referenced by N object(s): ... Not deleted. Other elements use it Remove the references first, or pass force=true
    Model '...' is not one of your custom models. modelName points to a reference model Use your own model
    A form extension control is refused The parent or previous sibling doesn't exist in the effective layout, or a modification uses a property outside the allowed list Call xpp_get_form_layout and pick placement from its output
    Partial results with a message from xpp_find_object The scan hit its time limit Pass objectType and exactMatch=true

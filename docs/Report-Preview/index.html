    Report Preview¶

    The Report Designer's Preview renders a precision design with Microsoft's own report engine (the Report Viewer runtime), with the same hard page layout as PDF and print. You see the real pages, with labels in the language you choose and sample data or rows you type, without deploying the report. Visual Studio has no local preview for D365FO reports; there you deploy and run the report on the environment.

    When to use it¶

    • Check a layout to the millimetre before you build and deploy: page breaks, growing textboxes, blank pages, fonts.
    • Compare the rendered page with a scanned form (see Scan-Overlay-and-Measure).
    • Check how long values (names, amounts) fit in their boxes, with the values printed on your sample form.

    Before you start¶

    • A precision design open in the Report-Designer. The preview renders precision designs only.
    • Microsoft's Report Viewer runtime, downloaded once from nuget.org after you accept Microsoft's licence. F&O Studio doesn't ship it. See Installing the runtime.
    • No environment connection is needed: rendering runs on your machine.

    How to use it¶

    1. In the Report Designer, click Preview in the toolbar. The first time, the preview renders right away.
    2. If the runtime isn't installed, the licence prompt opens first (see below).
    3. The pages appear in the centre. A line above them says which pages are shown, the total page count and the resolution, for example "Pages 1–3 of 5 · rendered by Microsoft's report engine (as PDF and print) at 110 dpi". Warnings follow.
    4. Change the settings in the right panel and click Render to render again.
    5. Click Design to go back to the layout.

    The preview renders the design as it is in the designer, including unsaved changes.

    Settings¶

    Setting Default Effect
    Language en-US Language of the label texts and the AX_RenderingCulture parameter. Labels missing in that language fall back to en-US.
    Company USMF Value of the AX_CompanyName parameter.
    Sample rows 1 Rows generated for each dataset you leave empty (0 to 200).
    Pages 3 Number of pages rendered (1 to 20).
    Resolution (dpi) 110 Resolution of the page images (48 to 300).
    Show scan under the page off Only when a scan is loaded: lays the scan under each page and blends them.

    Settings are remembered for the panel.

    Data¶

    Under Data (JSON rows per dataset) there is a text box per dataset. Type a JSON array of rows, field name to value:

    [
  { "AccountNum": "US-001", "Name": "Contoso Retail San Diego", "AmountCur": 1234567.89, "TransDate": "2026-01-31" },
  { "AccountNum": "US-002", "Name": "Contoso Wholesale", "AmountCur": 42.5, "TransDate": "2026-02-01" }
]
    • The placeholder of each box shows a sample row built from the dataset's fields.
    • A box that isn't a JSON array is rejected with a message when you leave it.
    • Fields you leave out of a row get a generated value.
    • Datasets left empty get Sample rows generated rows.

    Generated values are chosen to show realistic widths: text fields get the field name (Name, Name 2…), numbers 12345.67 (times the row number), integers the row number, dates 31 January 2026 plus the row number in days, and booleans false.

    Tip: type the values printed on your sample form, so the widths you see are the widths that print.

    What the preview does with D365FO specifics¶

    • Labels (=Labels!@SYS12345, @File:Id, and plain label references in values) are replaced by their text in the chosen language.
    • Parameters: every report parameter, the framework parameters (AX_PartitionKey, AX_CompanyName, AX_UserContext, AX_RenderingCulture, AX_ReportContext, AX_RdpPreProcessedId) and any parameter the design uses get a value: the company and language above, false for booleans, 0 for numbers, today for dates, empty text otherwise.
    • D365FO report functions that need an AOS session are replaced by local stand-ins: for example ToDisplayStringAmount, ToDisplayStringDate, ConvertUtcToAxUserTimeZoneForUser, GetFullCompanyNameForUser, NumeralsToTxt (amount in English words), SplitReportItem, GetExtendedDataTypeFormat, PostDataMethodEvaluation. Functions without a stand-in are shown empty, and a warning names them: "Shown empty in the preview (they need the environment): …".
    • Datasets and fields the design uses but the report doesn't define are added so the render doesn't fail, with a warning ("Dataset '…' is used by the design but not defined on the report.").
    • Embedded images of the report are included.

    Installing the runtime¶

    The first Preview (or the command Install Report Preview Runtime) shows a modal prompt:

    The report preview uses Microsoft's report engine (the Report Viewer runtime), which F&O Studio does not include. Install it now? …

    • View Licence Terms opens Microsoft's licence terms for both packages in the browser, then asks again.
    • Accept Licence and Install downloads and installs.
    • Closing the prompt cancels; the preview then says it needs Microsoft's report engine and shows Install runtime….

    What is installed:

    Package (nuget.org) Version Files used
    Microsoft.ReportingServices.ReportViewerControl.Winforms 150.1652.0 Microsoft.ReportViewer.Common, .DataVisualization, .ProcessingObjectModel, .WinForms and their resources (net40)
    Microsoft.SqlServer.Types 14.0.1016.290 Microsoft.SqlServer.Types.dll

    The download is about 15 MB. Each package is checked against a pinned SHA-512 hash, and each extracted file against a pinned SHA-256 hash; nothing is installed when a hash doesn't match. The files go to %LOCALAPPDATA%\FOStudio\ReportViewer\150.1652.0, with a .licence.txt per package recording the licence link.

    The same runtime is used by Copilot's report tools xpp_render_report and xpp_compare_layout (see Agent-Tools-Reports).

    Options and settings¶

    There are no VS Code settings for the preview. The preview settings above are stored in the panel.

    Command Effect
    Install Report Preview Runtime Checks the runtime; asks for the licence and installs it when it is missing or changed.

    How it works¶

    1. The designer sends the current RDL, your rows and the settings to the extension (src/reports/reportDesigner.ts), which makes sure the runtime is installed (src/reports/reportRuntime.ts) and calls the bridge action render_report.
    2. The server checks the runtime folder again: it loads the runtime only when every file matches its pinned hash (server/Host/Reports/ReportRuntime.cs).
    3. RdlPreview.Prepare builds a renderable report from the design (server/Host/Reports/RdlPreview.cs): it removes the design's code modules, data sources, datasets and parameters; resolves labels; rewrites the D365FO helper calls to the local stand-ins (a VB Code block); declares a local data source, the report's datasets (from the metadata) and its parameters; and fills a DataTable per dataset with your rows or sample rows.
    4. ReportRenderer renders it with LocalReport in a separate application domain whose base folder is the runtime folder, as PNG pages ("IMAGE" renderer with the chosen dpi), one page at a time (server/Host/Reports/ReportRenderer.cs). External images and hyperlinks are off. The domain is recycled every 50 renders to keep memory bounded.
    5. The result returns the pages, the total page count, the page geometry, each item's position in mm and the warnings (layout checks, preparation notes and the engine's own warnings).

    Limitations¶

    • Only precision designs render; for an auto design, create a precision design first.
    • Data is local: sample rows or rows you type. The data provider doesn't run, so values computed in X++ aren't there.
    • D365FO report functions without a local stand-in show empty. Stand-ins approximate the AOS (for example GetEnumLabelFromValue shows the value, time-zone conversion keeps the value as given).
    • Fonts not installed on your machine are substituted (a warning says which). MICR and barcode fonts are often not installed locally; check those on the environment.
    • At most 20 pages per render.
    • The runtime is Windows .NET Framework code and is downloaded, not shipped; without internet access to nuget.org you can't install it from F&O Studio.

    Troubleshooting¶

    Symptom Cause Fix
    "The preview needs Microsoft's report engine (Install Report Preview Runtime)." You declined or closed the licence prompt. Click Install runtime… or run Install Report Preview Runtime.
    "The Report Viewer runtime in … is incomplete or was changed (…). Run 'F&O Studio: Install Report Preview Runtime' again." A runtime file is missing or doesn't match its hash. Run Install Report Preview Runtime.
    "Downloading … from nuget.org failed: HTTP …" No access to nuget.org, or a proxy blocks it. Allow api.nuget.org and try again.
    "… from nuget.org is not the package F&O Studio expects (hash mismatch); nothing was installed." The downloaded package differs from the pinned one. Try again; check for a proxy that changes downloads.
    "The report engine could not render …: …" The engine rejected the RDL or an expression. Read the message; fix the expression or item in the designer.
    "Design '…' is an auto design; the preview renders precision designs." The design is an auto design. Create a precision design from it.
    "Dataset: enter a JSON array of rows (…)." The data box isn't a JSON array. Wrap rows in [ ] and use valid JSON.
    Values show empty The textbox uses a D365FO function without a stand-in. See the "Shown empty in the preview" warning; check on the environment.

    Open in SSMS¶

    Open Database in SQL Server Management Studio starts SQL Server Management Studio (SSMS) connected to the same database F&O Studio uses: the local AxDB with Windows authentication on a cloud-hosted or VHD environment, or the unified developer environment's Azure SQL database with the JIT credentials F&O Studio requested. The password is put on the clipboard, never on a command line. Use it when you need what the SQL Query Panel does not offer: graphical plans, actual execution plans, Activity Monitor, or longer scripts.

    When to use it¶

    • You want the graphical or actual execution plan, beyond the summary of Explain Plan.
    • You need SSMS tools: Object Explorer, Activity Monitor, Query Store reports, index properties.
    • You prefer SSMS's editor for a long investigation script.

    For a quick look at rows, Browse Table Data and the SQL Query Panel stay inside VS Code and are read-only by default. SSMS is not.

    Before you start¶

    • SQL Server Management Studio installed under Program Files or Program Files (x86) in a folder named Microsoft SQL Server Management Studio <version>. F&O Studio finds SSMS 21 and later (under Release\Common7\IDE) and older versions (under Common7\IDE), and starts the newest.
    • Database access for the active environment. See Database Access. On a unified developer environment, F&O Studio asks for JIT credentials if there are none.
    • On a UDE, your public IP address must be within the addresses you allowed when requesting the credentials.

    How to use it¶

    1. Run it from one of these places:
    2. Command Palette: F&O Studio: Open Database in SQL Server Management Studio.
    3. Database menu: click the database item in the status bar, or Dynamics 365 view > Data > Database…, then Open in SQL Server Management Studio.
    4. On a UDE, a notification says: "The database password is on the clipboard: paste it in SSMS's sign-in, then clear the clipboard."
    5. SSMS receives the connection on its command line:
    6. Server: the database server.
    7. Database: the business database.
    8. Sign-in: Windows authentication on a local database, SQL Server authentication with the JIT user name on a UDE.
    9. On a UDE, SSMS needs the password: paste it (Ctrl+V) when SSMS asks for it, and connect.
    10. When you are done, clear the clipboard (for example, copy something else).

    Getting the details by hand¶

    If SSMS is installed somewhere else, or you use another client (Azure Data Studio, the mssql extension, sqlcmd), use F&O Studio: Copy Database Connection Detail. It lets you copy Server, Database, and, on a UDE, User name and Password, one at a time. See Database Access.

    What to do in SSMS that the panel does not¶

    Task In SSMS In F&O Studio instead
    Graphical estimated plan Query > Display Estimated Execution Plan Explain Plan gives a text summary
    Actual plan with real row counts Query > Include Actual Execution Plan, then run Not available (the panel never runs a query to get its plan)
    Query Store reports Object Explorer > the database > Query Store "Most expensive queries" in Database Performance Insights
    Scripts with variables or temporary tables Any query window Not possible in read-only mode (DECLARE, INTO are refused)
    Browse a table with labels and enum names Not available Browse Table Data
    Follow relations between records Write the joins yourself The record inspector in Browse Table Data

    With Reader credentials on a UDE, some of these may be refused by the database's permissions.

    Be careful in SSMS¶

    SSMS is not limited the way F&O Studio's panel is:

    • With Writer credentials or on a local database, statements you run are committed unless you wrap them in a transaction yourself.
    • Changes made in SQL skip X++ business logic: insert/update/delete methods, validation, the database log, events, number sequences and the server's caches.
    • Request Reader credentials when you only need to read.

    Options and settings¶

    There are no settings for SSMS. The connection comes from Database Access.

    How it works¶

    src/database/ssms.ts:

    1. F&O Studio gets the database target: the local server and database from the active configuration, or the stored JIT credentials (asking for them if needed).
    2. It looks in %ProgramFiles% and %ProgramFiles(x86)% for folders named Microsoft SQL Server Management Studio <n>, checks <folder>\Release\Common7\IDE\SSMS.exe and <folder>\Common7\IDE\Ssms.exe, and takes the highest version that exists.
    3. It starts SSMS detached from VS Code with:
    4. -S <server> -d <database> -E for Windows authentication, or
    5. -S <server> -d <database> -U <user> for SQL authentication. The password is written to the clipboard instead of the command line, where other processes on the machine could read it.
    6. If SSMS fails to start, an error shows the reason.

    SSMS connects to the database directly; F&O Studio's server process is not involved.

    Limitations¶

    • Only SSMS is started. Other clients need the details from Copy Database Connection Detail.
    • SSMS installations outside Program Files folders with the standard name are not found.
    • The JIT credentials expire. An open SSMS session stops working when they do; request new credentials and connect again.
    • The password is on the clipboard until you replace it; clipboard history tools may keep it.

    Troubleshooting¶

    Symptom Cause Fix
    "SQL Server Management Studio was not found. Install it, or use New SQL Query here." No SSMS in the expected folders Install SSMS, or use the SQL Query Panel or Copy Database Connection Detail
    "SSMS could not start: …" Windows could not start the executable Check the SSMS installation
    SSMS sign-in fails on a UDE right after requesting credentials Azure SQL applies the firewall rule and password within minutes Wait a minute and connect again
    SSMS sign-in fails later Credentials expired or replaced, or your public IP changed Run Request Database Credentials and open SSMS again
    SSMS asks for a password Expected with JIT credentials: it is on the clipboard Press Ctrl+V in the password box

    X++ Code View¶

    The X++ code view shows the code of an element (a class, table, form, view, data entity, query or map) as one editable document in VS Code. It is the equivalent of the code editor Visual Studio opens when you choose View Code: a class shows its declaration and then its methods inside the class braces. When you save, F&O Studio splits the document back into the declaration and the methods and writes them through the D365FO metadata API. It never writes the XML files on disk by hand.

    When to use it¶

    • Read or change the X++ code of an element in your own model.
    • Read standard code (read-only) to understand how Microsoft implemented something, for example SalesFormLetter or CustGroup::find.
    • Use the code intelligence features (definition, references, implementations, code lens, completion and more). They all work on code view documents.
    • Set breakpoints for the debugger (see Breakpoints and Source Mapping).

    Before you start¶

    • An active D365FO configuration (see Connect to Environment or Select Environment). The code view reads metadata through the F&O Studio server, which loads Microsoft's metadata assemblies from your installation.
    • To edit and save, the element must be in one of your models (a model whose packages are in your custom metadata folder). Standard elements open read-only.
    • No project is needed to read code. To build after a change you need a D365FO project (see D365FO Projects).

    How to use it¶

    Open code¶

    You can open the code view from several places:

    1. Application Explorer or the project view: click a class. Classes open straight in the code view. For tables, forms, views, data entities, queries and maps, right-click and choose View Code (also an inline icon on the node). Other element types open in the Element Designer.
    2. Element designer: the editor title shows View Code when the element has code. Double-clicking a method node opens the code view at that method.
    3. Open Element… (Ctrl+Alt+O): pick a class to open its code. Other code elements have a View Code button in the picker row. See Open Element.
    4. From code: Go to Definition (F12), Find All References, Go to Implementations, the call hierarchy, a code lens or Ctrl+click on tableStr(...)-style references all open code views.
    5. Copilot: the xpp_open_element tool lets an agent open an element in the code editor at a method or a piece of text instead of opening its XML.

    The tab title is the element name with .xpp, for example CustGroup.xpp. The breadcrumbs show the element type (AxTable), the file, the element and the method the cursor is in. Standard elements show a lock icon on the tab.

    What you see¶

    For a class, the document looks like this:

    [ExtensionOf(classStr(SalesFormLetter))]
final class SalesFormLetter_ContosoExtensions_Extension
{
    boolean contosoChecked;

    public void run()
    {
        next run();
        this.contosoAfterRun();
    }

    private void contosoAfterRun()
    {
        info("Done");
    }

}
    • The declaration comes first, without its closing brace.
    • The methods follow inside the class body, each indented one level, with a blank line between them.
    • The last line is the closing brace of the class.

    Tables, views, maps, data entities and queries look the same way: their declaration (for example public class CustGroup extends common) and then their methods. A form shows its form-level class declaration and form methods.

    Methods that belong to a node inside an element, such as the methods of a form data source, a data source field or a form control, do not appear in the element's document. They open in their own editor, one method per document. Open them from the element designer (double-click the method node) or follow a reference to them.

    Edit and save¶

    1. Change code anywhere in the document: inside methods, in the declaration, or add and remove whole methods.
    2. Press Ctrl+S.
    3. F&O Studio splits the text into the declaration and the methods and saves them through the metadata API in one update:
    4. a method that is new in the text is added;
    5. a method that is missing from the text is removed from the element;
    6. a changed method or declaration is replaced.
    7. The code lens, member cache and other caches refresh. If Compile on save is on, the project builds (see Code Intelligence Settings).

    You don't need to keep any special markers. Write normal X++: methods start with their doc comments, attributes and signature, and end with their closing brace.

    Comments and macros at the end of the declaration stay with the declaration. A comment on the same line as a member stays with that member. Fields or macros you write between methods are moved into the declaration when you save.

    Build after editing¶

    Saving does not compile. Build with Build Project (Ctrl+Shift+B in an X++ editor). Unsaved code views are saved before the build when xpp.build.saveBeforeBuild is on (the default). Compiler errors go to Problems at the right line of the code view. See Build Project and Model and Compiler Diagnostics.

    Editor context menu¶

    Right-click in a code view to find these F&O Studio commands:

    Command What it does
    Open Designer Opens the element in the Element Designer
    Locate in Application Explorer Selects the element in the Application Explorer
    View History Shows the git history of the element (Element History)
    Analyze Performance Runs the static performance rules on the element (Analyze Performance)

    The standard VS Code commands (Go to Definition, Find All References, Go to Implementations, Rename Symbol, Format Document, Show Call Hierarchy and others) are on the same menu and are described on their own pages.

    Options and settings¶

    Setting Default Effect
    xpp.build.saveBeforeBuild true Save unsaved X++ code views before a build
    xpp.codeIntelligence.diagnosticsOnSave false Build the project after saving code, so semantic errors reach Problems
    xpp.codeIntelligence.* see Code Intelligence Settings Switch each code intelligence feature on or off

    How it works¶

    The xpp: document model¶

    Each code view is a virtual file served by a VS Code file system provider for the xpp scheme (src/codeView.ts). There is no .xpp file on disk.

    Document URI
    Element code xpp:/AxClass/SalesFormLetter.xpp, xpp:/AxTable/CustGroup.xpp
    Method of a nested node xpp:/AxForm/CustTable/DataSources/CustTable/Methods/init.xpp

    Element types with an editable code view: AxClass, AxTable, AxForm, AxView, AxDataEntityView, AxQuery, AxMap.

    Reading. For an element document the provider calls the bridge action read_object, which returns the declaration and the list of methods. composeSource in src/xppSource.ts builds the text:

    1. the declaration up to (not including) its closing brace;
    2. each method, indented to at least four spaces if it was stored at column 0 (a tab counts up to the next multiple of four, as in Visual Studio), separated by blank lines;
    3. the closing brace.

    Forms store their declaration as a method named classDeclaration; it becomes the head of the document. An element without a class-style declaration falls back to one block per method.

    For a nested method the provider calls get_element_method. The common indentation of the method is removed for display and put back when you save.

    The document is marked read-only when the server says the element is not in one of your models.

    Saving. splitSource parses the text back:

    • it finds the class header (attributes and using lines may come before it) and the opening brace;
    • it walks the class body, skipping comments, strings (including @"..." and @'...' verbatim strings) and attributes;
    • each top-level { ... } block in the body is a method, starting at its first non-blank line (so doc comments and attributes stay with the method);
    • members ending with ; after the first method are moved into the declaration;
    • the original declaration is used to tell trailing comments of the declaration from comments that start the first method.

    The provider then sends update_object with the declaration, the methods, the names of removed methods and formatCode: false (your layout is kept). A nested method is saved with set_element_method. Both go through the metadata API in the server (Metadata Server), which checks that the element is in a custom model.

    Line numbers. The compiler and the cross-reference database number lines as if the declaration (without its closing brace) and the methods were written back to back. compilerLineToDocumentLine and documentLineToCompilerLine translate between those numbers and code view lines. Build errors, references, call hierarchy entries and the debugger all use this mapping.

    Caching. The provider keeps the last text it read for each URI and reads the element again each time VS Code opens the document. After a save the cached copy is dropped. When you switch environment, open documents without unsaved changes reload with the new environment's metadata.

    What runs where¶

    • The code view, definition and references use the main F&O Studio server process.
    • Code intelligence (implementations, code lens, completion, syntax check, symbols) runs in a second server process, so a slow index build never blocks the designers. See Extension Internals.

    Limitations¶

    • Standard elements are read-only. Change them with an extension or Chain of Command; see Create Extension and Create Code Extension.
    • Methods of data sources, fields and controls are not part of the element's document. Writing a nested class (classDeclaration) into the element's document is refused with "Nested classes (data source and control methods) can't be edited in this view yet."
    • You can't create, delete or rename elements by creating, deleting or renaming code view files. Use New Element, the Application Explorer Delete command, or Rename and Refactoring.
    • The code view does not compile on save unless you turn on Compile on save.

    Troubleshooting¶

    Symptom Cause Fix
    Save fails with "... is not in a custom model. Change it with an extension or Chain of Command instead." The element is standard or in a model that is not yours Create an extension or a Chain of Command class
    Save fails with "Code after the class's closing brace (line N) is outside the class." Text after the last } Move the code inside the class braces
    Save fails with "Unbalanced braces: the class is not closed." A missing } Fix the braces; the live syntax check marks where
    Save fails with "Nested classes (data source and control methods) can't be edited in this view yet." A class ... { } block was pasted into the element's document Open the data source or control method from the designer
    Deleting the file or renaming the tab fails Not supported in the code view Use the Application Explorer commands
    Code view shows old code after a change elsewhere (designer, Copilot) The open document was read before the change Close and reopen the tab; it is read again from metadata

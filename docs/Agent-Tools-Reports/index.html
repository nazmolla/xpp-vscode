    Agent Tools: Reports¶

    These agent tools let an agent work on SSRS reports the way a report developer does in Visual Studio's report designer, and add what Visual Studio doesn't have: rendering a precision design with Microsoft's report engine and seeing the pages, measuring a scanned form in millimetres, and laying the rendered page over the scan to see how far each field is off. Together they let an agent build a report for preprinted stationery (a cheque, an invoice form) and check every field's position. For the overview and the guarantees, see MCP-Agent-Tools.

    Tool Purpose Changes metadata
    xpp_get_report_design Read a report: designs, datasets, parameters, page geometry, items in mm, warnings, RDL No
    xpp_set_report_design Save a precision design's RDL, generate one from an auto design, or copy a standard report into your model Yes, your model only
    xpp_render_report Render a precision design with sample or given data; pages as images, item positions, optional PDF No
    xpp_measure_image Measure a scanned form: scale, deskew, boxes, rules, text with positions, a picture with a mm grid No
    xpp_compare_layout Overlay a rendered page on the scan and report each text box's offset in mm No

    When the agent uses them¶

    • To learn how a standard report builds its layout (for example SalesInvoice, PurchPurchaseOrder, Cheque_US) before designing one.
    • To change the layout of a standard report: copy it into your model and change the copy (reports have no extensions).
    • To place fields on preprinted stationery from a scan, then iterate until every field is within tolerance.

    The Report Builder agent (Agents-for-Developers) follows this loop from a scanned or sample document. Scenario: Scenario-Report-from-a-Scanned-Document.

    Before you start¶

    • An active D365FO configuration with its packages on disk.
    • A custom model for xpp_set_report_design.
    • For xpp_render_report and xpp_compare_layout: the report preview runtime. Install it in VS Code with F&O Studio: Install Report Preview Runtime (Report-Preview).
    • For xpp_measure_image and xpp_compare_layout: a scan as PNG, JPEG, TIFF or BMP (export a PDF page as a 300 dpi image first). Text reading uses Windows' built-in OCR on your machine; nothing is uploaded. The OCR language must be installed in Windows.

    The loop the agent follows¶

    1. xpp_measure_image on the scan: calibrate the scale, read the boxes, rules and printed text with their positions in mm.
    2. xpp_get_report_design on the report to change (or a standard one to learn from): datasets, fields, page geometry.
    3. Create or copy the report and its precision design with xpp_set_report_design (duplicateOf, fromAutoDesign or rdl).
    4. Write the RDL with items at the measured positions; save it with xpp_set_report_design.
    5. xpp_render_report with data that shows the values printed on the sample, to see real widths.
    6. xpp_compare_layout against the scan; move each item by its reported offset; repeat steps 4 to 6 until every item is within toleranceMm.
    7. Build the model with xpp_build (Agent-Tools-Build-and-Data); the build compiles the report for deployment.

    xpp_get_report_design¶

    Reads an SSRS report: its designs, datasets with fields and types, parameters, and for a precision design the page geometry, every report item with its position in mm on the page (as designed, before growth), layout warnings (body wider than the page, fonts the cloud doesn't have, items outside the body) and the RDL text to edit.

    Parameter Type Meaning
    reportName (required) string The report (AxReport)
    designName string The design. Default: the first design
    includeRdl boolean Include the RDL text. Default true; false for the summary only 
    { "reportName": "SalesInvoice", "includeRdl": false }

    Output, in order:

    • Report <name> (model <model>, yours) or ..., standard: copy it into your model before changing it.
    • Designs: each design with its kind.
    • One Dataset line per dataset: data source type, query, fields with types.
    • Parameters: (the AX_ parameters are left out; hidden ones marked).
    • Page W x H mm, margins L R T B, body W x H mm, header H mm, footer H mm.
    • WARNING: lines.
    • Items: type, name, section/container, x, y, w, h, font and size, grow (CanGrow), hidden-if, value. Up to 400 items.
    • The RDL, truncated when very long.

    xpp_set_report_design¶

    Saves the RDL of a precision design (AxReportPrecisionDesign.Text) of a report in your model through the metadata API, as Visual Studio's report designer does, and creates the design when it doesn't exist. Images embedded in the RDL become the report's embedded images. Positions and sizes take units (mm, cm, in, pt). Returns layout warnings.

    Parameter Type Meaning
    reportName (required) string The report in your model (or the name of the copy, with duplicateOf)
    designName string The precision design to save or create
    rdl string The complete RDL document (<Report xmlns="http://schemas.microsoft.com/sqlserver/reporting/2016/01/reportdefinition">...). Keep the namespace of the design you read
    duplicateOf string Copy this report (for example SalesInvoice or Cheque_US) into your model as reportName first; its datasets keep using the standard data provider
    modelName string Your model for the copy; required with duplicateOf
    fromAutoDesign string Instead of rdl: create designName as a precision design from this auto design, with Microsoft's report generator (Visual Studio's Create Precision Design). The auto design stays

    Three ways to call it:

    { "reportName": "ContosoSalesInvoice", "duplicateOf": "SalesInvoice", "modelName": "ContosoExtensions" }

    { "reportName": "ContosoOrderStatusReport", "fromAutoDesign": "AutoDesign1", "designName": "Report" }

    { "reportName": "ContosoSalesInvoice", "designName": "Report", "rdl": "<Report xmlns=\"http://schemas.microsoft.com/sqlserver/reporting/2016/01/reportdefinition\">...</Report>" }

    What it tells the agent next:

    • After a copy: add it to the project with xpp_add_to_project, and route printing to it through print management (PrintMgmtDocType.getDefaultReportFormatDelegate, PrintMgmtReportFormatPopulator.addDocuments) or the controller (parmReportName).
    • After generating from an auto design: read the generated layout with xpp_get_report_design, adjust it, check it with xpp_render_report.
    • After saving RDL: check the layout with xpp_render_report; xpp_build compiles the report (reportsc) into the package for deployment.

    When the report is standard, the save is refused with the ownership message plus: "Reports have no extensions: copy it into your model with duplicateOf (the standard report), reportName (the copy) and modelName, then change the copy." Without rdl, fromAutoDesign or duplicateOf, it answers Pass designName and rdl (or fromAutoDesign to generate it from an auto design, or duplicateOf to copy a report).

    xpp_render_report¶

    Renders a precision design with Microsoft's SSRS report engine (the engine behind the Report Viewer, with the same hard page layout as PDF and print), using sample or given data. Returns the pages as images, the item positions in mm and warnings. Labels resolve in the chosen language; D365FO report functions that need the environment are shown empty and named. Optionally writes a PDF.

    Parameter Type Meaning
    reportName (required) string The report
    designName string The precision design. Default: the first design
    rdl string Render this RDL instead of the saved design (to try a change before saving)
    data object Rows per dataset: {"DatasetName": [{"Field": value, ...}, ...]}. Datasets left out get generated rows
    sampleRows number Generated rows for datasets without data (field names as text, 12345.67 for amounts). Default 1
    parameters object Report parameter values by name
    language string Label and format language. Default en-US
    company string AX_CompanyName for the preview. Default USMF
    firstPage number First page to return. Default 1
    maxPages number Pages to return as images, 1 to 4. Default 1
    dpi number Image resolution, 48 to 300. Default 96
    pdfPath string Also write the whole report as PDF to this path (.pdf, in an existing folder)
    overwrite boolean Replace pdfPath when the file exists. Default false
    includeItems boolean List the items with their positions. Default true 
    {
  "reportName": "ContosoSalesInvoice",
  "designName": "Report",
  "data": { "<dataset name>": [ { "<field>": "CIV-000123" } ] },
  "maxPages": 2,
  "pdfPath": "C:\\Temp\\ContosoSalesInvoice.pdf"
}

    Output: <report>.<design>: pages a-b of N at D dpi, rendered by Microsoft's report engine as PDF and print render (hard page breaks)., one Data line per dataset with its row count, the PDF path, the layout (as in xpp_get_report_design), and the pages as PNG images.

    xpp_measure_image¶

    Measures a scanned or photographed form for a precision design. All positions are in mm from the sheet's top-left corner.

    What it does:

    1. Calibrates the scale: whole sheet of a paper size, the scan's dpi, or two reference points.
    2. Straightens a skewed scan (up to 3 degrees).
    3. Finds ruled lines and boxes.
    4. Reads the text with Windows' built-in OCR, with each line's position and height and an estimated font size in points.
    5. Returns a picture of the image, or of a cropped area, with rulers and a millimetre grid (red lines every 10 or 50 mm, blue every grid step).
    Parameter Type Meaning
    imagePath (required) string Full path of the image
    paper string The scan shows the whole sheet of this size: Letter, Legal, A4, A5, Executive, or WIDTHxHEIGHT with mm, cm or in (for example 8.5x3.5in for a cheque). Default: from the image's dpi, else the paper size closest to the image's proportions
    dpi number The scan's resolution, when the image is not the whole sheet and has no dpi of its own
    referencePoints object { x1, y1, x2, y2, distanceMm }: two points on the image (pixels) and their real distance. Most precise for partial scans
    deskew boolean Straighten a skewed scan. Default true
    language string OCR language, for example en-US. Default: the user's languages
    crop object { x, y, width, height } in mm: only this area; the picture zooms in with a finer grid
    gridMm number Grid step in mm. Default by zoom (1, 2 or 5)
    imageWidth number Picture width in pixels, 600 to 2000. Default 1400
    minLineMm number Shortest ruled line to report, in mm. Default 10
    ocr boolean Read the text. Default true 
    { "imagePath": "C:\\Scans\\cheque-sample.png", "paper": "8.5x3.5in" }

    { "imagePath": "C:\\Scans\\cheque-sample.png", "paper": "8.5x3.5in", "crop": { "x": 150, "y": 10, "width": 60, "height": 20 } }

    Output: image size in px and mm with the calibration, NOTE: lines, Boxes (x, y, width, height), Rules (horizontal or vertical, from-to, thickness), Text lines (left, top, right, bottom, height, estimated pt, text, each word's x) and the grid picture.

    xpp_compare_layout¶

    Compares a rendered report page with a scanned sample: places the calibrated scan on the report's page, renders the design with Microsoft's report engine, and returns an overlay (scan ink red, report ink blue, both black). For the words that read the same on both, it reports the overall shift and each report text box's offset in mm, marked within or outside the tolerance.

    Parameter Type Meaning
    imagePath (required) string Full path of the scanned sample (whole sheet)
    reportName (required) string The report
    designName string The precision design. Default: the first design
    rdl string Render this RDL instead of the saved design
    data, sampleRows, parameters, company As in xpp_render_report
    language string Label language of the render and OCR language of both images
    page number Report page to compare. Default 1
    dpi number Comparison resolution, 72 to 200. Default 120
    paper string Sheet size of the scan, as in xpp_measure_image
    scanDpi number The scan's own resolution, when the image doesn't record it. Not needed with paper or referencePoints
    referencePoints object { x1, y1, x2, y2, distanceMm }
    deskew boolean Straighten a skewed scan. Default true
    toleranceMm number Offsets up to this are reported as ok. Default 0.5
    scanOffsetMm object { x, y }: where the scan's top-left corner sits on the page, when the scan doesn't start at the sheet's corner 
    {
  "imagePath": "C:\\Scans\\cheque-sample.png",
  "paper": "8.5x3.5in",
  "reportName": "ContosoCheque",
  "data": { "<dataset name>": [ { "<field>": "000123" } ] },
  "toleranceMm": 0.5
}

    When OCR is not available, the overlay is still returned and the text says why positions were not compared.

    How it works¶

    • The handlers are in ReportTools (server/Ported/Tools/ReportTools.cs). They call the bridge actions report_info, get_report_design, set_report_design, create_precision_design, duplicate_object and render_report.
    • set_report_design and create_precision_design are registered as Edit actions with object type AxReport, so the write policy checks that the report belongs to your model, and the Copilot scope and checkpoint apply. duplicate_object is a Copy action: the target model must be yours.
    • Rendering uses Microsoft's report engine from the report preview runtime; the PNG pages travel back to the agent as MCP image content.
    • Measuring and the overlay use ImageMeasure (calibration, deskew, line and box detection, grid picture) and Windows' OCR. Everything runs on your machine.
    • xpp_get_report_design, xpp_render_report, xpp_measure_image and xpp_compare_layout are registered as ParallelRead.

    Limitations¶

    • Reports have no extensions. To change a standard report's layout, copy it into your model and route printing to the copy.
    • The preview shows D365FO report functions that need the environment as empty, named placeholders; real values come only from a deployed report.
    • Fonts the cloud doesn't have are flagged as warnings by xpp_get_report_design; check them before you deploy.
    • xpp_render_report returns at most 4 pages as images per call.
    • OCR needs the language installed in Windows.

    Troubleshooting¶

    Symptom Cause Fix
    The save is refused with "Reports have no extensions: ..." The report is standard Copy it with duplicateOf and modelName, then change the copy
    Pass modelName: your model for the copy of ... duplicateOf without modelName Pass your model
    The report preview needs Microsoft's Report Viewer runtime, which is not installed. The runtime isn't installed Run F&O Studio: Install Report Preview Runtime (it downloads Microsoft's package after you accept its licence)
    The Report Viewer runtime in ... is incomplete or was changed Files of the runtime are missing or changed Run F&O Studio: Install Report Preview Runtime again
    Text: ... instead of text lines, or "Text positions were not compared" Windows OCR isn't available for the language Install the OCR language in Windows or pass language
    referencePoints needs x1, y1, x2, y2 (image pixels) and distanceMm. Incomplete reference points Pass all five values
    The image could not be read (corrupt or unsupported format). The file is not a readable PNG, JPEG, TIFF or BMP Export the page again as an image
    Measurements are off by a constant factor Wrong calibration Pass paper for a whole sheet, or referencePoints for a partial scan

    Glossary¶

    Terms used in this wiki, in F&O Studio and in Dynamics 365 Finance & Operations development. Where F&O Studio has a page for the term, it is linked.

    A¶

    • .axpp: The project export file of Visual Studio's Dynamics 365 tools: a zip with the project, the model information and the elements. Export Project… and Import Project… read and write the same format. See Export-and-Import-Projects.

    • Agent tools (MCP tools): The tools F&O Studio's server gives GitHub Copilot through the Model Context Protocol, such as xpp_read_object, xpp_create_object, xpp_find_references and xpp_build. They work through the metadata API and write only to your own models. See MCP-Agent-Tools.

    • AOS (Application Object Server): The Finance and Operations server process that runs X++ code. On a cloud-hosted or VHD environment it runs locally (in IIS or IIS Express, plus the batch service); on a unified developer environment it runs in the cloud.

    • AOT (Application Object Tree): The tree of all application elements (tables, classes, forms...). In Visual Studio and F&O Studio it is shown as the Application Explorer.

    • Application Explorer: The view that lists every model's elements, in a classic view (by element type) or a model view (by model). See Application-Explorer.

    • Application version: The version of the Finance and Operations application (for example 10.0.xxxx.xx). The metadata on your machine must match the environment's application version. See Version-Drift-Guard.

    • ATL (Acceptance Test Library): Microsoft's X++ library for creating test data in SysTest tests. Generate SysTest Class with Test Data (ATL) uses it. See Generate-SysTest-Class.

    • AxDB: The business database of a cloud-hosted or VHD environment, on the same machine. F&O Studio uses it with Windows authentication. See Database-Access.

    B¶

    • Batch service: The Windows service that runs batch jobs on a cloud-hosted or VHD environment (Batch.exe). F&O Studio can restart it after a build and attach the debugger to it.

    • Best practice checks (xppbp): Microsoft's rule checker for X++ code and metadata, the one Visual Studio runs. See Best-Practice-Checks.

    • Bridge action: A named JSON request from the extension to its metadata server, for example get_element_tree or where_used. See Bridge-Protocol.

    • Business event: An event raised from X++ that external systems can subscribe to through the business events catalog. See Wizard-Business-Event.

    C¶

    • CHE (cloud-hosted environment): A Finance and Operations development VM deployed through Lifecycle Services into your Azure subscription, with the AOS, AxDB and PackagesLocalDirectory on the VM. See Cloud-Hosted-and-VHD-Environments.

    • Chain of Command (CoC): The X++ way to wrap a method of a standard class, table or form in an extension class ([ExtensionOf(...)] with next). Create Code Extension creates one. See Create-Code-Extension and Implementations-and-Chain-of-Command.

    • Code view: F&O Studio's text editor for an element's X++ code, laid out the way Visual Studio shows it. See X++ code view.

    • Configuration (XPPConfig): A JSON file under %LOCALAPPDATA%\Microsoft\Dynamics365\XPPConfig that names the metadata folders, the custom metadata folder and the cross-reference database of one environment. The registry value CurrentMetadataConfig selects the active one. Visual Studio and F&O Studio share it. See Select-Environment.

    • Copilot checkpoint: A point you set with Start Copilot Checkpoint; everything Copilot changes afterwards can be reverted. See Copilot-Checkpoints-and-Scope.

    • Copilot scope: The set of elements Copilot may change, set with Set Copilot Scope….

    • Cross-reference database (XRef): A SQL Server database (in LocalDB on a developer machine) that records which code uses which element. Find References, rename and the references diagrams query it. Builds update it when xpp.build.crossReference is on.

    • Custom metadata folder (model store folder): The folder that holds your own packages and models, separate from the standard PackagesLocalDirectory on a UDE. Only models in this folder can be built and changed.

    D¶

    • Data entity: An element that exposes data for OData, data management (import and export) and integrations, usually with a staging table. See Wizard-Data-Entity and Try-Data-Entity-OData.

    • Dataverse: Microsoft's Power Platform data service. A unified developer environment is managed through its Dataverse organization (https://yourorg.crm.dynamics.com): F&O Studio uses Dataverse actions for setup, deploy, database sync, tests and database credentials.

    • Database synchronization (DB sync): Updating the SQL database schema to match the tables, views and indexes in the metadata. On a UDE it runs through Dataverse; on cloud-hosted and VHD environments through SyncEngine. See Synchronize-Database.

    • DebuggerProxy: Microsoft.Dynamics.AX.DebuggerProxy.exe, Microsoft's debugger proxy from the FinOps tools. It tunnels the debugger to a unified developer environment. See Debugger.

    • Deployable package: A zip of built packages for deployment through Lifecycle Services or Power Platform. Create Deployment Package… creates one. See Create-Deployment-Package.

    • Descriptor: The XML file in a package's Descriptor folder that describes a model: name, display name, layer, dependencies.

    • Duty, privilege, role: The security layers of Finance and Operations: a privilege grants access to entry points such as menu items; a duty groups privileges; a role groups duties and is assigned to users. See Security-View.

    E¶

    • EDT (extended data type): A reusable data type with properties such as label, size and relations, which table fields are based on.

    • Element: One item of metadata: a table, class, form, EDT, enum, menu item, security object, report and so on. Also called an object.

    • Entry point: Something a privilege grants access to: a menu item, a service operation or a data entity.

    • Event handler: A static method that runs on an element's event (for example a form control's OnClicked or a table's onInserted), declared with attributes such as [DataEventHandler]. See Event-Handlers.

    • Extension: An element in your model that adds to a standard element without changing it (for example CustTable.ContosoExtensions). See Create-Extension.

    F¶

    • FinOps tools: Microsoft's Visual Studio extension for Finance and Operations development, downloaded by Connect to Environment…. F&O Studio uses parts of it (for example the debugger proxy) without Visual Studio.

    • Form extension: An extension of a standard form that adds controls, data sources or property changes. See Form-Layout-and-Form-Extensions.

    I¶

    • Infolog: The list of info, warning and error messages X++ code shows to the user. F&O Studio's Infolog view shows them while you debug. See Infolog.

    J¶

    • JIT credentials (just-in-time database access): Temporary SQL credentials for a unified developer or sandbox environment's database, issued by the environment on request (Reader or Writer role) for a limited time. Request Database Credentials asks for them. See Database-Access.

    L¶

    • Label, label file: A translatable text referenced as @File:Id (for example @SYS7149). A label file holds the labels of one file ID in every language. See Label-Editor and Label-Tools.

    • LabelC: Microsoft's label compiler, in PackagesLocalDirectory's bin folder. Builds run it.

    • LCS (Lifecycle Services): Microsoft's portal for managing Finance and Operations implementations, including cloud-hosted environments and deployable packages.

    • LocalDB (SQL Server Express LocalDB): A lightweight SQL Server that runs on demand. It holds the cross-reference database on a developer machine.

    M¶

    • MCP (Model Context Protocol): The protocol through which Copilot calls tools. F&O Studio registers its server as an MCP server in VS Code. See MCP-Agent-Tools.

    • Metadata API: Microsoft's .NET API for reading and writing D365FO metadata, which Visual Studio uses. F&O Studio's server uses the same API, loaded from your installation. See Metadata-Server.

    • Model: A group of elements that belongs to one package and one layer, for example ContosoExtensions. New elements go into the model of your project. See Models-and-Model-Dependencies.

    O¶

    • OData: The REST protocol through which public data entities are read and written. See Try-Data-Entity-OData.

    P¶

    • pac (Power Platform CLI): Microsoft's command-line tool for Power Platform. F&O Studio uses it only for its two (pac) commands. See Power-Platform-CLI.

    • Package: The unit that is compiled and deployed: a folder with one or more models, built into assemblies in its bin folder.

    • PackagesLocalDirectory (PLD): The folder with all packages and the compiler tools (bin). On cloud-hosted and VHD environments it is under AosService; on a UDE machine Connect to Environment… downloads it.

    • Pdb2Pdb: Microsoft's tool that converts Windows PDB files into portable PDBs. F&O Studio runs it after each successful build, because VS Code's debugger reads only portable PDBs.

    • Precision design: An SSRS report design laid out to exact positions on the page. See Report-Designer.

    • Project (.rnrproj): A Visual Studio project file for Finance and Operations: the working set of elements of one model that you build and deploy. F&O Studio uses the same file. See D365FO-Projects.

    R¶

    • RDL: Report Definition Language, the XML format of SSRS report designs.

    • reportsc: Microsoft's report compiler. Builds run it so reports are part of the package.

    • RuntimePackagesDirectory: A folder of junctions that combines the standard packages and your custom metadata folder, so the compiler sees both. Connect to Environment… creates it.

    S¶

    • Sandbox: A Finance and Operations test environment (not a developer environment). Database credentials can be requested for sandboxes too.

    • Segregation of duties (SoD): Rules that keep two duties apart so one person cannot do both (for example maintain vendors and pay them). See Segregation-of-Duties.

    • SSRS (SQL Server Reporting Services): The report technology of Finance and Operations. See Report-Element-Designer.

    • SyncEngine: Microsoft's database synchronization tool in PackagesLocalDirectory's bin folder, used on cloud-hosted and VHD environments.

    • [SysObsolete]: An attribute that marks a class, table or method as obsolete, often with the replacement. F&O Studio warns about uses of obsolete APIs. See Syntax-Check-and-Obsolete-Warnings.

    • SysOperation: The framework for batch jobs and dialogs: a data contract, a service and a controller. See Wizard-Batch-Job.

    • SysTest: The X++ unit test framework. See Run-Tests and Test-Explorer.

    T¶

    • Team rules: The file .xpp/agent-rules.md in your repository, added to the Copilot agent instructions of everyone working in it. See Team-Rules.

    • TempDB / InMemory table: Temporary tables whose rows exist only while code runs. They cannot be browsed in the database.

    • Trace (.etl): A performance trace of the web client recorded in Event Tracing for Windows format. See Analyze-Trace.

    U¶

    • UDE (unified developer environment): A Finance and Operations developer environment hosted in Power Platform and managed through its Dataverse organization. Development happens on your own machine against downloaded metadata; deploy, database sync, tests and the debugger reach the environment through Dataverse. Its deployment type is OnlineDev. See Connect-to-Environment.

    V¶

    • VHD environment: A Finance and Operations development VM you run from Microsoft's downloadable virtual hard disk, with everything on the VM. F&O Studio treats it like a cloud-hosted environment.

    • vsdbg: The .NET debugger engine VS Code uses. On a UDE, Microsoft's debugger proxy runs in vsdbg mode for F&O Studio.

    W¶

    • Web client: The browser interface of Finance and Operations (https://yourenv.operations.dynamics.com). See Copy-Name-and-Open-in-Browser.

    • Workspace: VS Code's set of open folders. Opening a D365FO project opens its own workspace with the project folder and its model folder.

    X¶

    • X++: The programming language of Finance and Operations.

    • xppc: Microsoft's X++ compiler, in PackagesLocalDirectory's bin folder. F&O Studio builds with it, as Visual Studio does. See Build-Project-and-Model.

    • XRef: Short for the cross-reference database.

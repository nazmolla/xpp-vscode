    Scenario: Report from a scanned document¶

    This walkthrough is for developers who must print a business document on a given layout: a vendor cheque on preprinted cheque stock, a purchase order or an invoice that has to match a sample from the business. At the end you have a copy of the standard report in your model with a precision design placed to the millimetre against the scan, one small hook that routes printing to it, a preview made with Microsoft's report engine, and a build that compiles the report for deployment.

    You can do it by hand in the Report Designer, or let the F&O Report Builder agent do the measuring and placing. This page shows both.

    The situation¶

    Accounts payable prints vendor cheques from the payment journal on preprinted US cheque stock (Letter, 8.5 x 11 in): the bank's logo, the cheque frame, the MICR band area and the stub frames are already printed. The bank sent a new stock, and the fields that the standard Cheque_US report prints (date, amount, amount in words, payee name and address, cheque number, MICR line) no longer land in their boxes.

    You have:

    • a 300 dpi scan of one blank sheet of the new stock, C:\Scans\cheque-stock.png;
    • a ruler measurement from the real sheet: the top edge of the sheet to the top of the amount box is 22 mm;
    • the model ContosoExtensions, where the copy of the report must go.

    Facts from the standard application that matter here:

    • Cheque_US has one precision design, Report, and one dataset, Cheque_USDS, filled by the report data provider ChequeDP from the temporary table ChequeTmp (fields such as ChequeDate, AmountCur, AmountInWords, RecipientName, RecipientAddress, ChequeNum, MICRLine, Void).
    • Cheques don't use print management. ChequeController.determineReportMenuOutput picks the report from the cheque form type of the bank account's cheque layout (ChequeFormType::USStyle gives Cheque_US).
    • Standard reports can't be changed in place: you duplicate the report into your model and route printing to the copy.

    What you need¶

    • A development environment (UDE, cloud-hosted or VHD) with F&O Studio connected, and a project in ContosoExtensions (see D365FO Projects).
    • The scan as PNG, JPEG, TIFF or BMP. Export a PDF page as a 300 dpi image first.
    • The report preview runtime. The first preview asks you to accept Microsoft's licence and downloads Microsoft's Report Viewer runtime (about 15 MB) from nuget.org. You can install it ahead with Install Report Preview Runtime. F&O Studio doesn't ship it.
    • For the agent: GitHub Copilot. The agent's xpp_measure_image reads text with Windows' built-in OCR on this machine; nothing is uploaded.

    Step by step¶

    Phase 1: Decide what to create¶

    Keep the element list short. For a cheque layout you need exactly two elements:

    Element Why
    ContosoCheque_US, a copy of the report Cheque_US the new precision design; it keeps Microsoft's dataset from ChequeDP
    ChequeController_ContosoExtensions_Extension, a Chain of Command class on ChequeController routes US-style cheques to the copy

    You don't need a new data provider, contract, controller, menu item or privilege: the standard cheque printing keeps running them. A table extension of ChequeTmp and a Chain of Command on ChequeDP are only needed when you print a field the standard data provider doesn't fill. For invoices, purchase orders and confirmations the hook is the print management registration instead (see Report Element Designer).

    Phase 2: Copy the standard report into your model¶

    1. Open the report: Open Element… (Ctrl+Alt+O), type Cheque_US, Enter. Or find it in the Application Explorer under Reports.
    2. Right-click the report and choose Open Report Designer. A standard report opens read-only with a banner saying that it belongs to a model you can't change, and the button Duplicate into my model….
    3. Choose Duplicate into my model… (it runs Duplicate…, which you can also pick by right-clicking the report in the Application Explorer). Pick the model ContosoExtensions and enter the name ContosoCheque_US. F&O Studio creates the copy through the metadata API, adds it to the project and opens it.
    4. Open the copy in the Report Element Designer. Check that the dataset Cheque_USDS is still there with its Query SELECT * FROM ChequeDP.ChequeTmp. See Report Datasets.

    Phase 3: Lay the scan under the page¶

    1. Right-click the precision design Report of ContosoCheque_US and choose Open Report Designer (or double-click it). See Report Designer.
    2. Check the page properties: paper Letter (215.9 x 279.4 mm), margins, body size. The designer warns when the body is wider than the page (that prints blank pages) and when items sit outside the body.
    3. Click the Scan overlay button (camera icon) and pick C:\Scans\cheque-stock.png. The scan lies under the page at the size of the paper it shows. The overlay is never saved in the report.
    4. In Scan overlay (not saved in the report) in the properties pane, set Paper to Letter, or type Width (mm) and Height (mm). Use Offset x (mm) and Offset y (mm) when the scan does not start at the sheet's corner, and the Opacity slider to see both the scan and the design.
    5. Check the scale with the Measure tool (ruler icon, or hold Alt and drag): measure from the top of the page to the top of the amount box. It must read 22 mm, as on the real sheet. If it doesn't, fix the overlay's size first. See Scan Overlay and Measure.

    Phase 4: Place the fields¶

    1. Select a textbox, for example the one showing =Fields!AmountCur.Value, and drag it into the amount box of the scan. Arrow keys move by the grid, Ctrl+arrows by 0.1 mm, Shift+arrows resize.
    2. For each fixed field use what preprinted stock needs:
    3. Can grow and Can shrink off, so a long value never pushes the next field down (the designer warns about growing textboxes that push others);
    4. padding 0 pt;
    5. the font size you measured, amounts right-aligned.
    6. Remove items that the stock already prints (frames, captions, the bank logo). On preprinted stock you print only the data.
    7. Fonts: use only fonts D365FO renders. The designer warns about fonts D365FO doesn't offer and fonts that aren't installed on this machine (the preview substitutes them, the environment doesn't). The MICR line uses a MICR font such as MICR E13B 2.1.
    8. Drag more fields from the report data onto the page when the new stock has a field the old one didn't, for example RecipientAddress in a window envelope position.
    9. Save. The designer keeps the RDL's schema version, units and everything it doesn't edit.

    Phase 5: Preview with Microsoft's report engine¶

    1. Click Preview. F&O Studio renders the design with Microsoft's report engine, the same hard page layout as PDF and print. See Report Preview.
    2. In the preview settings set Language, Company, Sample rows, Pages and Resolution (dpi). Under Data (JSON rows per dataset), each dataset has a box that takes a JSON array of rows; datasets left empty get generated sample rows. Enter the values printed on a real cheque in the Cheque_USDS box so the widths are realistic, for example:
    [
  { "ChequeNum": "000123", "ChequeDate": "2026-11-25", "AmountCur": 1234.56,
    "AmountInWords": "One thousand two hundred thirty-four and 56/100",
    "RecipientName": "Contoso Supplies", "Void": "" }
]
    1. Turn on Show scan under the page and click Render to see the rendered page over the scan. Fix the positions in the designer and preview again until every field sits in its box.
    2. Read the warnings above the pages: they come from the engine and from the layout checks.

    Phase 6: Route cheque printing to the copy¶

    1. In the Application Explorer, right-click the class ChequeController and choose Create Code Extension. Accept or change the name (it must end with _Extension). See Create Code Extension.
    2. Wrap determineReportMenuOutput. The standard method sets the protected member chequeReport from the cheque form type and returns it:
    [ExtensionOf(classStr(ChequeController))]
final class ChequeController_ContosoExtensions_Extension
{
    protected str determineReportMenuOutput(ChequeFormType _chequeFormType, BankChequeLayout _bankChequeLayout)
    {
        str report = next determineReportMenuOutput(_chequeFormType, _bankChequeLayout);

        if (_chequeFormType == ChequeFormType::USStyle)
        {
            chequeReport = ssrsReportStr(ContosoCheque_US, Report);
            report = chequeReport;
        }
        return report;
    }
}
    1. Decide with the business whether every US-style layout should use the new stock. If only some bank accounts use it, add a condition (for example on _bankChequeLayout) instead of switching all of them.
    2. Peek the wrapper from the standard method with Go to Implementations (Ctrl+F12) to confirm it is picked up. See Implementations and Chain of Command.

    Phase 7: Build, deploy and print a test¶

    1. Run Build Project. The build compiles the reports with Microsoft's reportsc into the package, as Visual Studio does, plus the controller extension. Fix every error. See Report Build and Build Project and Model.
    2. On a UDE, run Deploy Models to Environment (no database sync is needed for a report and a class). On cloud-hosted and VHD environments the build is what runs. See Deploy to Environment.
    3. In the client, print a test cheque from the bank account's cheque layout on plain paper and hold it over a sheet of the preprinted stock against the light. Print at actual size, never "fit to page".
    4. Confirm on the real printer. MICR lines in particular need a test on the bank's requirements; F&O Studio has not tested MICR on a real printer.

    Doing it with Copilot¶

    Pick F&O Report Builder in the agent picker. It turns the scan into the report: it measures the scan, decides between a new report and a copy of the standard one, lists the elements it will create before creating any, writes the precision design at the measured positions, renders it and compares it with the scan until every field lines up, then builds.

    First prompt (give it what it can't see):

    Build a vendor cheque layout from C:\Scans\cheque-stock.png. It is preprinted US cheque stock, Letter size, scanned at 300 dpi. From the top edge of the sheet to the top of the amount box is 22 mm. It replaces the standard US cheque for all bank accounts. Fields: date, amount, amount in words, payee name and address, cheque number, MICR line. Model: ContosoExtensions.

    What the agent does:

    Step Tool
    Measures the scan: scale, deskew, boxes, ruled lines, text lines in mm from the sheet's top-left corner, a mm grid picture; crops to areas for finer readings xpp_measure_image
    Reads the standard report's designs, datasets and item positions xpp_get_report_design on Cheque_US
    Copies the standard report into your model, then saves the precision design xpp_set_report_design (duplicateOf, modelName)
    Creates the Chain of Command class on ChequeController.determineReportMenuOutput xpp_create_object
    Renders the design with sample data that shows the values on the scan xpp_render_report
    Overlays the render on the scan and reports each textbox's offset in mm; repeats until every item is within 0.5 mm (or your tolerance) xpp_compare_layout
    Compiles the report and the class xpp_build

    Checkpoints for you:

    • The agent asks first what it can't see: preprinted or plain paper, paper size, whether it replaces a standard document, which data each field shows, the target model, the scan's dpi, and one or two ruler measurements.
    • Before creating anything it lists the elements with one line each on why. If it proposes extras (a parameter to switch the layout, a label file, menu items), they are proposals; it doesn't create them unless you ask.
    • Start a checkpoint before you let it write (Start Copilot Checkpoint), so Revert Copilot Changes Since the Checkpoint… undoes everything. Watch its calls in Copilot Activity. See Copilot Checkpoints and Scope.
    • Its answer lists the elements, the comparison result per field, and what you must still do: deploy, print a test on plain paper over the stock, confirm on the real printer at actual size, and fonts this machine doesn't have.
    • Open the result in the Report Designer yourself and check it with the scan overlay.

    Follow-ups:

    • "Move the payee address 1.5 mm down and render again." (the agent re-renders and compares)
    • Handoff Review to the F&O Code Reviewer, or Release to the F&O Release Manager.
    • For a report that is not a layout copy (a new list report with its own data provider and contract), use the F&O Report Developer agent or the New Report… wizard (see Wizard Report).

    Checklist¶

    • [ ] Elements kept to the minimum: the report copy and one routing hook.
    • [ ] The copy keeps the standard dataset and data provider.
    • [ ] Scan overlay at the right paper size; one ruler measurement checked with the Measure tool.
    • [ ] Fixed fields: no Can grow, padding 0, measured font size, amounts right-aligned.
    • [ ] Nothing printed that the stock already shows.
    • [ ] Only fonts D365FO renders; MICR font for the MICR line.
    • [ ] Preview with realistic data and the scan under the page: every field in its box.
    • [ ] Controller extension routes the right cheque form type (and only the right bank accounts).
    • [ ] Build compiles the report without errors; deployed.
    • [ ] Test print on plain paper over the stock at actual size; confirmed on the real printer.

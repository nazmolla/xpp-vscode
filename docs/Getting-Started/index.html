    Getting started¶

    F&O Studio for VS Code lets you develop Dynamics 365 Finance & Operations (D365FO) X++ code in VS Code, without Visual Studio. It works on unified developer environments (UDE), cloud-hosted environments (CHE) and VHD environments, and uses the same metadata API, compiler and scripts as Visual Studio, so projects and models open in both tools. This page takes you from installing the extension to your first build, your first data query and your first Copilot request.

    Before you start¶

    You need Why
    Windows F&O Studio runs Microsoft's D365FO tools (metadata API, xppc, LabelC), which are Windows only
    VS Code 1.101 or later The minimum version the extension declares
    A D365FO development environment A unified developer environment, or a cloud-hosted or VHD environment
    SQL Server LocalDB For the cross-reference database (where-used, rename, references diagrams)
    GitHub Copilot (optional) Only for the Copilot agents and the agent tools
    Power Platform CLI pac (optional) Only for the two (pac) commands. Deploy and database sync do not need it
    C# extension (cloud-hosted and VHD only) The debugger on a local AOS uses its .NET debugger. F&O Studio offers to install it

    On a unified developer environment you also need about 16 GB of free disk space for the standard metadata, and an account that can sign in to the environment's Dataverse organization.

    On a cloud-hosted or VHD environment, run VS Code as administrator, as Visual Studio does, so builds can write into PackagesLocalDirectory.

    F&O Studio never ships Microsoft's D365FO assemblies. It loads them from your own installation at run time: from the metadata it downloads on a UDE, or from PackagesLocalDirectory on a cloud-hosted or VHD environment.

    Step 1: install the extension¶

    1. Open the Extensions view (Ctrl+Shift+X) in VS Code.
    2. Search for F&O Studio for VS Code (publisher MNazmi, ID MNazmi.xpp-vscode) and select Install.
    3. An F&O Studio icon appears in the activity bar. Select it to open the F&O Studio views.

    The extension starts when VS Code has finished starting, when a workspace contains a .rnrproj file, or when you open an X++ code view.

    The Get started with F&O Studio walkthrough (Help > Welcome, or Welcome: Open Walkthrough... in the Command Palette) has the same steps as this page, with buttons that run each command.

    Step 2: set up the machine¶

    Unified developer environment¶

    A UDE runs in the cloud; your machine needs a copy of the standard metadata, the compiler and the cross-reference database. Connect to Environment… does what Visual Studio's Connect to Dataverse does.

    1. Open the Dynamics 365 view in the F&O Studio side bar and expand Environment, then select Connect to Environment…. Or run F&O Studio: Connect to Environment… from the Command Palette.
    2. Enter the environment's Dataverse URL, for example https://yourorg.crm.dynamics.com. You find it as "Environment URL" in the Power Platform admin center. You can also paste the environment's web client URL (https://yourenv.operations.dynamics.com); F&O Studio looks up the matching Dataverse URL.
    3. Sign in when VS Code asks. F&O Studio uses VS Code's Microsoft account sign-in.
    4. Watch the six steps in the Environment group of the Dynamics 365 view and in the notification:
    5. Sign in to Dataverse
    6. Check SQL Server LocalDB
    7. Download metadata and tools
    8. Extract PackagesLocalDirectory
    9. Restore cross-reference database
    10. Configure this machine
    11. When it finishes you see "Environment connected. The Application Explorer, designers and code views now use it."

    If a step fails, the notification says "Environment setup failed: ..." with Retry, Show Log and Report Problem. Retry also appears in the Environment group. See Troubleshooting.

    Before a long download you can run Check Environment Connection: it signs in and runs every read-only step of the setup (environment type, versions, download links) and writes the result to the X++ output.

    The setup writes the same configuration Visual Studio reads, so Visual Studio on the same machine can use it too. See Connect-to-Environment and Visual-Studio-Side-by-Side.

    Cloud-hosted or VHD environment¶

    There is nothing to set up. F&O Studio uses the local PackagesLocalDirectory, AOS and AxDB. UDE-only commands (Deploy Models to Environment, Run Tests, the (pac) commands) are hidden. See Cloud-Hosted-and-VHD-Environments.

    Several environments¶

    You can connect several UDEs. Select Environment… (or the environment name in the status bar) switches between them without a reload, and each workspace remembers its own environment. See Select-Environment.

    Step 3: pick your starting point¶

    A project is optional. The Application Explorer and the agent tools work without one.

    You want to Do this
    Work on your team's code Open Team Repository… clones or picks a repository, links its packages into the metadata folder and builds them in dependency order. See Open-Team-Repository
    Open an existing project Open D365FO Project… (or Open Recent D365FO Project…) in the D365FO Project view. See D365FO-Projects
    Start a new project Create D365FO Project… writes a .rnrproj and a .slnx, as Visual Studio does
    Create a model first Create Model… in the Dynamics 365 view under Create. See Models-and-Model-Dependencies
    Just look around Use the Application Explorer

    Opening a project opens its own workspace with the project folder and its model folder. New elements go into the project's model.

    Step 4: find your way around¶

    • Application Explorer lists every model's elements, like Visual Studio's. Switch between the classic view (elements by type) and the model view (elements by model) with the buttons at the top. See Application-Explorer.
    • Open Element… (Ctrl+Alt+O) finds any element by name. A prefix narrows the type: t:cust finds tables, c: classes, f: forms. See Open-Element.
    • Click a class to open its code; click a label file to open the label editor; click any other element to open its designer. Right-click for everything else: Find References, Create Extension, Create Code Extension, View Hierarchy, Browse Table Data and more. See Element-Designer and X++ code view.
    • In code, F12 goes to a definition, Shift+F12 finds references and Ctrl+F12 lists implementations, including Chain of Command extensions and event handlers. See Go-to-Definition and Implementations-and-Chain-of-Command.
    • The Dynamics 365 view groups the commands of Visual Studio's Dynamics 365 menu by task. Every command is listed in the Command-Reference.

    Step 5: create and build¶

    1. In the D365FO Project view, select + (New Element…) and pick an element type, or a wizard such as New Batch Job (SysOperation)…. See New-Element.
    2. To change a standard element, right-click it in the Application Explorer and choose Create Extension (metadata) or Create Code Extension (Chain of Command). See Create-Extension and Create-Code-Extension.
    3. Build with Ctrl+Shift+B in an X++ code view, or select the project name in the status bar. Unsaved code views are saved first. Builds use xppc and LabelC, the compilers Visual Studio uses.
    4. Errors and warnings go to the Problems view, on the right line of the code view. When a build fails, the notification offers Show Problems and Show Output (the full compiler log in the X++ Build output).

    See Build-Project-and-Model and Compiler-Diagnostics.

    Step 6: deploy, test and debug¶

    Environment Deploy Tests Debug
    Unified developer environment Deploy Models to Environment uploads your packages as built on this machine, through the environment's Dataverse, with an optional database sync Run Tests runs SysTest classes on the environment; they also appear in VS Code's Test Explorer Launch Debugger attaches through Microsoft's debugger proxy
    Cloud-hosted or VHD Not needed: the build goes into the local PackagesLocalDirectory, and the running AOS restarts after a successful build Not available in F&O Studio; run tests from Visual Studio on the VM Launch Debugger attaches to the local AOS with the C# extension's .NET debugger

    Tests and the debugger run the code deployed on the environment. When your build is newer than the last deploy, F&O Studio warns you and offers Deploy First. See Deploy-to-Environment, Run-Tests and Debugger.

    Step 7: look at the data¶

    • Right-click a table and choose Browse Table Data to see its rows, with enum names, a company filter, column filters and a record inspector. See Browse-Table-Data.
    • New SQL Query opens a read-only query panel with Explain Plan. See SQL-Query-Panel.
    • On a UDE, F&O Studio requests temporary database credentials for you (the same request Visual Studio makes); they are kept in VS Code's secret storage until they expire. On a cloud-hosted or VHD environment it uses the local AxDB with Windows authentication. See Database-Access.

    Step 8: ask Copilot¶

    With GitHub Copilot installed, F&O Studio registers its agent tools automatically and adds F&O agents to the chat's agent picker (F&O Developer, Code Reviewer, Support, Functional Explainer and others).

    1. Run F&O Studio: Start Copilot Checkpoint first if you want to be able to undo everything Copilot changes.
    2. Open Copilot Chat in agent mode and pick an F&O agent, or let Copilot suggest one.
    3. Ask, for example:
    4. Create a table extension of CustTable with a field for the customer's loyalty tier, and show it on the CustTable form.
    5. Which roles can open the SalesTable form, and what license do they need?
    6. Why does posting fail with "Field 'Customer group' must be filled in."? Find where the message comes from.
    7. Watch what it does in the Copilot Activity view in the F&O Studio panel.
    8. Keep the changes with End Copilot Checkpoint (Keep Changes), or undo them with Revert Copilot Changes Since the Checkpoint….

    Agent tools write only to your own models, and every write is all or nothing. See Copilot-Agents, MCP-Agent-Tools and Copilot-Checkpoints-and-Scope.

    What you see in the status bar¶

    Item Shows Click
    Environment The active environment's name; a warning icon when the environment runs a newer application version Opens the environment menu
    Database The local database name, or the role and expiry time of temporary UDE credentials; hidden while you have no database access Opens the Database menu
    Project The active project and the last build result; a cloud icon when the build is newer than the last deploy Builds the project
    X++ server Only while the metadata loads, or when the server stopped Restarts the server when it stopped
    Copilot checkpoint An open Copilot checkpoint Opens the checkpoint menu

    See Status-Bar.

    Where to look when something goes wrong¶

    • The X++ output channel has the server and setup log. X++ Build, X++ Deploy and X++ Tests have the build, deploy and test logs.
    • Error notifications offer Show Log and Report Problem.
    • Troubleshooting lists the common messages and their fixes; FAQ answers common questions.

    Release Process¶

    F&O Studio releases are built from the public source by a GitHub Actions workflow, not on a developer machine. A version tag vX.Y.Z starts the build; the workflow compiles and tests everything, has the server signed when signing is set up, packages the VSIX and a stand-alone server zip, and creates the GitHub release. The VSIX then goes to the Visual Studio Marketplace.

    This page describes the steps and what each check protects. It is for maintainers and for users who want to know how the published extension is made.

    What a release contains¶

    Asset Contents
    xpp-vscode-X.Y.Z.vsix the extension: out/, core/dist/, server/bin/XppVsCode.Server.exe and its .config, tools/pdb2pdb/, media, grammar, agents, CHANGELOG.md
    fno-studio-server-X.Y.Z.zip server/bin on its own, for hosts outside VS Code (see MCP-Server-Outside-VS-Code)
    fno-studio-server-X.Y.Z.zip.sha256 the zip's SHA-256

    No asset contains a Microsoft D365FO assembly. The server loads them at run time from the user's own installation.

    Versioning and branches¶

    • Work happens on main. Releases are tags vX.Y.Z, not branches.
    • The version in package.json is the release version. The tag must match it exactly, or the build stops with "Tag ... does not match package.json version ...".
    • The same version goes into the server exe's file metadata (build-server.ps1 passes -p:Version).

    Release steps¶

    1. Set the version in package.json.
    2. Write the release notes in docs/FEATURES.md under ## What's new in X.Y (one section per minor version, at the top). This is the only place release notes are written.
    3. Run npm run changelog. It writes CHANGELOG.md from the "What's new" sections; the Marketplace shows it as the Changelog tab. Never edit CHANGELOG.md by hand.
    4. If agents changed, run npm run agents.
    5. Commit and push main. Images in FEATURES.md resolve to docs/images on GitHub, so push before publishing.
    6. Tag and push the tag:
    git tag vX.Y.Z
git push origin vX.Y.Z
    1. Wait for the Release build workflow to pass.
    2. Publish the VSIX to the Marketplace (automatic when the workflow has a Marketplace token; otherwise by hand, see below).

    The workflow¶

    .github/workflows/release.yml runs on a pushed v* tag, or by hand (workflow_dispatch) as a dry run. It has two jobs on windows-latest.

    flowchart TD
    T["tag vX.Y.Z pushed"] --> V["Version: tag must match package.json"]
    V --> R["Restore Microsoft's D365 compiler package (private feed)"]
    R --> NS["npm ci"]
    NS --> BS["Build and test the server<br/>build-server.ps1 -Test, check-bridge-actions.js"]
    BS --> NM["No Microsoft DLL in server/bin;<br/>exe metadata = F&O Studio + version"]
    NM --> BE["Build and test the extension<br/>compile, test:core, offline tests,<br/>agents --check, changelog --check"]
    BE --> SG["Sign the server (SignPath, when configured)"]
    SG --> ZIP["Server zip + SHA-256<br/>(no Microsoft files)"]
    ZIP --> VSIX["Fetch Pdb2Pdb, check it runs, vsce package"]
    VSIX --> P["publish job"]
    P --> C1["zip matches SHA-256"]
    C1 --> C2["VSIX holds the server, Pdb2Pdb, changelog, core;<br/>no Microsoft DLL; signature valid when signing is configured"]
    C2 --> N["Release notes from 'What's new in X.Y'"]
    N --> GH["GitHub release (create or update)"]
    GH --> MP["Marketplace publish (when a token is set)"]

    Build job¶

    Step What it does Why
    Version Reads package.json; on a tag, compares with the tag name The release, the VSIX and the exe all carry the same version
    Restore compiler package Restores Microsoft's Dynamics 365 compiler package from a private feed and sets XPP_BIN The server compiles against Microsoft's assemblies; they are never part of the repository, an artifact or the VSIX
    npm ci Installs development dependencies
    Build and test the server build-server.ps1 -Test (build plus test/server unit tests), then check-bridge-actions.js Server correctness, contract with the extension
    Never ship Microsoft assemblies Fails when server/bin has any .dll; checks the exe's ProductName "F&O Studio for VS Code" and ProductVersion Licensing; signing requires the metadata
    Build and test the extension npm run compile, npm run test:core, source-test.js, form-preview-test.js, xpp-config-test.js, vs-tools-test.js, build-agents.js --check, changelog.js --check No stale generated files
    Upload the unsigned server Artifact for signing
    Sign the server Submits the exe to SignPath and waits (every request needs a manual approval), only when signing is configured Code signing (see below)
    Use the signed server Copies the signed exe back and prints its Authenticode status. On a tag with signing configured, an invalid signature stops the release; without signing configured the server ships unsigned with a warning
    Package the server Zips server/bin, fails on any .dll or Microsoft.Dynamics.* file and when the exe is missing, writes the SHA-256 Hosts outside VS Code
    Package the VSIX npm run build:tools, checks Pdb2Pdb exists and runs, then vsce package with docs/FEATURES.md as the overview Deploy and debugging need Pdb2Pdb

    Publish job¶

    Step What it does
    Zip hash The downloaded server zip must match its .sha256
    VSIX contents extension/server/bin/XppVsCode.Server.exe, its .config, extension/tools/pdb2pdb/Pdb2Pdb.exe, extension/changelog.md and extension/core/dist/index.js must be there; no Microsoft.Dynamics.*.dll. When signing is configured and this is a tag, the exe must carry a valid SignPath Foundation signature
    Release notes Takes the ## What's new in X.Y section of docs/FEATURES.md (fails when there is none) and adds an install line
    GitHub release On a tag: creates release "F&O Studio X.Y.Z" with the VSIX, the server zip and its hash, marked latest. Re-running the workflow for the same tag updates the release instead of failing
    Marketplace On a tag: publishes the VSIX when a Marketplace token is configured; otherwise prints a warning with the manual command
    Dry run On a manual run: everything except the GitHub release and publishing

    Publishing to the Marketplace by hand¶

    When the workflow did not publish, publish the release's own VSIX (the one with the signed server, if signing is configured), never a local build:

    gh release download vX.Y.Z --pattern *.vsix
npx vsce publish --packagePath xpp-vscode-X.Y.Z.vsix

    The publisher is MNazmi; vsce needs a login for it on the machine. npm run publish refuses on purpose with a message that points to the workflow, because a local build's server is unsigned. npm run package still makes a local VSIX for testing.

    Code signing¶

    From the public code signing policy in the README:

    • Free code signing is provided by SignPath.io, certificate by SignPath Foundation.
    • What is signed: the F&O Studio server (server/bin/XppVsCode.Server.exe) in the published extension. The release workflow builds it from the repository's source on GitHub Actions and submits it to SignPath. The Visual Studio Marketplace signs the extension package itself.
    • Microsoft's assemblies are restored from a private feed during the build only; they are never part of the repository or the extension.
    • Every signing request is approved by hand.

    The workflow signs only when signing is configured for the repository. Without it, the server ships unsigned and the build shows a warning.

    Checklist before tagging¶

    • package.json version bumped.
    • ## What's new in X.Y in docs/FEATURES.md describes the user-visible changes.
    • npm run changelog run and CHANGELOG.md committed.
    • node scripts/build-agents.js --check passes.
    • Server changes: npm run test:server, scripts/smoke-test.ps1, node scripts/security-probes.js all pass (see Testing-the-Extension).
    • Refactorings: golden master IDENTICAL.
    • main pushed, then the tag.

    Troubleshooting¶

    Symptom Cause Fix
    "Tag vX.Y.Z does not match package.json version ..." Tag and package.json differ Delete the tag, fix the version, tag again
    "docs/FEATURES.md has no section ## What's new in X.Y" No release notes for the minor version Add the section, run npm run changelog, push, re-run
    changelog.js --check or build-agents.js --check fails Generated files out of date Run npm run changelog / npm run agents and commit
    "server/bin must hold only F&O Studio's own files" A Microsoft assembly was copied to the output Check that every D365FO reference has <Private>false</Private>
    "Pdb2Pdb is missing" or "Pdb2Pdb doesn't run" The tool download failed Re-run; check scripts/fetch-pdb2pdb.ps1
    "The server is not signed ... although signing is configured" The signing request was rejected or timed out Approve the request in SignPath and re-run the workflow
    Warning: Marketplace was not updated No Marketplace token in the workflow Publish by hand as above
